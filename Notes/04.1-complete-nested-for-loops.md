# Part 1 â€” Fundamentals, grammar, and exact execution

## 1.1 Core mental model

**Outer iteration** selects a group. **Inner iteration** visits its members. The inner statement is *reached again* on each outer iteration; its initializer runs again. They do **not** advance simultaneously.

```text
ENTER OUTER: initialize outer
  TEST outer â”€â”€ false â†’ DONE
      â”‚ true
      â–¼
  ENTER INNER: initialize inner
      TEST inner â”€â”€ false â†’ finish outer body
          â”‚ true                 â”‚
          â–¼                      â–¼
      EXECUTE inner body      UPDATE outer
          â”‚                      â”‚
      UPDATE inner                â””â”€â”€â†’ TEST outer
          â””â”€â”€â†’ TEST inner
```

### Syntax anatomy

```javascript
for (let row = 1; row <= 3; row++) {
  for (let column = 1; column <= 2; column++) {
    console.log(row, column);
  }
}
```

| Token | Category | Logic |
|---|---|---|
| `for` | keyword | enter a counted-loop statement |
| `(` `)` | punctuation | enclose three header sections |
| `let` | declaration keyword | create a block-scoped counter binding |
| `row`, `column` | identifiers | hold current coordinate values |
| `=` | assignment | set starting value |
| `1`, `3`, `2` | numeric literals | starts and inclusive limits |
| `;` in header | separators | distinguish initializer/test/update |
| `<=` | comparison | return boolean used as continuation test |
| `++` | postfix update | increase counter by one after body |
| `{` `}` | block delimiters | group statements under each loop |
| `console.log` | method call | log current pair; not store a record |
| `,` in call | argument separator | pass two values |

**Exact order:** outer initialization (once) â†’ outer test â†’ inner initialization â†’ inner test â†’ body â†’ inner update â†’ inner test ... â†’ inner false â†’ outer update â†’ outer test ... â†’ outer false. A false test means the body is skipped, not executed one last time.

### Example 1.1 â€” Class Ã— student roster (real-world question)

**Requirement:** A school has 2 classes and 3 students per class. Print every `(class, student)` identifier in class order. Inputs are positive integers; no records may be skipped; for zero counts output nothing.

**Recognize:** â€œeach student **in each** classâ€ â†’ one repetition nested inside another. **Input:** class count, student count. **Output:** six lines. **State:** two counters. **Stop:** class > 2 or student > 3.

**Pseudocode:** for each class 1..2 â†’ for each student 1..3 â†’ print identifier.

```javascript
const classCount = 2;
const studentsPerClass = 3;
for (let classId = 1; classId <= classCount; classId++) {
  for (let studentId = 1; studentId <= studentsPerClass; studentId++) {
    console.log(`Class ${classId}: Student ${studentId}`);
  }
}
```

**Line-by-line logic ledger:**

| Line | Read â†’ compute/test â†’ change/output â†’ next |
|---|---|
| `const classCount = 2` | read literal `2` â†’ bind immutable identifier `classCount` â†’ next line |
| `const studentsPerClass = 3` | read `3` â†’ bind count â†’ next line |
| `for (let classId = 1; classId <= classCount; classId++)` | initialize `classId=1` once; test `classId <= 2`; if true enter outer body; after body update `classId++` and retest |
| `for (let studentId = 1; studentId <= studentsPerClass; studentId++)` | **every outer entry** initialize `studentId=1`; test `<=3`; execute body; update `studentId++`; retest |
| `console.log(\`Class ${classId}: Student ${studentId}\`)` | read both counters â†’ interpolate into string â†’ log string â†’ next inner update |
| inner `}` | close inner body; control reaches inner update (not outer update yet) |
| outer `}` | close outer body; after inner ends control reaches outer update |

**Token dissection:** `const` prevents reassignment of the binding; `=` assigns; template backticks create a string; `${...}` evaluates an expression and inserts its string form; `console.log(...)` is a call with one argument; `++` increments a numeric counter; `<=` includes the boundary.

**Output:** Class 1: Student 1, 2, 3; then Class 2: Student 1, 2, 3 (one line each).

**Test:** 1Ã—1 â†’ one line; 0Ã—3 â†’ zero lines; 2Ã—0 â†’ zero lines. **Alternative:** a single loop could compute pairs using quotient/remainder, but nested loops directly express the business hierarchy.

# Part 2 â€” Loop headers, counters, scope, and boundaries

## 2.1 Header capability matrix

| Form | Valid? | Mechanism / caution |
|---|---|---|
| `for (let i=0; i<3; i++)` | Yes | ordinary upward |
| `for (let i=3; i>0; i--)` | Yes | downward |
| `for (let i=0; i<=10; i+=2)` | Yes | stepped |
| `for (let i=1; i<10; i*=2)` | Yes | geometric progression; ensure termination |
| `for (let i=0,j=5; i<j; i++,j--)` | Yes | two bindings, comma-separated update expressions |
| `for (; condition; )` | Yes | external initialization/update required |
| `for (;;) { ... }` | Yes | no test means truthy forever unless abrupt exit |
| `for (const i=0; i<3; i++)` | Parses; throws on update | `const` binding cannot be reassigned |
| `for (let i=0; ; i++)` | Yes | no condition; must have deliberate exit |
| `for (let i=0; i<3;)` | Yes | update must occur in body or another exit path |
| `for (let i=0; i<3; i++);` | Yes | empty statement body: trailing semicolon changes meaning |
| `for (let i=0; i<3; i++) console.log(i);` | Yes | single statement body, braces recommended |

**Multiple expressions:** the comma operator evaluates left to right and yields the rightmost expression's value. In `for` headers, commas may also separate declarations. Avoid side effects in tests unless intentional.

## 2.2 Counter and boundary rules

| Pattern | Values | Body count |
|---|---|---:|
| `i=1; i<=4; i++` | 1,2,3,4 | 4 |
| `i=1; i<4; i++` | 1,2,3 | 3 |
| `i=4; i>=1; i--` | 4,3,2,1 | 4 |
| `i=0; i<6; i+=2` | 0,2,4 | 3 |
| `i=1; i<10; i*=2` | 1,2,4,8 | 4 |
| `i=0; i<0; i++` | none | 0 |

### Example 2.1 â€” Delivery zone Ã— reverse shift (decrement)

**Requirement:** Two delivery zones must be checked, starting with shift 3 and counting backward to shift 1. Print all six checks in zone order. Input zones 1..2, shifts 3..1.

**Recognition:** repeated zones; reverse repeated shifts. **Algorithm:** for each zone â†’ for shift 3 down to 1 â†’ log.

```javascript
for (let zone = 1; zone <= 2; zone++) {
  for (let shift = 3; shift >= 1; shift--) {
    console.log(`Zone ${zone}, shift ${shift}`);
  }
}
```

| Line | Reads | Test/update/output |
|---|---|---|
| Outer header | `zone`, limit `2` | initialize 1; `<=2`; `zone++` after inner |
| Inner header | `shift`, limit `1` | initialize 3 per zone; `>=1`; `shift--` after each log |
| Log | both counters | interpolate â†’ log zone/shift |
| Inner close | no values | inner update/test |
| Outer close | no values | outer update/test |

**Output order:** (1,3),(1,2),(1,1),(2,3),(2,2),(2,1). **Mistake:** `shift++` with `shift>=1` will not terminate under ordinary numeric operation.

### Example 2.2 â€” Sampling every other shelf (step sizes)

**Requirement:** Two warehouses have shelf identifiers 2,4,6. Print all scheduled sample points; do not inspect odd shelves. Edge: zero warehouses â†’ no output.

**Recognition:** nested loops plus step-size 2. **Pseudocode:** warehouse 1..2 â†’ shelf 2..6 step 2 â†’ log.

```javascript
for (let warehouse = 1; warehouse <= 2; warehouse++) {
  for (let shelf = 2; shelf <= 6; shelf += 2) {
    console.log(warehouse, shelf);
  }
}
```

| Line | Deconstruction |
|---|---|
| Outer header | `let` declares `warehouse`; `=1` initializes; `<=2` checks; `++` advances |
| Inner header | `shelf=2`; `<=6` includes 6; `+=2` means `shelf = shelf + 2` |
| Log | reads both numbers; comma separates two call arguments; logs one pair |
| Closing braces | first finishes inner body; second finishes outer body |

**Output:** (1,2),(1,4),(1,6),(2,2),(2,4),(2,6). **Test:** change limit to 5 â†’ shelf 6 omitted. **Alternative:** step 1 with `if (shelf % 2 === 0)` does more checks and is less direct for this requirement.

### Example 2.3 â€” Dependent inner limit

**Requirement:** In a three-day onboarding program, day 1 has one activity, day 2 has two, and day 3 has three. Print each day/activity pair. This is **not** a rectangular grid.

**Recognition:** â€œday number determines activity countâ€ â†’ inner bound depends on outer variable.

**Pseudocode:** day 1..3 â†’ activity 1..day â†’ print.

```javascript

  for (let activity = 1; activity <= day; activity++) {
    console.log(day, activity);
  }
}
```

| Line | Read â†’ test â†’ update |
|---|---|
| Outer header | initialize `day=1`; test `day<=3`; update after inner |
| Inner header | initialize `activity=1` each day; test `activity<=day` **using current outer value**; update `activity++` |
| Log | read `(day,activity)`; print pair |
| Inner/outer closing | finish inner then advance day |

**Output:** (1,1),(2,1),(2,2),(3,1),(3,2),(3,3). **Count:** `1+2+3=6`, not `3Ã—3=9`. **Edge:** if outer starts at 0, inner has zero iterations on that first day.

## 2.3 `let`, `var`, `const`, blocks and shadowing

| Declaration | Scope | Reassignment | In nested loop |
|---|---|---|---|
| `let` | block / loop | yes | preferred counters; fresh per-iteration bindings |
| `const` | block | no | good for fixed values inside body; unsuitable for updated header binding |
| `var` | function or global-var scope | yes | leaks outside loop within containing function; closure pitfalls |

```javascript
for (let outer = 0; outer < 2; outer++) {
  const label = `Group ${outer}`; // new constant binding per outer body execution
  for (let inner = 0; inner < 2; inner++) {
    const value = outer + inner;
    console.log(label, value);
  }
}
```

**Line ledger:** outer header initializes/tests/updates `outer`; `label` is created inside outer block each successful iteration; inner header creates/tests/updates `inner`; `value` is a fresh constant inside inner body; `console.log` reads both; closing braces return to inner update then outer update. **Output:** Group 0 0; Group 0 1; Group 1 1; Group 1 2.

**Shadowing:**

```javascript
let item = 99;
for (let item = 1; item <= 2; item++) {
  for (let slot = 1; slot <= 2; slot++) console.log(item, slot);
}
console.log(item); // 99: outer `item` was shadowed, not changed
```

**TDZ:** A `let`/`const` binding cannot be accessed before its initialization within its scope. **Closures:** callbacks capturing `let` loop bindings observe per-iteration values; `var` often surprises because one binding is shared. Full closure mechanics are deferred to Functions.

### Example 2.4 â€” Counter vs accumulator placement

**Requirement:** Two departments each process three identical KES 100 forms. Report each department's total and the company grand total. This is educational integer-money arithmetic; real money workflows need robust monetary modeling.

**Recognition:** â€œtotal for each departmentâ€ â†’ reset subtotal inside outer body; â€œgrand totalâ€ â†’ initialize once outside outer loop.

**Pseudocode:** grand=0 â†’ each department: subtotal=0 â†’ each form: subtotal+=100, grand+=100 â†’ print subtotal â†’ print grand.

```javascript
let grandTotal = 0;
for (let department = 1; department <= 2; department++) {
  let departmentTotal = 0;
  for (let form = 1; form <= 3; form++) {
    departmentTotal += 100;
    grandTotal += 100;
  }
  console.log(`Department ${department}: ${departmentTotal}`);
}
console.log(`Grand total: ${grandTotal}`);
```

| Line | Read â†’ compute â†’ state change |
|---|---|
| `let grandTotal = 0` | initialize company total once |
| Outer header | choose department 1 then 2 |
| `let departmentTotal = 0` | reset subtotal for **current** department |
| Inner header | process forms 1,2,3 for each department |
| `departmentTotal += 100` | read current subtotal â†’ add 100 â†’ assign subtotal |
| `grandTotal += 100` | read running company total â†’ add 100 â†’ assign total |
| Inner `}` | next form or finish forms |
| Department log | read department and subtotal â†’ print 300 each time |
| Outer `}` | next department |
| Final log | print grand total 600 |

**Common bug:** moving `departmentTotal=0` outside outer loop produces 300 then 600 rather than 300 then 300. **Edge:** zero forms gives zero subtotals. **Alternative:** calculate `3*100` directly if no per-form logic is needed.

### 2.4 Header pitfalls and scope micro-traces

```javascript
for (let i = 0, j = 4; i < j; i++, j--) {
  console.log(i, j); // 0 4; 1 3
}
```

- `let i=0, j=4`: two initialized bindings; `i<j` checked each time.
- `i++, j--`: evaluate left update then right update; both happen after body.
- After outputs (0,4) and (1,3), updates produce (2,2); test false.

```javascript
let i = 0;
for (; i < 2; ) {
  console.log(i);
  i++;
}
```

- Empty initializer: `i` already exists. Empty update: increment happens in body. Without `i++`, nontermination.

```javascript
for (;;) {
  break;
}
```

- Empty test behaves as always true; `break` exits immediately. `break` is covered in Part 3.

**Dangerous semicolon:** `for (let i=0; i<3; i++);` has an empty loop body; the following `{...}` is a separate block, not the loop body. **`const` header:** `for (const i=0; i<2; i++)` attempts reassignment and throws a `TypeError` on the first update.

# Part 3 â€” Nested conditions and control flow

## 3.1 Control-flow decision matrix

| Construct | Effect inside inner body | Outer loop? | Inner update? |
|---|---|---|---|
| `if (condition)` | conditionally run branch | continues | yes after normal body completion |
| `continue;` | skip rest of **innermost** iteration | continues | **yes** for inner `for` |
| `break;` | exit **innermost** loop | continues | **no** for broken inner loop |
| `continue outerLabel;` | skip to outer loop update | continues at next outer iteration | inner abandoned |
| `break outerLabel;` | exit labeled outer statement | exits | inner abandoned |
| `return` in a function | exit function | exits all contained loops | no updates for exited loops |
| `throw` | abrupt completion; propagate error | usually exits unless caught | no normal updates; `finally` may run |

**Label syntax:** `outer: for (...) { ... }`. A label is a JavaScript identifier followed by `:`; it is **not** a `goto` statement. `continue label` requires a labeled iteration statement; `break label` can target a labeled statement. `break` and `continue` cannot jump across function boundaries.

### Example 3.1 â€” Skip unavailable hotel rooms (`continue`)

**Requirement:** Two floors each have four rooms. Room 3 on every floor is under maintenance and must not appear in the inspection list. All other rooms appear in floor order.

**Recognition:** nested iteration plus â€œskip this itemâ€ â†’ conditional `continue` in inner loop.

**Pseudocode:** for floor â†’ for room â†’ if room=3 skip â†’ print.

```javascript
for (let floor = 1; floor <= 2; floor++) {
  for (let room = 1; room <= 4; room++) {
    if (room === 3) continue;
    console.log(floor, room);
  }
}
```

| Line | Read â†’ decision â†’ next |
|---|---|
| Outer header | floor 1 then 2 |
| Inner header | room 1 through 4, restarted for each floor |
| `if (room === 3) continue` | `===` strict equality; if true skip log and go to `room++` |
| `console.log(floor, room)` | read current pair; log only when room is not 3 |
| Inner/outer braces | normal update and retest |

**Output:** (1,1),(1,2),(1,4),(2,1),(2,2),(2,4). **Trace of skip:** room=3 â†’ condition true â†’ no log â†’ room++ â†’ room=4. **Alternative:** `if(room!==3) console.log(...)` is often clearer for a single statement.

### Example 3.2 â€” Stop at first match within each branch (`break`)

**Requirement:** Two branches have five numbered lockers. For demonstration, locker 3 in every branch is the first locker requiring attention. Print checks only up to and including locker 3 for each branch. Continue to next branch afterward.

**Recognition:** â€œstop within each branch, but keep other branchesâ€ â†’ `break` inner loop.

**Pseudocode:** branch â†’ locker â†’ log â†’ if locker=3 break inner.

```javascript
for (let branch = 1; branch <= 2; branch++) {
  for (let locker = 1; locker <= 5; locker++) {
    console.log(`Check ${branch}-${locker}`);
    if (locker === 3) break;
  }
}
```

| Line | Logic |
|---|---|
| Outer header | choose branch; repeat twice |
| Inner header | start locker 1 each branch; nominal max 5 |
| Log | output checked locker before decision |
| `if (locker === 3) break` | test strict equality; when true exit inner immediately; no `locker++` |
| Braces | after inner exits, outer update executes |

**Output:** 1-1,1-2,1-3,2-1,2-2,2-3. **Boundary:** placing `break` before log excludes locker 3 from output. **Tradeoff:** a condition `locker<=3` avoids `break` if 3 is known ahead of time; `break` is useful when a match is discovered dynamically.

### Example 3.3 â€” Exit both loops on critical incident (labeled `break`)

**Requirement:** Inspect three zones, each with four gates. A critical alarm at zone 2 gate 2 requires stopping **all** inspection immediately. Report each gate reached, including the alarm gate.

**Recognition:** â€œstop all remaining workâ€ â†’ labeled outer exit, or a function `return` when inside a function.

**Pseudocode:** labeled zone loop â†’ gate loop â†’ print â†’ if critical then break label.

```javascript

  for (let gate = 1; gate <= 4; gate++) {
    console.log(zone, gate);
    if (zone === 2 && gate === 2) break inspection;
  }

```

| Line | Logic |
|---|---|
| `inspection:` + outer header | label names the outer iteration statement; initialize/test/update zone |
| Inner header | gate 1..4 for each zone |
| Log | record current gate before alarm check |
| `zone === 2 && gate === 2` | compare both values; `&&` requires both true (short-circuits if first false) |
| `break inspection` | exit labeled outer loop; no remaining gate/zone updates |
| Closing braces | delimit both bodies; control resumes after labeled statement |

**Output:** (1,1),(1,2),(1,3),(1,4),(2,1),(2,2). **Alternative:** put loops in a function and `return` upon alarm; this also exits function and can return a result. **Edge:** alarm never occurs â†’ all 12 gates checked.

### Example 3.4 â€” Skip remaining checks in an entire branch (labeled `continue`)

**Requirement:** Two branches each have four counters. When counter 2 fails a safety test, skip the rest of that branch and start the next branch. Print each counter reached.

**Recognition:** skip rest of **outer** iteration, not merely inner body.

```javascript

    console.log(branch, counter);
    if (counter === 2) continue nextBranch;

```

| Line | Logic |
|---|---|
| Labeled outer header | initialize branch; label enables targeting its continuation |
| Inner header | counter resets to 1 for each branch |
| Log | output reached pair |
| `if(counter===2) continue nextBranch` | if true abandon inner loop; run outer update and test |
| Braces | normal nesting when condition false |

**Output:** (1,1),(1,2),(2,1),(2,2). **Difference from `break;`:** an unlabeled `break` also leaves the inner loop and then advances outer when there is no additional outer-body work; the difference becomes observable if statements follow the inner loop inside the outer body.

### Example 3.5 â€” Multiple rules: classify product by store and shelf

**Requirement:** Two stores each have shelves 1..4. Shelf 1 is priority; shelves 2 and 3 are standard; shelf 4 is restricted. Log classification for each store/shelf.

**Recognition:** repeated combinations plus mutually exclusive categories â†’ `if / else if / else`.

```javascript

  for (let shelf = 1; shelf <= 4; shelf++) {
    let category;
    if (shelf === 1) category = "priority";
    else if (shelf <= 3) category = "standard";
    else category = "restricted";
    console.log(store, shelf, category);
  }

```

| Line | Logic |
|---|---|
| Outer header | choose store |
| Inner header | choose shelf |
| `let category` | declare a binding; currently `undefined` until assignment |
| `if (shelf === 1)` | strict equality; assign priority only for shelf 1 |
| `else if (shelf <= 3)` | checked only if first test false; assign standard for 2,3 |
| `else` | fallback for shelf 4 under valid bounds |
| Log | read store, shelf, assigned category â†’ output |
| Braces | advance shelf then store |

**Output categories per store:** priority, standard, standard, restricted. **Edge:** if shelves can exceed 4, the final `else` would label them restricted; verify whether this matches business rules.

### 3.2 `switch`, functions, errors, mixed loops â€” connection ledger

```javascript
for (let row = 1; row <= 2; row++) {
  for (let col = 1; col <= 3; col++) {
    switch (col) {
      case 1: console.log("first"); break; // exits switch, NOT inner for
      default: console.log("other");
    }
  }
}
```

**Critical:** `break` inside `switch` exits the `switch`, not the surrounding `for`. `continue` inside a `switch` nested in a loop can continue the loop. `return` is only legal inside a function body; `throw` creates an exception; `try/finally` may run cleanup during abrupt exit, and a `finally` that itself exits can override earlier completion. Full semantics: Functions and Errors topics.

**Mixed loops:** `for` can contain `while`, `do...while`, `for...of`, or `for...in` and vice versa. `for...of` visits iterable values; `for...in` enumerates property keys and is generally unsuitable for array element iteration. Their complete API/protocol surface belongs to Arrays, Objects, and Iteration.

### 4.2 Other shapes and traversal orders

```javascript
// Main diagonal only (but tests all 3Ã—3 coordinates)
for (let r = 0; r < 3; r++) {
  for (let c = 0; c < 3; c++) {
    if (r === c) console.log(r, c);
  }
}

// Upper triangle including diagonal
for (let r = 0; r < 3; r++) {
  for (let c = r; c < 3; c++) console.log(r, c);
}

// Column-major traversal: column outermost, row innermost
for (let c = 0; c < 3; c++) {
  for (let r = 0; r < 2; r++) console.log(r, c);
}
```

**Logic ledger:** first snippet checks `r===c` and logs only diagonal matches; second starts `c=r` to avoid below-diagonal visits; third reverses loop nesting order so columns are grouped instead of rows. All use zero-based identifiers; `0` is the first coordinate, unlike earlier one-based business labels.

**Complexity nuance:** logging 3 diagonal cells by scanning 9 coordinates costs `O(nÂ²)` checks; using `for(let i=0;i<n;i++) console.log(i,i)` costs `O(n)`.

### Bug 6.2 â€” Wrong update variable

### Bug 6.5 â€” Variable shadowing

|---|---|---|

## 6.3 Tests and invariants

**Invariant:** a property that stays true at a specified point during execution. Example: at the beginning of each inner iteration of a 2Ã—3 rectangular loop, `row` is 1 or 2 and `seat` is 1,2,or3. A running total equals the number of qualifying combinations processed so far.

```javascript
function countPairs(rows, columns) {
  if (!Number.isInteger(rows) || !Number.isInteger(columns) || rows < 0 || columns < 0) {
    throw new RangeError("Counts must be nonnegative integers");
  }
  let count = 0;
  for (let row = 0; row < rows; row++) {
    for (let column = 0; column < columns; column++) count++;
  }
  return count;
}
console.assert(countPairs(3, 4) === 12, "3Ã—4 failed");
console.assert(countPairs(0, 4) === 0, "zero rows failed");
console.assert(countPairs(2, 0) === 0, "zero columns failed");
console.assert(countPairs(1, 1) === 1, "single pair failed");
```

| Line | Logic |
|---|---|
| `function countPairs(rows,columns)` | define reusable function with two parameters; full functions later |
| `Number.isInteger` and comparisons | reject fractional, negative, NaN, and nonnumber counts |
| `throw new RangeError(...)` | stop with an exception for invalid domain |
| `let count=0` | initialize result |
| Outer `for` | row indexes 0..rows-1 |
| Inner `for` | column indexes 0..columns-1 |
| `count++` | count every visited pair |
| `return count` | return computed result to caller |
| `console.assert(condition,message)` | report failed expectation in supporting runtimes; does not normally throw |

**Testing matrix:** zero, one, normal, large, invalid negative, fractional, `NaN`, strings, duplicates, and variable bounds. `console.assert` behavior differs by runtime and is not a replacement for a full test runner. For errors, use `try/catch` or a test framework's `toThrow` assertion.

## 6.4 Complexity and optimization

| Pattern | Work | Time | Auxiliary space |
|---|---|---|---|
| fixed rectangle nÃ—m | n*m body visits | `O(nm)` | `O(1)` counters |
| square nÃ—n | nÂ² | `O(nÂ²)` | `O(1)` |
| triangle 1..n | n(n+1)/2 | `O(nÂ²)` | `O(1)` |
| unique pairs | n(nâˆ’1)/2 | `O(nÂ²)` | `O(1)` |
| three dimensions aÃ—bÃ—c | abc | `O(abc)` | `O(1)` |
| early-exit search | 1..nm checks if nonempty | worst `O(nm)` | `O(1)` |
| build output string | depends on concatenation/runtime | account for string size | `O(output size)` |

**Complexity is about input growth, not just nesting depth.** A loop with inner bound fixed at 3 is `O(n)`, not `O(nÂ²)`. A nested loop whose inner loop runs once is also `O(n)`. A pair-generation algorithm with nÂ² outputs cannot run in subquadratic time if it must actually emit all pairs.

**Optimization order:** (1) correct algorithm â†’ (2) validate inputs â†’ (3) measure bottleneck â†’ (4) reduce unnecessary visits, e.g. `j=i+1` â†’ (5) consider lookup structures such as `Set`/`Map` when data supports them â†’ (6) benchmark representative workloads. Do not replace readable loops without evidence.

### Example 6.6 â€” Direct diagonal instead of scanning entire grid

**Requirement:** For a square grid of size 4, print only diagonal coordinates. Compare a full scan with direct diagonal iteration.

```javascript
// Full scan: 16 coordinate checks, 4 outputs
for (let row = 0; row < 4; row++) {
  for (let column = 0; column < 4; column++) {
    if (row === column) console.log(row, column);
  }
}
// Direct: 4 visits, 4 outputs
for (let index = 0; index < 4; index++) {
  console.log(index, index);
}
```

| Line | Logic |
|---|---|
| Full outer | row 0..3 |
| Full inner | column 0..3 for each row |
| `if(row===column)` | test equality; only 4 coordinates pass |
| Direct header | index 0..3 |
| Direct log | use same index for row and column; no unnecessary checks |

**Result:** same output (0,0),(1,1),(2,2),(3,3). **Growth:** full scan `O(nÂ²)` vs direct `O(n)`. **Lesson:** do not use nested loops when the requirement can be expressed with one loop.

### Example 7.1 â€” Jagged nested arrays (preview; not full Arrays module)

**Requirement:** Three classes have 2, 1, and 3 student IDs respectively. Print all existing IDs; do not assume equal class sizes.


| Line | Logic |
|---|---|
| `classes = [...]` | array containing three arrays; values are IDs |

### Example 7.2 â€” Async sequencing trap (preview)

**Requirement:** An API client must send requests for every branch/day combination in order. Assume `sendRequest` is an existing asynchronous function. The code below is illustrative and not runnable without that function.

```javascript

  for (let branch = 1; branch <= 2; branch++) {
    for (let day = 1; day <= 3; day++) {

    }
  }

```

| Line | Logic |
|---|---|
| `async function` | declares function able to use `await` |
| Outer header | branch 1..2 |
| Inner header | day 1..3 |

## 7.2 Security, accessibility, compatibility

- **Security:** validate loop bounds to avoid denial-of-service workloads; cap output size; do not interpolate untrusted data into `innerHTML` (use `textContent` or safe DOM APIs); prevent accidental repeated financial mutations; make payment processing idempotent at the system boundary.
- **Accessibility:** when rendering tabular data, use semantic HTML tables with headers; keyboard navigation and meaningful announcements are DOM concerns, not built into nested loops.
- **Compatibility:** ordinary `for`, `let`, labels, `break`, `continue`, and template literals are standardized; modern supported browsers and Node.js implement them. `let` and template literals are ES2015; legacy pre-ES2015 environments require different syntax. No experimental proposal is required for these examples.
- **Numeric edge cases:** floating-point increments can accumulate rounding error; `NaN` comparisons fail; very large integers lose precision beyond `Number.MAX_SAFE_INTEGER`; `BigInt` requires consistent operand types. Validate numeric bounds and choose integer counters when possible.
- **Mutations:** modifying a collection while iterating can skip/revisit entries depending on iteration strategy; treat this in depth under Arrays/Objects.

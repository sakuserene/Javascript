## 2. What is EventTarget?

`EventTarget` is a web-platform interface for objects that can register listeners and dispatch events. Its three instance methods are:

| Method | Purpose | Return |
|---|---|---|
| `addEventListener(type, callback, options)` | Register listener | `undefined` |
| `removeEventListener(type, callback, options)` | Remove matching listener | `undefined` |
| `dispatchEvent(event)` | Dispatch event synchronously | Boolean |

```javascript
const target = new EventTarget();

function handleHello(event) {
  console.log(event.type);
}

target.addEventListener("hello", handleHello);
target.dispatchEvent(new Event("hello"));
target.removeEventListener("hello", handleHello);
```

Output:

```text
hello
```

**Trace:** Construct target -> define callback -> register callback -> construct event -> dispatch -> callback logs type -> remove callback. The event object and the event target are different objects.

`EventTarget` is not synonymous with `Element`. A standalone `new EventTarget()` has no DOM parent, styling, or `closest()` method.

## 3. Understanding event.target

`event.target` is a read-only property identifying the event target, subject to DOM retargeting rules. Its value can be an `EventTarget` or `null`.

```html
<button id="save"><span id="label">Save</span></button>
```

```javascript
const save = document.getElementById("save");

save.addEventListener("click", function (event) {
  console.log(event.target);
});
```

Clicking the span normally makes `event.target` the span; clicking the button outside the span normally makes it the button. Thus, the target is **not necessarily** the element on which the callback was registered.

Before first dispatch:

```javascript
const event = new Event("hello");
console.log(event.target); // null
```

After dispatch to a standalone target, the event normally retains its target:

```javascript
const target = new EventTarget();
const event = new Event("hello");
target.dispatchEvent(event);
console.log(event.target === target); // true
```

Do not assume that every `event.target` has `style`, `id`, `dataset`, or `closest()`. Those are associated with particular DOM interfaces, not all `EventTarget` objects.

## 4. Understanding event.currentTarget

`event.currentTarget` is a read-only property identifying the target whose listener is **currently being invoked**.

```html
<div id="parent"><button id="child">Click</button></div>
```

```javascript
const parent = document.getElementById("parent");
parent.addEventListener("click", function (event) {
  console.log(event.target.id);        // child, if button clicked
  console.log(event.currentTarget.id); // parent
});
```

`currentTarget` is set during a listener invocation and normally returns to `null` when dispatch completes. Read it while the callback is running or save a reference synchronously.

## 5. When the properties are equal

For an event whose target is the button itself, a listener registered on the button ordinarily sees:

```javascript
button.addEventListener("click", function (event) {
  console.log(event.target === event.currentTarget); // true
  console.log(event.eventPhase === Event.AT_TARGET); // true
});
```

If a nested span is the actual target, a button listener may instead see `false`. Also, Shadow DOM retargeting can change what different listeners observe.

## 6. When the properties differ

```html
<section id="section">
  <div id="container">
    <button id="button">Click</button>
  </div>
</section>
```

```javascript
const section = document.getElementById("section");
const container = document.getElementById("container");
const button = document.getElementById("button");

for (const element of [button, container, section]) {
  element.addEventListener("click", function (event) {
    console.log(event.target.id, event.currentTarget.id);
  });
}
```

For a click directly on the button:

```text
button button
button container
button section
```

| Listener invocation | `target` | `currentTarget` |
|---|---|---|
| Button | Button | Button |
| Container | Button | Container |
| Section | Button | Section |

The target identifies where the event originated in this light-DOM example. `currentTarget` follows the listener currently being called.

## 7. Complete EventTarget API

### 7.1 addEventListener()

Signatures:

```javascript
target.addEventListener(type, callback);
target.addEventListener(type, callback, captureBoolean);
target.addEventListener(type, callback, optionsObject);
```

| Parameter | Meaning |
|---|---|
| `type` | Case-sensitive event type string |
| `callback` | Function, object with `handleEvent()`, or `null` |
| `options` | Boolean capture flag or listener options object |

| Option | Type | Standard default | Meaning |
|---|---|---|---|
| `capture` | Boolean | `false` | Use capture listener |
| `once` | Boolean | `false` | Remove after first invocation |
| `passive` | Boolean | Generally `false` | Listener will not cancel default action |
| `signal` | `AbortSignal` | Not supplied | Remove when aborted |

**Compatibility caveat:** Some browsers apply passive-by-default behavior for certain touch and wheel listeners on specific document-level targets. Explicitly choose the desired option when it matters.

```javascript
const controller = new AbortController();

button.addEventListener("click", handleClick, {
  capture: false,
  once: false,
  passive: false,
  signal: controller.signal
});

// Later: controller.abort();
```

A listener registered with an already-aborted signal is not added. Identical listener registrations (same type, callback identity, and capture flag) do not create duplicate registrations. `addEventListener()` returns `undefined`.

### 7.2 removeEventListener()

```javascript
target.removeEventListener(type, callback);
target.removeEventListener(type, callback, captureBoolean);
target.removeEventListener(type, callback, { capture: true });
```

Removal matches **type, callback identity, and capture**. `once`, `passive`, and `signal` are not part of the removal matching key. Removing a listener that is not registered is harmless. Return: `undefined`.

```javascript
function handleClick(event) {
  console.log(event.type);
}
button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

### 7.3 dispatchEvent()

```javascript
const result = target.dispatchEvent(new Event("hello", {
  cancelable: true
}));
```

`dispatchEvent()` takes an `Event`, dispatches it synchronously, and returns `false` when a cancelable event is canceled during dispatch; otherwise it returns `true`. It throws `InvalidStateError` if the event is already being dispatched or has an empty type. Passing a value that is not an `Event` causes a type error. Exceptions thrown *inside listeners* are generally reported as uncaught rather than propagated to the `dispatchEvent()` caller. Async listener promises are not awaited.

### 7.4 API boundaries

`dispatchEvent()` belongs to **EventTarget**. `preventDefault()`, `stopPropagation()`, `stopImmediatePropagation()`, and `composedPath()` belong to **Event**. `closest()` and `matches()` belong to **Element**. `contains()` belongs to **Node**.

## 8. Kinds of event targets

| Type | Example | Typical events |
|---|---|---|
| `Window` | `window` | `resize`, `load` |
| `Document` | `document` | `DOMContentLoaded`, `keydown` |
| `Element` | `document.querySelector("button")` | `click`, `pointerdown` |
| `Text` node | `document.createTextNode("Hi")` | Programmatic custom events |
| Standalone `EventTarget` | `new EventTarget()` | Programmatic events |
| `AbortSignal` | `controller.signal` | `abort` |
| `WebSocket` | Socket instance | `message`, `close` |
| `MediaQueryList` | `matchMedia("(max-width: 600px)")` | `change` |
| `FileReader` | Reader instance | `load`, `error` |

Safe type checks:

```javascript
function colorTarget(event) {
  if (event.target instanceof HTMLElement) {
    event.target.style.color = "red";
  }
}
```

`HTMLElement` covers HTML elements, not SVG elements. Use `Element` when you need element-level methods common to HTML and SVG.

## 9. DOM nodes and propagation paths

```text
Window
  |
Document
  |
HTML
  |
BODY
  |
DIV
  |
BUTTON
  |
SPAN <- click target
```

A typical composed, bubbling click can travel outward along this path. An ordinary standalone `EventTarget` does not have DOM ancestors, even if its event has `bubbles: true`.

`event.composedPath()` reports the exposed dispatch path while dispatch is active. Closed shadow roots can hide internal nodes. It generally returns an empty array outside active dispatch.

## 10. Propagation phases and currentTarget

| Phase | Constant | Value |
|---|---|---|
| None | `Event.NONE` | 0 |
| Capturing | `Event.CAPTURING_PHASE` | 1 |
| At target | `Event.AT_TARGET` | 2 |
| Bubbling | `Event.BUBBLING_PHASE` | 3 |

```javascript
parent.addEventListener("click", function (event) {
  console.log("capture", event.eventPhase, event.currentTarget.id);
}, true);

child.addEventListener("click", function (event) {
  console.log("target", event.eventPhase, event.currentTarget.id);
});

parent.addEventListener("click", function (event) {
  console.log("bubble", event.eventPhase, event.currentTarget.id);
});
```

For a click on `child`:

```text
capture 1 parent
target 2 child
bubble 3 parent
```

A capture listener registered on the actual target runs in the **at-target** phase (`2`), not the capturing phase (`1`). An event with `bubbles: false` can still be observed by ancestor capture listeners.

## 11. Event delegation

Event delegation registers one listener on an ancestor and determines the relevant descendant from the event target.

```html
<ul id="menu">
  <li><button data-action="save">Save</button></li>
  <li><button data-action="edit">Edit</button></li>
  <li><button data-action="delete">Delete</button></li>
</ul>
```

```javascript
const menu = document.getElementById("menu");

menu.addEventListener("click", function (event) {
  if (!(event.target instanceof Element)) return;

  const button = event.target.closest("button");
  if (!button || !menu.contains(button)) return;

  console.log(button.dataset.action);
});
```

Click Save -> `save`; click Edit -> `edit`; click Delete -> `delete`.

**Why delegation?** One listener handles existing and newly inserted matching descendants. The ancestor's `currentTarget` stays the menu, while `target` identifies the element involved in the click. The containment check ensures the selected button belongs to the intended component.

## 12. matches, closest, and contains

| API | Owner | Parameter | Return | Caveat |
|---|---|---|---|---|
| `matches(selectors)` | `Element` | CSS selector string | Boolean | Invalid selector throws `SyntaxError` |
| `closest(selectors)` | `Element` | CSS selector string | `Element` or `null` | Invalid selector throws `SyntaxError` |
| `contains(otherNode)` | `Node` | `Node` or `null` | Boolean | A node contains itself |

```javascript
if (event.target instanceof Element) {
  console.log(event.target.matches(".delete-button"));
  console.log(event.target.closest("button"));
}

console.log(menu.contains(menu)); // true
```

`matches()` checks only the element itself. `closest()` checks the element and its ancestors. `contains()` checks whether a node is within another node's subtree (or is the same node).

## 13. currentTarget versus this

An ordinary event listener function is invoked with `this` set to the current event target:

```javascript
button.addEventListener("click", function (event) {
  console.log(this === event.currentTarget); // true
});
```

Arrow functions have lexical `this`:

```javascript
button.addEventListener("click", (event) => {
  console.log(event.currentTarget); // button
  // 'this' comes from the surrounding scope, not the listener call.
});
```

Prefer `event.currentTarget` when you want to make the event-specific meaning explicit. Detailed prototype and class concepts remain deferred to the OOP module.

## 14. Asynchronous callbacks

Incorrect assumption:

```javascript
button.addEventListener("click", async function (event) {
  await Promise.resolve();
  console.log(event.currentTarget); // normally null
});
```

Correct:

```javascript
button.addEventListener("click", async function (event) {
  const current = event.currentTarget;
  await Promise.resolve();
  current.textContent = "Completed";
});
```

**Trace:** callback starts -> `currentTarget` is button -> save button -> `await` suspends callback -> synchronous dispatch finishes -> `currentTarget` resets -> continuation resumes -> saved button reference still works.

## 15. Shadow DOM retargeting

```html
<div id="host"></div>
```

```javascript
const host = document.getElementById("host");
const shadow = host.attachShadow({ mode: "open" });
const innerButton = document.createElement("button");
innerButton.textContent = "Inside shadow root";
shadow.appendChild(innerButton);

document.addEventListener("click", function (event) {
  console.log(event.target); // normally the host
  console.log(event.composedPath()); // can expose open-shadow internals
});
```

When a composed click originates inside the shadow tree, outside listeners usually see the host as `event.target`. This is **retargeting**. A closed shadow root does not expose its internal nodes to outside observers through `composedPath()`.

Custom events intended to bubble beyond a shadow root commonly use both `bubbles: true` and `composed: true`.

## 16. Common mistakes and debugging

| Mistake | Problem | Fix |
|---|---|---|
| Assuming `target === currentTarget` | Descendant clicks | Inspect both |
| Calling `closest()` on any target | Not every target is `Element` | Type-check |
| Reading `currentTarget` after `await` | Dispatch may be complete | Save synchronously |
| Styling `event.target` to style listener's button | Nested span may be target | Use `currentTarget` |
| Assuming every event bubbles | Some do not | Check `bubbles` |
| Assuming `this` in arrow callback is target | Arrow `this` is lexical | Use `currentTarget` |
| Ignoring shadow boundaries | Retargeting | Inspect `composedPath()` |

```javascript
function debugEvent(event) {
  console.group(event.type);
  console.log("target", event.target);
  console.log("currentTarget", event.currentTarget);
  console.log("phase", event.eventPhase);
  console.log("bubbles", event.bubbles);
  console.log("path", event.composedPath());
  console.groupEnd();
}

document.addEventListener("click", debugEvent);
```

### script.js

```javascript
const outer = document.getElementById("outer");
const middle = document.getElementById("middle");
const inner = document.getElementById("inner");
const details = document.getElementById("details");
const history = document.getElementById("history");
const clearButton = document.getElementById("clear");

function describeTarget(target) {
  if (target instanceof Element) {
    return target.tagName.toLowerCase() +
      (target.id ? "#" + target.id : "");
  }
  if (target === window) return "window";
  if (target === document) return "document";
  return String(target);
}

function inspectEvent(event) {
  const targetName = describeTarget(event.target);
  const currentName = describeTarget(event.currentTarget);
  const phase = event.eventPhase;

  details.textContent =
    "Event type: " + event.type + "\n" +
    "Target: " + targetName + "\n" +
    "Current target: " + currentName + "\n" +
    "Phase: " + phase + "\n" +
    "Same target: " + (event.target === event.currentTarget);

  const item = document.createElement("li");
  item.textContent = targetName + " -> " + currentName +
    " (phase " + phase + ")";
  history.appendChild(item);
}

outer.addEventListener("click", inspectEvent);
middle.addEventListener("click", inspectEvent);
inner.addEventListener("click", inspectEvent);

clearButton.addEventListener("click", function () {
  history.replaceChildren();
  details.textContent = "No event yet.";
});
```

### Code walkthrough

1. `getElementById()` obtains DOM references.
2. `describeTarget()` creates readable names; it checks `Element` first, then `window` and `document`.
3. `inspectEvent()` is one reusable callback registered on three different elements.
4. `event.target` identifies the clicked element; `currentTarget` identifies the listener currently running.
5. `textContent` displays plain text safely rather than interpreting it as HTML.
6. `createElement("li")` creates a new history entry; `appendChild()` adds it to the list.
7. `replaceChildren()` removes old history entries.

### Execution trace

Click the text inside the inner button:

| Order | Listener | Target | Current target | Phase |
|---|---|---|---|---|
| 1 | Inner button | Span | Button | 3 |
| 2 | Middle div | Span | Middle | 3 |
| 3 | Outer section | Span | Outer | 3 |

Because the clicked span is the target and no listener is registered on the span, the button listener executes in **bubbling phase 3**. If the button itself is clicked, the button listener sees phase **2**, followed by phases **3, 3** on its ancestors.

**Challenge:** Add capture listeners to the outer and middle elements and compare execution order and `eventPhase`.

### script.js

```javascript
const taskForm = document.getElementById("taskForm");
const taskInput = document.getElementById("taskInput");
const taskList = document.getElementById("taskList");
const status = document.getElementById("status");
let nextTaskId = 1;

function createTask(text) {
  const item = document.createElement("li");
  item.dataset.taskId = String(nextTaskId);
  nextTaskId += 1;

  const taskText = document.createElement("span");
  taskText.className = "task-text";
  taskText.textContent = text;

  const completeButton = document.createElement("button");
  completeButton.type = "button";
  completeButton.dataset.action = "complete";
  completeButton.textContent = "Complete";

  const deleteButton = document.createElement("button");
  deleteButton.type = "button";
  deleteButton.className = "delete";
  deleteButton.dataset.action = "delete";
  deleteButton.textContent = "Delete";

  item.append(taskText, completeButton, deleteButton);
  return item;
}

function handleTaskSubmit(event) {
  event.preventDefault();
  const text = taskInput.value.trim();
  if (text === "") {
    status.textContent = "Enter a task.";
    return;
  }
  taskList.appendChild(createTask(text));
  taskInput.value = "";
  taskInput.focus();
  status.textContent = "Task added.";
}

function handleTaskClick(event) {
  if (!(event.target instanceof Element)) return;

  const button = event.target.closest("button");
  if (!button || !taskList.contains(button)) return;

  const task = button.closest("li[data-task-id]");
  if (!task || !taskList.contains(task)) return;

  const action = button.dataset.action;

  if (action === "complete") {
    task.classList.toggle("completed");
    const completed = task.classList.contains("completed");
    button.textContent = completed ? "Undo" : "Complete";
    status.textContent = completed ? "Task completed." : "Task reopened.";
  }

  if (action === "delete") {
    task.remove();
    status.textContent = "Task deleted.";
  }
}

taskForm.addEventListener("submit", handleTaskSubmit);
taskList.addEventListener("click", handleTaskClick);
```

### Code walkthrough

1. `createTask(text)` creates a list item, text span, and two buttons.
2. `dataset.taskId` and `dataset.action` store string metadata in `data-*` attributes.
3. `append()` inserts multiple child nodes at once.
4. `handleTaskSubmit()` prevents navigation and constructs a new task.
5. `handleTaskClick()` runs for clicks that bubble to `taskList`.
6. `instanceof Element` protects access to `closest()`.
7. `closest("button")` finds a button even when its nested content is clicked.
8. `contains()` verifies that the button and task belong to this list.
9. `classList.toggle()` switches completion state; `classList.contains()` reads the new state.
10. `task.remove()` deletes the selected task from the DOM.

| 4 | `createTask()` | Task DOM nodes created |
| 5 | `appendChild()` | Task appears |
| 6 | Click Complete | Click bubbles to list |
| 7 | `closest("button")` | Action button found |
| 8 | `dataset.action` | `complete` |
| 9 | `classList.toggle()` | Completed style applied |
| 10 | Click Delete | Delegated handler removes task |

**Why this matters:** Dynamically created task buttons need no individually registered click handlers. The single listener on the list handles all of them.

## 19. Ten interview questions and answers

**1. What is `EventTarget`?**  
An interface implemented by objects capable of registering listeners and dispatching events. Its core methods are `addEventListener()`, `removeEventListener()`, and `dispatchEvent()`.

**2. What is `event.target`?**  
The target associated with the event, subject to retargeting. It is not necessarily the element whose listener is executing.

**3. What is `event.currentTarget`?**  
The target whose event listener is currently being invoked.

**4. When are `target` and `currentTarget` different?**  
When an ancestor's listener handles an event originating from a descendant, for example during bubbling.

**5. Is `event.target` always an `HTMLElement`?**  
No. It can be `Window`, `Document`, another node, or a standalone `EventTarget`.

**6. What is event delegation?**  
A technique where one ancestor listener handles events originating from multiple descendants, usually using `target`, `closest()`, and selector matching.

**7. How do `matches()` and `closest()` differ?**  
`matches()` tests the current element and returns a Boolean. `closest()` searches the element and its ancestors and returns the nearest matching element or `null`.

**8. Why can `currentTarget` become `null` after `await`?**  
The synchronous dispatch may have completed while the async callback was suspended. Save `currentTarget` before awaiting.

**9. What is Shadow DOM retargeting?**  
When an event crosses a shadow boundary, outside listeners may see the shadow host as `event.target` rather than the internal originating element.

**10. How does `this` relate to `currentTarget`?**  
Inside an ordinary event listener function, `this` normally equals `currentTarget`. Arrow functions retain lexical `this` instead.

## 20. Ten coding exercises with solutions

### Exercise 1 - Log a clicked element ID

```javascript
document.addEventListener("click", function (event) {
  if (event.target instanceof Element) {
    console.log(event.target.id);
  }
});
```

**Explanation:** Type-check first because arbitrary event targets do not necessarily have an `id` property.

### Exercise 2 - Log currentTarget

```javascript
const button = document.getElementById("myButton");
button.addEventListener("click", function (event) {
  console.log(event.currentTarget === button);
});
```

**Explanation:** The listener's current target is the button.

### Exercise 3 - Compare target and currentTarget

```javascript
button.addEventListener("click", function (event) {
  console.log("Same:", event.target === event.currentTarget);
});
```

**Explanation:** Clicking nested content may produce `false`.

### Exercise 4 - Standalone EventTarget

```javascript
const target = new EventTarget();
target.addEventListener("hello", event => console.log(event.type));
target.dispatchEvent(new Event("hello"));
```

**Output:** `hello`.

### Exercise 5 - Use matches()

```javascript
document.addEventListener("click", function (event) {
  if (event.target instanceof Element &&
      event.target.matches(".save-button")) {
    console.log("Save");
  }
});
```

**Explanation:** Only an element matching `.save-button` itself triggers the action.

### Exercise 6 - Use closest()

```javascript
document.addEventListener("click", function (event) {
  if (!(event.target instanceof Element)) return;
  const button = event.target.closest("button");
  if (button) console.log(button.textContent.trim());
});
```

**Explanation:** Works even when the click targets a span nested in a button.

### Exercise 7 - Remove a listener

```javascript
const target = new EventTarget();
function handler() { console.log("Hello"); }
target.addEventListener("hello", handler);
target.dispatchEvent(new Event("hello"));
target.removeEventListener("hello", handler);
target.dispatchEvent(new Event("hello"));
```

**Output:** `Hello` only once.

### Exercise 8 - Save currentTarget before await

```javascript
button.addEventListener("click", async function (event) {
  const current = event.currentTarget;
  await Promise.resolve();
  console.log(current === button);
});
```

**Output:** `true`.

### Exercise 9 - Delegate list clicks

```javascript
const list = document.getElementById("myList");
list.addEventListener("click", function (event) {
  if (!(event.target instanceof Element)) return;
  const item = event.target.closest("li");
  if (!item || !list.contains(item)) return;
  console.log(item.textContent.trim());
});
```

**Explanation:** One list listener handles all list items.

### Exercise 10 - Reusable debugger

```javascript
function debugEvent(event) {
  console.log({
    type: event.type,
    target: event.target,
    currentTarget: event.currentTarget,
    phase: event.eventPhase,
    path: event.composedPath()
  });
}
document.addEventListener("click", debugEvent);
document.addEventListener("keydown", debugEvent);
```

**Explanation:** The same callback inspects multiple event types.

## 21. Ten-question quiz with explanations

**1. Which interface defines `addEventListener()`?**  
A. `Event` B. `EventTarget` C. `ElementStyle` D. `NodeList`  
**Answer: B.** `EventTarget` defines listener registration and event dispatch.

**2. What does `currentTarget` identify?**  
A. Always the clicked descendant B. The listener's current target C. A CSS class D. The first ancestor  
**Answer: B.** It identifies the target whose listener is executing.

**3. Can `event.target` be something other than an HTMLElement?**  
A. Yes B. No  
**Answer: A.** `Document`, `Window`, and standalone event targets are examples.

**4. What does `closest("button")` return?**  
A. All buttons B. Nearest matching element or `null` C. Boolean D. NodeList  
**Answer: B.** It searches the element itself and its ancestors.

**5. What does `matches(".active")` return?**  
A. String B. Element C. Boolean D. Array  
**Answer: C.** It tests whether the element matches a selector.

**6. Which technique uses a parent listener to handle child events?**  
A. Polling B. Event delegation C. JSON parsing D. Throttling  
**Answer: B.** Delegation uses propagation and target inspection.

**7. What can happen to `currentTarget` after `await`?**  
A. Always becomes window B. Can be `null` C. Becomes original target D. Becomes a string  
**Answer: B.** Dispatch may finish while the async function is suspended.

**8. Can Shadow DOM affect `event.target`?**  
A. No B. Only keyboard events C. Yes, through retargeting D. Only custom events  
**Answer: C.** Shadow boundary retargeting can expose the host.

**9. Does a standalone `EventTarget` automatically have DOM ancestors?**  
A. Always B. No C. Only when bubbles is true D. Only when cancelable is true  
**Answer: B.** It does not automatically participate in a DOM tree.

**10. What does `dispatchEvent()` return?**

**Answer: C.** It returns `false` for a cancelable event canceled during dispatch and `true` otherwise.

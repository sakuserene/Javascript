## 2. What is addEventListener?

`addEventListener()` is a method defined by the browser's `EventTarget` interface. It registers a callback function or listener object to respond when a matching event is dispatched to an event target.

```html
<button id="myButton" type="button">Click Me</button>
<script>
  const button = document.getElementById("myButton");
  button.addEventListener("click", function () {
    console.log("Button clicked");
  });
</script>
```

**Timeline:**

```text
1. Browser parses the button element.
2. JavaScript obtains a reference to that button.
3. JavaScript creates a callback function.
4. addEventListener registers the callback for "click".
5. Registration finishes; callback has NOT executed.
6. User clicks the button.
7. Browser dispatches a click event.
8. Registered callback executes and prints "Button clicked".
```

The browser does not require you to write a loop repeatedly checking whether the button was clicked.
## 3. Syntax and every token

General form:

```javascript
target.addEventListener(type, callback, options);
```

The third argument is optional. An older boolean form also exists:

```javascript
target.addEventListener(type, callback, useCapture);
```

| Part | Meaning |
| --- | --- |
| `target` | An object implementing `EventTarget` |
| `.` | Property-access operator; looks up a member of the object |
| `addEventListener` | Name of the registration method |
| `(` | Begins the method's argument list |
| `type` | Event-type string, such as `"click"` |
| `,` | Separates arguments |
| `callback` | Function, listener object, or nullish callback |
| `options` | Optional configuration object or capture boolean |
| `)` | Ends the argument list |
| `;` | Ends the JavaScript statement |

Concrete example:

```javascript
const button = document.getElementById("myButton");
button.addEventListener("click", handleClick);
```

Detailed evaluation:

1. `const` declares a binding named `button`.
2. `document` refers to the current document.
3. `.getElementById` accesses the document's lookup method.
4. `("myButton")` calls that method with the ID string.
5. The returned element reference is stored in `button`.
6. JavaScript looks up `.addEventListener` on that element.
7. It evaluates `"click"` to a string value.
8. It evaluates `handleClick` to a function object **without calling it**.
9. The method records the listener registration.
10. The method returns `undefined` and the script proceeds.

**Important:** `addEventListener()` is not the same as the callback function. The method performs registration; the callback performs your event response.
## 4. Which objects support it?

Many browser objects implement `EventTarget`:

```javascript
window.addEventListener("resize", handleResize);
document.addEventListener("keydown", handleKeyDown);
document.body.addEventListener("click", handleBodyClick);

const input = document.querySelector("input");
input.addEventListener("input", handleInput);
```

The handler identifiers in this example are assumed to refer to previously defined functions.

You can create a separate event target:

```javascript
const target = new EventTarget();
target.addEventListener("hello", () => console.log("Hello!"));
target.dispatchEvent(new Event("hello"));
```

Output: `Hello!`

But an ordinary object does **not** automatically have this method:

```javascript
const person = { name: "Alice" };
person.addEventListener("click", () => {}); // TypeError
```

A frequent error is `Cannot read properties of null (reading 'addEventListener')`. This usually means a DOM lookup returned `null`, often because the element ID is wrong or the script ran before the element was parsed. Use `<script src="script.js" defer></script>` when appropriate.
## 5. Argument one: event type

```javascript
button.addEventListener("click", handleClick);
```

The first argument, `"click"`, is a **string literal**. Quotation marks tell JavaScript to use the literal characters `c`, `l`, `i`, `c`, `k`.

Compare:

```javascript
button.addEventListener("click", handleClick); // Correct
button.addEventListener(click, handleClick);   // Refers to an identifier named click
```

The second form is not a string. If no `click` binding exists, it causes a `ReferenceError`; if a binding exists, its value is used instead.

Event names are case-sensitive:

```javascript
"click" !== "Click"
"click" !== "CLICK"
```

`!==` means *strictly not equal*. Both expressions above evaluate to `true`.

| Category | Common event types |
| --- | --- |
| Mouse | `click`, `dblclick`, `mousedown`, `mouseup`, `mousemove` |
| Pointer | `pointerdown`, `pointerup`, `pointermove` |
| Keyboard | `keydown`, `keyup` |
| Form | `input`, `change`, `submit`, `reset` |
| Focus | `focus`, `blur`, `focusin`, `focusout` |
| Browser | `resize`, `scroll`, `load`, `DOMContentLoaded` |
| Media | `play`, `pause`, `ended`, `timeupdate` |
| Drag | `dragstart`, `dragover`, `drop` |

An event type alone does not make an event happen. For example, registering `"click"` does not automatically click the button.
## 6. Argument two: callback

A **callback** is a function passed to another function or API to be invoked when appropriate.

**Named function:**

```javascript
function showMessage() {
  console.log("Hello");
}
button.addEventListener("click", showMessage);
```

**Anonymous function expression:**

```javascript
button.addEventListener("click", function () {
  console.log("Hello");
});
```

**Arrow function:**

```javascript
button.addEventListener("click", () => {
  console.log("Hello");
});
```

Token-by-token arrow syntax:

```javascript
(event) => {
  console.log(event.type);
}
```

| Token | Meaning |
| --- | --- |
| `(` and `)` | Surround the parameter list |
| `event` | Local parameter that receives the dispatched event |
| `=>` | Defines an arrow function |
| `{` and `}` | Enclose the function body |
| `event.type` | Reads the event's type property |
| `console.log(...)` | Prints a value to the console |

Arrow functions do **not** have their own `this`. Regular function callbacks invoked by the DOM event listener mechanism receive `this` equal to `event.currentTarget`. To write code that works with either callback style, use `event.currentTarget` explicitly.
## 7. Function reference versus invocation

```javascript
function greet() {
  console.log("Hello");
}
```

- `greet` evaluates to the function object, without running it.
- `greet()` invokes the function now.

Correct:

```javascript
button.addEventListener("click", greet);
```

Incorrect for delayed execution:

```javascript
button.addEventListener("click", greet());
```

Detailed trace of the incorrect example:

```text
Step 1: Evaluate the second argument greet().
Step 2: The parentheses invoke greet immediately.
Step 3: Console prints Hello.
Step 4: greet reaches its end with no return statement.
Step 5: greet returns undefined.
Step 6: addEventListener receives undefined, treated as a null listener.
Step 7: No greet callback is registered for later clicks.
```

The key principle: **Passing a function** and **calling a function** are different operations.

For a function that actually returns another function, `factory()` could legitimately be used as a listener argument. What matters is that the final argument must be an appropriate callback or listener object.
## 8. Passing arguments to callbacks

Suppose the handler needs a name:

```javascript
function greet(name) {
  console.log("Hello " + name);
}
```

Do not register `greet("Alice")` directly if you want to defer the call. Wrap it:

```javascript
button.addEventListener("click", function () {
  greet("Alice");
});
```

Or:

```javascript
button.addEventListener("click", () => {
  greet("Alice");
});
```

**Breakdown of the wrapper:**

1. `() => { ... }` creates a new function object.
2. `addEventListener` registers that function object.
3. The inner `greet("Alice")` statement has not yet executed.
4. On click, the browser invokes the wrapper.
5. The wrapper invokes `greet` with `"Alice"`.
6. `"Hello " + name` concatenates two strings and prints `Hello Alice`.

**About `+`:** When an operand is a string, `+` can perform string concatenation. In `"Hello " + "Alice"`, it joins the strings into `"Hello Alice"`.

You can also forward the event:

```javascript
button.addEventListener("click", (event) => {
  greet(event.type);
});
```

That prints `Hello click` when a click is dispatched.
## 9. Understanding the event object

The listener callback receives an event object:

```javascript
button.addEventListener("click", function (event) {
  console.log("Type:", event.type);
  console.log("Target:", event.target);
  console.log("Current:", event.currentTarget);
});
```

| Property | Meaning |
| --- | --- |
| `type` | Event type string |
| `target` | Target of the event |
| `currentTarget` | Object whose listener is currently running |
| `timeStamp` | Event timestamp |
| `bubbles` | Whether the event bubbles |
| `cancelable` | Whether the default action can be canceled |
| `defaultPrevented` | Whether cancellation occurred |
| `isTrusted` | Whether the user agent generated the event |

The parameter can be called `event`, `e`, or another valid name:

```javascript
button.addEventListener("click", (e) => console.log(e.type));
```

**Target vs currentTarget:** If a button is nested inside a `div` and the click listener is on the `div`, `event.target` can be the button while `event.currentTarget` is the `div`. The distinction is important for bubbling and delegation. The later propagation lessons cover this in depth.
## 10. Listener objects and handleEvent

The callback argument may be an object with a `handleEvent` method:

```javascript
const listener = {
  handleEvent(event) {
    console.log("Event type:", event.type);
  }
};

button.addEventListener("click", listener);
```

**Syntax breakdown:**

- `const listener` declares a binding.
- `=` assigns the object literal to the binding.
- `{ ... }` creates an object.
- `handleEvent(event) { ... }` is method shorthand syntax.
- `event` receives the event object when the method is invoked.
- `button.addEventListener("click", listener)` registers the object, not the result of calling its method.

When the event is dispatched, the event system invokes the object's `handleEvent(event)` method. This can be useful for grouping event behavior and state in a reusable object.
## 11. Argument three: options

The optional third argument is an object or a boolean capture flag:

```javascript
button.addEventListener("click", handleClick, {
  capture: false,
  once: true,
  passive: false
});
```

| Option | Meaning |
| --- | --- |
| `capture` | Register a capturing listener rather than a non-capturing listener |
| `once` | Remove the listener automatically after its first invocation |
| `passive` | Promise not to cancel the event's default action |
| `signal` | Associate the listener with an `AbortSignal` for cleanup |

`capture` and `once` default to `false`. Passive defaults can vary by browser and event type, especially for certain touch and wheel events. `signal` is optional.

The options object uses **property-name: value** pairs. For example, `once: true` means the property named `once` has the boolean value `true`. The comma separates properties. The braces create an object literal.
## 12. The once option

```javascript
button.addEventListener("click", function () {
  console.log("Executed");
}, { once: true });
```

| Click number | Callback runs? | Reason |
| --- | --- | --- |
| 1 | Yes | Listener is registered |
| 2 | No | Listener was automatically removed |
| 3 | No | Listener remains removed |

Trace:

```text
1. Register callback with once: true.
2. First click event reaches listener.
3. Browser removes the one-time registration as part of invocation.
4. Callback executes and prints Executed.
5. Later clicks find no matching registration.
```

This is useful for one-time setup, dismissals, or actions that should react to one occurrence. It is not a general substitute for disabling a button or enforcing application-level rules.
## 13. The capture option

For nested elements:

```html
<div id="parent">
  <button id="child" type="button">Click</button>
</div>
```

```javascript
const parent = document.getElementById("parent");
const child = document.getElementById("child");

parent.addEventListener("click", () => console.log("Parent capture"), {
  capture: true
});
child.addEventListener("click", () => console.log("Child"));
parent.addEventListener("click", () => console.log("Parent bubble"));
```

Clicking the child prints:

```text
Parent capture
Child
Parent bubble
```

Conceptual path:

```text
Capturing: ancestor --> child
Target:    child
Bubbling:  child --> ancestor
```

`capture: true` requests listener invocation on the capture path. A default listener uses `capture: false`. At the event target, both capture and non-capture listeners can run according to the event dispatch rules. Detailed event phases will be covered in Lessons 16.34-16.38.
## 14. The passive option

```javascript
window.addEventListener("touchmove", function (event) {
  console.log("Touch movement");
}, { passive: true });
```

`passive: true` means the listener promises not to call `preventDefault()` to cancel the event. If it calls `preventDefault()` anyway, cancellation is ignored; the browser may warn.

**What `preventDefault()` means:** It requests cancellation of an event's default browser action, but only if the event is cancelable and the listener is allowed to cancel it.

A passive listener may improve scrolling responsiveness for certain input events. Do not use `passive: true` when your intended behavior requires canceling the default action. The browser's default passive behavior is not identical for every event and environment.
## 15. The signal option

An `AbortController` can remove associated listeners:

```javascript
const controller = new AbortController();

button.addEventListener("click", function () {
  console.log("Clicked");
}, { signal: controller.signal });

controller.abort();
```

**Line-by-line:**

1. `new AbortController()` constructs a controller.
2. `controller.signal` accesses its `AbortSignal`.
3. The options object passes that signal to `addEventListener()`.
4. The listener is registered if the signal is not already aborted.
5. `controller.abort()` aborts the signal.
6. The browser removes listeners associated with that signal.

One controller can clean up multiple listeners:

```javascript
const controller = new AbortController();
button.addEventListener("click", handleClick, { signal: controller.signal });
window.addEventListener("resize", handleResize, { signal: controller.signal });
controller.abort();
```

`handleClick` and `handleResize` are assumed to be defined. This cleanup mechanism is covered in depth in Lesson 16.48.
## 16. Boolean capture shorthand

```javascript
parent.addEventListener("click", handleClick, true);
```

is equivalent to:

```javascript
parent.addEventListener("click", handleClick, { capture: true });
```

Similarly, `false` means `{ capture: false }`.

The object form is generally easier to read because it names the option explicitly. The boolean form controls **only** capture; it does not configure `once`, `passive`, or `signal`.
## 17. Duplicate listener registrations

```javascript
function handleClick() {
  console.log("Clicked");
}
button.addEventListener("click", handleClick);
button.addEventListener("click", handleClick);
```

A click prints `Clicked` **once**. The event system treats a listener with the same event type, callback identity, and capture setting on the same target as a duplicate.

But these are two distinct functions:

```javascript
button.addEventListener("click", function () {
  console.log("Hello");
});
button.addEventListener("click", function () {
  console.log("Hello");
});
```

A click prints `Hello` twice.

**Why?** Every evaluation of a function expression creates a distinct function object:

```javascript
const first = function () { console.log("Hello"); };
const second = function () { console.log("Hello"); };
console.log(first === second); // false
```

`===` is strict equality. For objects and functions, it checks identity, not whether source text is identical.

**Subtle point:** If a matching listener is already registered, calling `addEventListener()` again with different `once` or `passive` values does **not** update the existing registration. Remove it first, or use a different callback, when you need changed options.
## 18. Multiple listeners and event types

```javascript
button.addEventListener("click", () => console.log("First"));
button.addEventListener("click", () => console.log("Second"));
button.addEventListener("click", () => console.log("Third"));
```

For this example, one click produces:

```text
First
Second
Third
```

The callbacks are separate registrations, executed in registration order when invoked on the same target in the same phase (assuming no removal or propagation-stopping changes).

One target can also listen for several types:

```javascript
button.addEventListener("click", () => console.log("Clicked"));
button.addEventListener("mouseenter", () => console.log("Entered"));
button.addEventListener("mouseleave", () => console.log("Left"));
```

Each registration specifies a separate event type. The browser invokes callbacks when their event type matches.
## 19. Execution order and tracing

```javascript
console.log("A");
button.addEventListener("click", function () {
  console.log("B");
});
console.log("C");
```

Before clicking:

```text
A
C
```

After clicking once:

```text
B
```

| Step | Action | Console output so far |
| --- | --- | --- |
| 1 | Execute first `console.log` | `A` |
| 2 | Create callback function | `A` |
| 3 | Register listener | `A` |
| 4 | Execute final `console.log` | `A`, `C` |
| 5 | Browser dispatches click | `A`, `C` |
| 6 | Browser invokes callback | `A`, `C`, `B` |

**Important nuance:** Browser-generated user interactions normally arrive through the browser's event processing, but programmatic `dispatchEvent()` invokes listeners synchronously:

```javascript
const target = new EventTarget();
target.addEventListener("demo", () => console.log("Listener"));
console.log("Before");
target.dispatchEvent(new Event("demo"));
console.log("After");
```

Output:

```text
Before
Listener
After
```

Do not assume every event listener callback must be queued for later execution.
## 20. Return value

`addEventListener()` returns `undefined`:

```javascript
const result = button.addEventListener("click", function () {
  console.log("Clicked");
});
console.log(result); // undefined
```

**Trace:**

1. The callback function object is created.
2. The listener is registered.
3. The method finishes with no useful return value.
4. `result` receives `undefined`.
5. `console.log(result)` prints `undefined`.

It does not return a listener ID or a subscription handle. If you plan to remove a listener later, retain the same function reference:

```javascript
function handleClick() { console.log("Clicked"); }
button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

The next lesson explains `removeEventListener()` in detail.
## 21. Common mistakes and debugging

| Mistake | What goes wrong | Correct approach |
| --- | --- | --- |
| `handler()` instead of `handler` | Function runs during registration | Pass the function reference |
| `click` instead of `"click"` | Identifier lookup, possibly ReferenceError | Use an event type string |
| `"Click"` instead of `"click"` | Wrong case for native click event | Use lowercase `"click"` |
| Selecting before element exists | `getElementById` returns `null` | Use `defer`, correct ID, or DOM readiness |
| Assuming registration runs handler | No callback execution yet | Wait for event dispatch |
| Assuming listeners run once | Default listener persists | Use `{ once: true }` |
| Using new anonymous function to remove | Function identity differs | Keep original reference |
| `preventDefault()` inside passive listener | Default action not canceled | Use suitable passive configuration |
| Expecting a registration handle | Method returns `undefined` | Keep callback/controller |
| Using arrow-function `this` as element | Arrow function inherits lexical `this` | Use `event.currentTarget` |

**Debugging procedure:**

1. Confirm the HTML element exists.
2. Print the lookup result with `console.log(button)`.
3. Confirm the event type string is correct.
4. Confirm you passed a callback reference rather than calling it.
5. Put a `console.log("handler reached")` inside the callback.
6. Check whether another handler removes or stops the event.
7. Check whether `{ once: true }` or an aborted signal has removed the listener.
8. Use the browser developer tools console to inspect errors.

A practical guard:

```javascript
const button = document.getElementById("myButton");
if (button !== null) {
  button.addEventListener("click", () => console.log("Clicked"));
}
```

`!==` means strictly not equal. Here it prevents a method call on `null`.
## 22. EventTarget API: complete method inventory and return values

`addEventListener()` is defined on `EventTarget`. The interface has three standard methods:

| Method | Signature | Return value | What it does |
|---|---|---|---|
| `addEventListener` | `target.addEventListener(type, callback, options)` | `undefined` | Adds a listener unless an identical registration exists |
| `removeEventListener` | `target.removeEventListener(type, callback, options)` | `undefined` | Removes a matching registration |
| `dispatchEvent` | `target.dispatchEvent(event)` | Boolean | Synchronously dispatches an event |

A listener registration and the later execution of that listener are separate actions.

```javascript
const target = new EventTarget();
function onHello(event) {
  console.log("Received:", event.type);
}
target.addEventListener("hello", onHello);
console.log("Before");
const result = target.dispatchEvent(new Event("hello"));
console.log("After", result);
target.removeEventListener("hello", onHello);
```

Output:

```text
Before
Received: hello
After true
```

`new EventTarget()` creates an independent target; `new Event("hello")` creates an event. `dispatchEvent()` invokes listeners synchronously and returns `false` only if the dispatched event is cancelable and its default action was canceled. It returns `true` otherwise. This is not the same return value as `addEventListener()`.

### Complete listener options and default rules

| Option | Type | Default / omitted behavior | Important consequence |
|---|---|---|---|
| `capture` | Boolean | `false` | Selects capture registration; participates in duplicate matching |
| `once` | Boolean | `false` | Removes listener before/when first invocation begins, even if callback throws |
| `passive` | Boolean | Generally `false`, with browser/event/target-specific defaults | `preventDefault()` cannot cancel an event from a passive listener |
| `signal` | `AbortSignal` | No signal | Aborting removes associated listener registrations |

The third argument may be a boolean capture flag rather than an object. Firefox-specific `wantsUntrusted` is not part of the standard portable options set. `once`, `passive`, and `signal` do not distinguish duplicate registrations. If the same type, callback, and capture match an existing listener on that target, a second registration does not update its options.

### Argument conversion and invalid callbacks

A listener may be a function, an object with callable `handleEvent(event)`, or `null` (which registers nothing). `undefined` is treated as a null callback. An invalid primitive such as `123` cannot serve as a listener and raises a `TypeError`. Event type strings are case-sensitive. Calling `addEventListener` on `null` (such as a missing DOM element) also raises a `TypeError`.

### EventTarget versus plain objects

```javascript
const plain = { name: "Alice" };
// plain.addEventListener("hello", onHello); // TypeError
const customTarget = new EventTarget();
customTarget.addEventListener("hello", onHello);
```

Examples of EventTargets include `window`, `document`, HTML elements, `AbortSignal`, `WebSocket`, `Worker`, `MediaQueryList`, `EventSource`, and various IndexedDB request objects. Different targets support different natural event types.
## 23. The core Event interface: properties, methods, constants and legacy members

Every standard DOM `Event` supplies the following core properties. Subclasses add more.

| Property | Type | Meaning |
|---|---|---|
| `type` | String | Event type |
| `target` | EventTarget or null | Target, possibly retargeted across boundaries |
| `currentTarget` | EventTarget or null | Target whose listener is currently executing |
| `eventPhase` | Number | Current propagation phase |
| `bubbles` | Boolean | Whether the event bubbles |
| `cancelable` | Boolean | Whether its default action can be canceled |
| `composed` | Boolean | Whether it can cross shadow-root boundaries |
| `defaultPrevented` | Boolean | Whether cancellation succeeded |
| `isTrusted` | Boolean | Whether the user agent generated the event |
| `timeStamp` | Number | Event timestamp |

Core methods:

| Method | Meaning |
|---|---|
| `preventDefault()` | Request cancellation of a cancelable default action |
| `stopPropagation()` | Stop propagation to subsequent targets |
| `stopImmediatePropagation()` | Also stop subsequent listeners on current target |
| `composedPath()` | Get event propagation path, subject to shadow DOM visibility |

Core constants:

```javascript
Event.NONE             // 0
Event.CAPTURING_PHASE  // 1
Event.AT_TARGET        // 2
Event.BUBBLING_PHASE   // 3
```

Legacy members to recognize but generally avoid: `cancelBubble`, `returnValue`, `srcElement`, and deprecated `initEvent()`.

### Inspect the event object

```javascript
button.addEventListener("click", function (event) {
  console.log("type:", event.type);
  console.log("target:", event.target);
  console.log("currentTarget:", event.currentTarget);
  console.log("phase:", event.eventPhase);
  console.log("bubbles:", event.bubbles);
  console.log("cancelable:", event.cancelable);
  console.log("composed:", event.composed);
  console.log("prevented:", event.defaultPrevented);
  console.log("trusted:", event.isTrusted);
  console.log("timestamp:", event.timeStamp);
  console.log("path:", event.composedPath());
});
```

`event.target` identifies the target of the event. `event.currentTarget` identifies the target whose listener is executing. If a button inside a parent is clicked, a listener on the parent may observe `target` as the button and `currentTarget` as the parent.

### Cancellation is not propagation

```javascript
link.addEventListener("click", function (event) {
  event.preventDefault(); // Request no navigation, when cancellation is permitted.
});
```

`preventDefault()` does not stop propagation. `stopPropagation()` does not cancel default actions. `stopImmediatePropagation()` stops further listeners on the same target as well as propagation. A passive listener cannot cancel default actions through `preventDefault()`.

## 25. Event propagation, listener order, and target phases

DOM propagation normally moves through three phases: capture (toward the target), at-target, and bubble (back through ancestors if `bubbles` is true).

```text
Window
  |
  v
Document
  |
  v
Parent
  |
  v
Target
  |
  ^
Parent
  |
  ^
Document
  |
  ^
Window
```

A capturing listener on the event target runs during the at-target phase, not necessarily during `Event.CAPTURING_PHASE`. Listeners on the same target and phase normally run in registration order unless propagation is stopped or the listener list is modified.

### Complete nested example

```html
<div id="outer">
  <div id="inner">
    <button id="child" type="button">Click</button>
  </div>
</div>
```

```javascript

const inner = document.getElementById("inner");
const child = document.getElementById("child");
outer.addEventListener("click", () => console.log("Outer capture"), true);
inner.addEventListener("click", () => console.log("Inner capture"), true);
child.addEventListener("click", () => console.log("Child target"));

outer.addEventListener("click", () => console.log("Outer bubble"));
```

Clicking the button yields:

```text

Child target

Outer bubble
```

### Execution trace

| Step | Phase | Callback |
|---|---|---|
| 1 | Capturing | Outer capture |
| 2 | Capturing | Inner capture |
| 3 | At target | Child target |
| 4 | Bubbling | Inner bubble |

`focus`, `blur`, `mouseenter`, and `mouseleave` are examples of events that do not bubble in their usual forms. Capturing listeners on ancestors can still observe relevant non-bubbling DOM events.
## 26. Advanced dispatch behavior, edge cases, errors and asynchronous callbacks

### Adding a listener while an event is being dispatched

```javascript
const target = new EventTarget();
function second() { console.log("Second"); }
target.addEventListener("hello", function first() {
  console.log("First");
  target.addEventListener("hello", second);
});
target.dispatchEvent(new Event("hello")); // First
target.dispatchEvent(new Event("hello")); // First, Second
```

The newly added listener does not retroactively execute during the same target's current listener invocation. A listener added to an ancestor during an earlier propagation phase can sometimes run when the event reaches that ancestor later.

### Removing a listener before its turn

```javascript
const target = new EventTarget();
function second() { console.log("Second"); }
target.addEventListener("hello", function first() {
  console.log("First");
  target.removeEventListener("hello", second);
});
target.addEventListener("hello", second);
target.dispatchEvent(new Event("hello")); // Only First
```

### Nested synchronous dispatch

```javascript
const target = new EventTarget();
target.addEventListener("first", function () {
  console.log("A");
  target.dispatchEvent(new Event("second"));
  console.log("C");
});
target.addEventListener("second", () => console.log("B"));
target.dispatchEvent(new Event("first"));
// Output: A, B, C
```

`dispatchEvent()` synchronously invokes applicable listeners before returning. The `new` keyword constructs an object; `=>` defines an arrow function; `()` invokes a function or constructor; `//` begins a line comment.

### Microtasks and async handlers

```javascript
const target = new EventTarget();
target.addEventListener("hello", function () {
  console.log("Listener starts");
  Promise.resolve().then(() => console.log("Microtask"));
  console.log("Listener ends");
});
console.log("Before");
target.dispatchEvent(new Event("hello"));
console.log("After");
// Before, Listener starts, Listener ends, After, Microtask
```

`Promise.resolve()` creates a fulfilled Promise. `.then()` schedules a reaction as a microtask. The microtask does not interrupt the current synchronous script. An `async` listener may return a Promise, but `addEventListener()` does not await it. Handle rejected Promises inside asynchronous handlers.

### Exceptions and `once`

If a listener throws, the browser reports the error through its event-reporting mechanism. Such exceptions do not normally propagate to the surrounding caller of `dispatchEvent()` as ordinary direct function-call exceptions do. A `once: true` listener is removed even if its callback throws.

### `AbortSignal` lifecycle and related API

| Member | Purpose |
|---|---|
| `new AbortController()` | Create a controller |
| `controller.signal` | Get its signal |
| `controller.abort(reason)` | Abort, optionally with a reason |
| `signal.aborted` | Whether aborted |
| `signal.reason` | Abort reason |
| `signal.addEventListener("abort", ...)` | Observe abortion |
| `signal.throwIfAborted()` | Throw when aborted |
| `AbortSignal.abort()` | Create already-aborted signal |
| `AbortSignal.timeout()` | Create time-limited signal |
| `AbortSignal.any()` | Combine signals |

A listener registered with an already-aborted signal is not added. Multiple listeners can share one signal; aborting removes all associated registrations. Once aborted, that signal cannot be reset.

### DOM readiness

If `document.getElementById("myButton")` returns `null`, the element may not exist yet. Load a classic script with `defer`, place it after the HTML, or wait for DOM readiness. `defer` causes the classic script to execute after parsing and before `DOMContentLoaded`.

### Trusted versus synthetic events

Events created with `new Event()` or `new MouseEvent()` and dispatched with `dispatchEvent()` are synthetic and have `isTrusted === false`. Synthetic events do not necessarily produce all the privileged browser behaviors of genuine user interaction. Security-sensitive APIs may require real user activation.

### Performance and memory

Avoid attaching unnecessary listeners to many elements when event delegation can work. Clean up listeners on components that are no longer needed. Use stable callback references or `AbortController`. Passive listeners can help scrolling, but `passive: true` does not move JavaScript to a background thread or guarantee good performance.

const profileCard = document.getElementById("profileCard");
const profileName = document.getElementById("profileName");
const nameInput = document.getElementById("nameInput");
const themeButton = document.getElementById("themeButton");
const resetButton = document.getElementById("resetButton");

function updateName(event) {
  const enteredName = event.target.value;
  profileName.textContent = enteredName.trim() || "Guest User";
}

  profileCard.classList.toggle("dark");
}

### Line-by-line explanation

**Input callback:** `updateName(event)` receives the event object. `event.target` is the input that triggered the event. `.value` reads the current input text. `const enteredName = ...` stores that text.

**The `trim()` method:** Removes whitespace from the start and end of a string. For example, `"  Alice  ".trim()` produces `"Alice"`.

**The `||` operator:** In `enteredName.trim() || "Guest User"`, JavaScript evaluates the trimmed string first. If it is truthy (such as `"Alice"`), that string is returned. **The assignment `=`:** `profileName.textContent = ...` updates the element's text. The right-hand expression is evaluated before assignment.

**The toggle:** `profileCard.classList.toggle("dark")` adds the `dark` CSS class if absent and removes it if present. The `.profile-card.dark` CSS rule applies when both classes exist.

**The reset:** `nameInput.value = ""` clears the input. `profileName.textContent = "Guest User"` restores the text. `classList.remove("dark")` restores the light theme.

**The listener registrations:** Each `addEventListener` receives an event type and a named function reference, not a function call.

### script.js

```javascript
const targetButton = document.getElementById("targetButton");
const enableButton = document.getElementById("enableButton");
const onceButton = document.getElementById("onceButton");
const disableButton = document.getElementById("disableButton");
const status = document.getElementById("status");
const countDisplay = document.getElementById("count");

let count = 0;
let listenerMode = "disabled";

function handleTargetClick() {
  count = count + 1;
  countDisplay.textContent = count;

  if (listenerMode === "once") {
    listenerMode = "disabled";
    status.textContent = "Listener: Disabled";
  }
}

function disableListener() {
  targetButton.removeEventListener("click", handleTargetClick);
  listenerMode = "disabled";
  status.textContent = "Listener: Disabled";
}

function enableListener() {
  disableListener();
  targetButton.addEventListener("click", handleTargetClick);
  listenerMode = "enabled";
  status.textContent = "Listener: Enabled";
}

function enableOnce() {
  disableListener();
  targetButton.addEventListener("click", handleTargetClick, { once: true });
  listenerMode = "once";
  status.textContent = "Listener: Once";
}

enableButton.addEventListener("click", enableListener);
onceButton.addEventListener("click", enableOnce);
disableButton.addEventListener("click", disableListener);
```

### Line-by-line explanation

**`let count = 0`:** Creates a variable whose value can change. The initial number of handled clicks is zero.

**`let listenerMode = "disabled"`:** Stores one of three string states: `"disabled"`, `"enabled"`, or `"once"`. A boolean would not represent all three states as clearly.

**`count = count + 1`:** Evaluate the current value of `count`, add numeric `1`, and assign the result back to `count`. If count is `2`, the expression calculates `2 + 1 = 3` and stores `3`.

**`countDisplay.textContent = count`:** Assigns the count to the span's text content. The DOM converts the numeric value to displayable text.

**`if (listenerMode === "once")`:** `if` conditionally executes a block. `===` is strict equality: the condition is `true` only if the mode is exactly the string `"once"`.

**`disableListener()`:** Calls `removeEventListener` with the same event type and named function reference. It then changes the mode to disabled and updates the status text.

**`enableListener()`:** First calls `disableListener()` to remove an old matching registration. Then registers `handleTargetClick` without `once`, updates mode, and updates the status.

**`enableOnce()`:** Also removes any old registration before adding one with `{ once: true }`. This matters because re-registering the same callback with different `once` options does not update an existing matching listener.

**Control button listeners:** The last three statements register named functions for the enable, enable-once, and disable buttons. Those control listeners stay registered even while the target listener is disabled.

### Advanced extension: shared AbortController cleanup

The original project uses `removeEventListener()` and stable callback references. A different approach is to register several listeners with the same signal:

```javascript
let controller = new AbortController();

function onTargetClick(event) {
  console.log("Clicked:", event.type);
}

function onInput(event) {
  console.log("Input:", event.target.value);
}

targetButton.addEventListener("click", onTargetClick, {
  signal: controller.signal
});

// If the page also contains <input id="demoInput">:
const demoInput = document.getElementById("demoInput");
if (demoInput !== null) {
  demoInput.addEventListener("input", onInput, {
    signal: controller.signal
  });
}

// Call when you want to remove all associated listeners:
function cleanupDemo() {
  controller.abort();
}
```

This is an optional extension, not a replacement for the original runnable project. The input is guarded against `null` so it does not break the original HTML. The controller cannot be reused after `abort()`; create a new one for a fresh registration cycle.
## 29. 10 interview questions and answers

### Question 1. What is addEventListener()?

**Answer:** It is an EventTarget method that registers a callback function or listener object for a specified event type. Registration itself does not execute the callback.

### Question 2. What are its three arguments?

**Answer:** The event type string, a callback function or listener object, and an optional options object or capture boolean.

### Question 3. What does addEventListener() return?

**Answer:** It returns undefined, not a listener ID or a subscription handle.

### Question 4. Why pass a function reference instead of calling it?

**Answer:** A reference allows later invocation by the event system. Calling the function immediately passes its return value instead.

### Question 5. What does the event object provide?

**Answer:** Information such as type, target, currentTarget, timeStamp, bubbles, cancelable, and isTrusted.

### Question 6. Can the callback be an object?

**Answer:** Yes. A listener object implementing handleEvent(event) can be registered.

### Question 7. What does once: true do?

**Answer:** It automatically removes the registration when the listener is first invoked, so subsequent events do not call it unless re-registered.

### Question 8. What does capture: true do?

**Answer:** It registers the listener to run on the capture path of event propagation rather than as a non-capturing listener.

### Question 9. What does passive: true mean?

**Answer:** It declares that the listener will not cancel the default action. A preventDefault call from that passive listener will not cancel it.

### Question 10. How are duplicates identified?

**Answer:** On the same target, a registration with matching event type, callback identity, and capture setting is considered a duplicate. Different once or passive options do not create another matching registration.

**Task:** Register the same named callback twice; predict output after one click.

**Solution:**

```javascript
const button = document.getElementById("myButton");
function handleClick() {
  console.log("Clicked");
}
button.addEventListener("click", handleClick);
button.addEventListener("click", handleClick);
```

**Step-by-step explanation:** Output is one Clicked, not two, because the same type, callback identity, and capture setting are registered twice.

### Exercise 9. Remove a listener

**Task:** Register and remove a named click callback.

**Solution:**

```javascript
const button = document.getElementById("myButton");
function handleClick() {
  console.log("Clicked");
}
button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

**Step-by-step explanation:** The same callback reference is used for both operations. A later click does not run this listener.

### Exercise 10. Use AbortController cleanup

**Task:** Register a listener with a signal, then abort.

**Solution:**

```javascript
const button = document.getElementById("myButton");
const controller = new AbortController();
button.addEventListener("click", function () {
  console.log("Clicked");
}, { signal: controller.signal });
controller.abort();
```

**Step-by-step explanation:** Aborting the signal removes the associated listener, so subsequent clicks do not invoke it.

### Question 1. What does addEventListener() return?

### Question 2. What does once: true do?

A. Runs twice

### Question 3. Which option enables capture registration?

### Question 4. What defines a duplicate registration?

A. Same source text

**Correct answer: B.** Listener matching uses type, callback identity, and capture flag on the same target.

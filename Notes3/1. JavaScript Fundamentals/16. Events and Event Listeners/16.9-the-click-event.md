## 1. Learning objectives

After this lesson you should be able to explain what click means, attach and remove click listeners, read the event object, distinguish target and currentTarget, interpret coordinates and button states, explain pointer versus keyboard activation, cancel default actions appropriately, use delegation, distinguish `.click()` from `dispatchEvent()`, and build accessible click-driven interfaces.

**Prerequisites:** variables, functions, DOM selection, callbacks, `addEventListener()`, event objects, and event targets. No object-oriented programming knowledge is assumed.

## 2. What is the click event?

A `click` event represents primary-button activation or an equivalent activation through another input mechanism. It is **not mouse-only**: native controls can generate clicks from mouse, touch, pen, keyboard, and assistive-technology activation.

```html
<button id="myButton" type="button">Click Me</button>
<script>
  const button = document.getElementById("myButton");
  button.addEventListener("click", function () {
    console.log("Button activated");
  });
</script>
```

**Trace:** browser finds the button -> user activates it -> browser dispatches a click -> listener runs -> console prints `Button activated`.

## 3. How browsers generate clicks

For a typical primary mouse activation, a simplified order is:

```text
pointerdown -> mousedown -> pointerup -> mouseup -> click
```

This is **not** a universal event order for every input source. Focus changes, pointer capture, touch compatibility events, and cancellation may affect what is dispatched. Keyboard activation of a focused native button can also produce `click` without a physical mouse press. Other mouse buttons may generate `auxclick` or `contextmenu` rather than ordinary primary `click`.

## 4. Registering listeners

```javascript
const button = document.querySelector("#saveButton");

function handleSave(event) {
  console.log("Saving", event.type);
}

button.addEventListener("click", handleSave);
```

Pass the function **reference**, not its immediate result:

```javascript
button.addEventListener("click", handleSave);   // Correct
button.addEventListener("click", handleSave()); // Calls immediately; usually wrong
```

Anonymous functions and arrows are also valid:

```javascript
button.addEventListener("click", function (event) {
  console.log(event.type);
});

button.addEventListener("click", (event) => {
  console.log(event.type);
});
```

## 5. Listener syntax and options

```javascript
element.addEventListener("click", listener, options);
```

| Argument | Meaning |
|---|---|
| `"click"` | Event type string |
| `listener` | Function, listener object, or `null` |
| `options` | Optional Boolean capture flag or options object |

| Option | Default | Effect |
|---|---|---|
| `capture` | `false` | Registers for capture phase |
| `once` | `false` | Removes listener after its first invocation |
| `passive` | Generally `false` for click | Promises not to cancel default action |
| `signal` | No signal | AbortSignal for automatic listener removal |

```javascript
const controller = new AbortController();
button.addEventListener("click", handleSave, {
  capture: false,
  once: false,
  passive: false,
  signal: controller.signal
});
// Later: controller.abort();
```

`addEventListener()` returns `undefined`. Some touch and wheel events have browser-specific passive defaults; do not generalize those defaults to every event.

## 6. Callbacks and event objects

The browser supplies an event object to the listener:

```javascript
button.addEventListener("click", function (event) {
  console.log("type:", event.type);
  console.log("target:", event.target);
  console.log("currentTarget:", event.currentTarget);
  console.log("cancelable:", event.cancelable);
  console.log("trusted:", event.isTrusted);
});
```

Execution trace:

1. Activation happens.
2. The browser dispatches an event.
3. The browser invokes the registered callback.
4. The callback receives `event`.
5. Properties are read during listener execution.
6. The callback returns and dispatch continues or finishes.

## 7. Event interfaces and inheritance

Modern browsers generally expose click events as `PointerEvent`, inheriting from `MouseEvent`, `UIEvent`, and `Event`:

```text
Event
  `-- UIEvent
        `-- MouseEvent
              `-- PointerEvent
```

Browser compatibility varies; older browsers may expose `MouseEvent`. Synthetic clicks may be constructed as base `Event` objects:

```javascript
const synthetic = new Event("click"); // Not a PointerEvent
```

Use feature checks when relying on pointer-specific properties:

```javascript
button.addEventListener("click", function (event) {
  if (typeof PointerEvent !== "undefined" && event instanceof PointerEvent) {
    console.log(event.pointerType);
  }
});
```

## 8. Property inventory

### Base Event properties

| Property | Meaning |
|---|---|
| `type` | Event name (`"click"`) |
| `target` | Event target, possibly retargeted |
| `currentTarget` | Target whose listener is currently running |
| `eventPhase` | Capturing, at-target, or bubbling phase |
| `bubbles` | Whether event bubbles |
| `cancelable` | Whether default action can be canceled |
| `composed` | Whether event can cross shadow boundaries |
| `defaultPrevented` | Whether cancellation succeeded |
| `isTrusted` | Whether user agent generated the event |
| `timeStamp` | Timestamp, usually relative to performance time origin |

### UIEvent properties

| Property | Meaning |
|---|---|
| `detail` | Commonly the repeated click count |
| `view` | Associated window, if any |

### MouseEvent properties

| Property | Meaning |
|---|---|
| `clientX`, `clientY` | Viewport-relative coordinates |
| `pageX`, `pageY` | Document-relative coordinates |
| `screenX`, `screenY` | Screen-relative coordinates |
| `offsetX`, `offsetY` | Relative to event target padding edge, subject to coordinate rules |
| `movementX`, `movementY` | Movement relative to previous mouse event |
| `button` | Button associated with event |
| `buttons` | Currently pressed button bitmask |
| `ctrlKey`, `shiftKey`, `altKey`, `metaKey` | Modifier key state |
| `relatedTarget` | Related target where applicable |

### PointerEvent properties

| Property | Meaning |
|---|---|
| `pointerId` | Pointer identifier |
| `pointerType` | `"mouse"`, `"pen"`, `"touch"`, or other/empty |
| `isPrimary` | Whether pointer is primary |
| `width`, `height` | Contact geometry |
| `pressure`, `tangentialPressure` | Pressure information |
| `tiltX`, `tiltY` | Stylus tilt |
| `twist` | Stylus rotation |
| `altitudeAngle`, `azimuthAngle` | Stylus orientation |

Some properties are not meaningful for keyboard-generated clicks. Specialized pointer properties and full constructor dictionaries are deliberately deferred to the dedicated pointer lessons.

## 9. Coordinates and buttons

```javascript
document.addEventListener("click", function (event) {
  console.log("viewport:", event.clientX, event.clientY);
  console.log("document:", event.pageX, event.pageY);
  console.log("screen:", event.screenX, event.screenY);
  console.log("button:", event.button, "buttons:", event.buttons);
});
```

If a user clicks 100 CSS pixels below the viewport top after scrolling down 500 pixels, `clientY` may be `100` while `pageY` may be `600`.

| `button` | Meaning |
|---|---|
| 0 | Primary |
| 1 | Auxiliary/middle |
| 2 | Secondary/right |
| 3 | Fourth |
| 4 | Fifth |

| `buttons` bit | Meaning |
|---|---|
| 1 | Primary held |
| 2 | Secondary held |
| 4 | Auxiliary held |
| 8 | Fourth held |
| 16 | Fifth held |

`button` identifies the associated button; `buttons` describes pressed-button state. A completed click usually has `buttons === 0` because the button has been released.

## 10. Propagation

```html
<div id="parent"><button id="child" type="button">Click</button></div>
```

```javascript
const parent = document.getElementById("parent");
const child = document.getElementById("child");

parent.addEventListener("click", () => console.log("capture"), true);
child.addEventListener("click", () => console.log("target"));
parent.addEventListener("click", () => console.log("bubble"));
```

Clicking the child prints:

```text
capture
target
bubble
```

`event.stopPropagation()` stops further propagation to other targets. `event.stopImmediatePropagation()` additionally stops later listeners on the same current target. Neither automatically cancels the browser's default action.

## 11. Targets and delegation

```html
<div id="toolbar">
  <button type="button" data-action="save"><span>Save</span></button>
  <button type="button" data-action="edit">Edit</button>
  <button type="button" data-action="delete">Delete</button>
</div>
```

```javascript
const toolbar = document.getElementById("toolbar");

toolbar.addEventListener("click", function (event) {
  if (!(event.target instanceof Element)) return;
  const button = event.target.closest("button");
  if (!button || !toolbar.contains(button)) return;
  console.log(button.dataset.action);
});
```

`event.target` may be the inner span; `event.currentTarget` is the toolbar while its listener runs. `closest("button")` locates the relevant button. `contains()` checks that the button belongs to this toolbar.

## 12. Default actions

A click may follow a link, submit a form, toggle a checkbox, or activate a native control.

```html
<a id="link" href="https://example.com">Example</a>
<script>
  document.getElementById("link").addEventListener("click", function (event) {
    event.preventDefault();
    console.log("Navigation prevented");
  });
</script>
```

`preventDefault()` requests cancellation when the event is cancelable and the listener is not passive. It **does not** stop propagation. Use `<button type="button">` for non-submit buttons inside forms instead of adding a cancellation handler merely to prevent accidental submission.

## 13. Keyboard accessibility

A native button supports focus and keyboard activation automatically:

```html
<button id="download" type="button">Download</button>
<script>
  document.getElementById("download").addEventListener("click", () => {
    console.log("Activated by a supported input method");
  });
</script>
```

Enter or Space can activate a focused native button. Avoid using clickable `<div>` elements when `<button>` is appropriate; a div does not automatically provide button semantics or keyboard activation. Avoid triggering the same action in both `keydown` and `click` on a native button, as that may cause duplicate activation.

## 14. click() versus dispatchEvent()

```javascript
button.click();

button.dispatchEvent(new MouseEvent("click", {
  bubbles: true,
  cancelable: true,
  composed: true
}));
```

| Feature | `HTMLElement.click()` | `EventTarget.dispatchEvent()` |
|---|---|---|
| Takes event argument | No | Yes |
| Event type | Click | Any specified event type |
| Return value | `undefined` | Boolean |
| Genuine user activation | No | No |
| Disabled form control behavior | Follows click activation rules | Not equivalent |

Use a direct function call when you only need to reuse application logic. `dispatchEvent()` is synchronous and returns `false` if a cancelable event was canceled, otherwise `true`.

## 15. Trusted and synthetic clicks

```javascript
button.addEventListener("click", function (event) {
  console.log(event.isTrusted);
});
button.click(); // click event is untrusted
```

Programmatic clicks, including `HTMLElement.click()` and events created with constructors, do not grant genuine user activation. Browser-gated features such as popup or clipboard access may require actual user interaction. `isTrusted` is not an application authorization mechanism.

## 16. Multiple clicks and timing

```javascript
button.addEventListener("click", function (event) {
  console.log(event.detail);
});
```

For repeated pointer clicks, `detail` commonly progresses from 1 to 2 to 3; keyboard-generated clicks commonly have `detail === 0`. A double-click may dispatch two `click` events followed by `dblclick`. Do not assume `dblclick` suppresses `click`.

For async actions, disable the button during work and use server-side idempotency for consequential operations:

```javascript
button.addEventListener("click", async function (event) {
  const currentButton = event.currentTarget;
  currentButton.disabled = true;
  try {
    await saveData(); // Application-defined function
  } finally {
    currentButton.disabled = false;
  }
});
```

Save `currentTarget` before `await`; it may be `null` when the async function resumes.

## 17. Listener lifecycle

```javascript
button.addEventListener("click", handleSave, { once: true });

const controller = new AbortController();
button.addEventListener("click", handleSave, { signal: controller.signal });
controller.abort();

button.addEventListener("click", handleSave);
button.removeEventListener("click", handleSave);
```

Removal matches the event type, callback identity, and capture setting. Anonymous callbacks cannot be removed by passing a different anonymous function.

## 18. Dynamic elements

```javascript
const newButton = document.createElement("button");
newButton.type = "button";
newButton.className = "dynamic-button";
newButton.textContent = "New Button";
document.body.appendChild(newButton);
```

You can register directly on the new button or use a delegated listener on a stable ancestor. Delegation is often more convenient for changing lists and menus.

## 19. Shadow DOM

Click events are generally composed and can cross shadow boundaries. Outside a shadow root, `event.target` may be retargeted to the host. `event.composedPath()` can expose the internal path for open shadow roots; closed roots hide internal details from outside listeners. Do not assume an outside listener can always see the actual internal clicked element.

## 20. Mistakes and debugging

| Mistake | Fix |
|---|---|
| `addEventListener("click", handler())` | Pass `handler` |
| Assuming click is mouse-only | Support native controls and keyboard activation |
| Assuming `target` is always button | Use `currentTarget` or checked `closest()` |
| Accidental form submission | Set `type="button"` |
| Clickable div without keyboard support | Prefer `<button>` |
| Assuming `.click()` is trusted | Respect user activation requirements |
| Expecting `preventDefault()` to stop bubbling | Use propagation APIs separately |
| Assuming double-click replaces clicks | Plan for both events |

```javascript
function debugClick(event) {
  console.group("Click");
  console.log("type", event.type);
  console.log("target", event.target);
  console.log("currentTarget", event.currentTarget);
  console.log("detail", event.detail);
  console.log("isTrusted", event.isTrusted);
  console.log("defaultPrevented", event.defaultPrevented);
  if (event instanceof MouseEvent) {
    console.log("coordinates", event.clientX, event.clientY);
    console.log("button", event.button, "buttons", event.buttons);
  }
  console.groupEnd();
}
document.addEventListener("click", debugClick);
```

## 21. Performance and security

Keep click callbacks responsive; heavy synchronous work blocks the main thread. Provide feedback during asynchronous actions. Never treat a client click as proof of authorization: validate on the server. Prefer `textContent` for user-supplied text rather than unsanitized `innerHTML`. For payments or other important operations, enforce idempotency server-side, not only by disabling a button.

### script.js

```javascript
const inspectButton = document.getElementById("inspectButton");
const syntheticButton = document.getElementById("syntheticButton");
const programmaticButton = document.getElementById("programmaticButton");
const clearButton = document.getElementById("clearButton");
const output = document.getElementById("output");
const history = document.getElementById("history");
let clickCount = 0;

function describeTarget(target) {
  if (target instanceof Element) {
    const id = target.id ? "#" + target.id : "";
    return target.tagName.toLowerCase() + id;
  }
  return String(target);
}

function inspectClick(event) {
  clickCount = clickCount + 1;
  const details = {
    count: clickCount,
    type: event.type,
    interface: event.constructor.name,
    target: describeTarget(event.target),
    currentTarget: describeTarget(event.currentTarget),
    bubbles: event.bubbles,
    cancelable: event.cancelable,
    defaultPrevented: event.defaultPrevented,
    composed: event.composed,
    isTrusted: event.isTrusted,
    detail: event.detail,
    timeStamp: event.timeStamp
  };
  if (event instanceof MouseEvent) {
    details.clientX = event.clientX;
    details.clientY = event.clientY;
    details.pageX = event.pageX;
    details.pageY = event.pageY;
    details.button = event.button;
    details.buttons = event.buttons;
    details.ctrlKey = event.ctrlKey;
    details.shiftKey = event.shiftKey;
    details.altKey = event.altKey;
    details.metaKey = event.metaKey;
  }
  if (typeof PointerEvent !== "undefined" && event instanceof PointerEvent) {
    details.pointerType = event.pointerType;
    details.pointerId = event.pointerId;
    details.isPrimary = event.isPrimary;
    details.pressure = event.pressure;
  }
  output.textContent = JSON.stringify(details, null, 2);
  const item = document.createElement("li");
  item.textContent = "Click " + clickCount +
    " | trusted: " + event.isTrusted +
    " | target: " + describeTarget(event.target);
  history.prepend(item);
}

function dispatchSyntheticClick() {
  const event = new MouseEvent("click", {
    bubbles: true,
    cancelable: true,
    composed: true
  });
  inspectButton.dispatchEvent(event);
}

function activateProgrammatically() {
  inspectButton.click();
}

function clearHistory() {
  clickCount = 0;
  history.replaceChildren();
  output.textContent = "No click recorded.";
}

inspectButton.addEventListener("click", inspectClick);
syntheticButton.addEventListener("click", dispatchSyntheticClick);
programmaticButton.addEventListener("click", activateProgrammatically);
clearButton.addEventListener("click", clearHistory);
```

### Code breakdown and trace

- `clickCount` stores the number of inspected clicks.
- `describeTarget()` converts an element to a readable label such as `button#inspectButton`.
- `event instanceof MouseEvent` protects access to mouse-specific properties.
- `typeof PointerEvent !== "undefined"` protects against environments without that constructor.
- `JSON.stringify(details, null, 2)` formats a snapshot as readable JSON. The second argument is the replacer (`null`), and the third controls indentation (`2`).
- `history.prepend(item)` adds the newest record at the top.
- `.dispatchEvent()` sends an explicitly created `MouseEvent`; `.click()` invokes HTML click activation behavior.

| Step | Action | Observed result |
|---|---|---|
| 1 | Click inner span | Browser dispatches click |
| 2 | Button listener executes | `currentTarget` is button |
| 3 | Read `target` | May be span |
| 4 | Increment count | Number increases |
| 5 | Snapshot event | Details object created |
| 6 | Serialize | Readable JSON shown |
| 7 | Prepend history | New history entry appears |

**Experiments:** click with the mouse, activate with the keyboard, dispatch a synthetic MouseEvent, and invoke `.click()`. Compare `isTrusted`, `detail`, and constructor names.

### script.js

```javascript
const productList = document.getElementById("productList");
const count = document.getElementById("count");
const selectedList = document.getElementById("selectedList");
const clearSelection = document.getElementById("clearSelection");
const status = document.getElementById("status");

function updateSummary() {
  const selectedProducts = productList.querySelectorAll(".product.selected");
  count.textContent = "Selected products: " + selectedProducts.length;
  selectedList.replaceChildren();
  for (const product of selectedProducts) {
    const name = product.querySelector("h2").textContent;
    const item = document.createElement("li");
    item.textContent = name;
    selectedList.appendChild(item);
  }
}

function handleProductClick(event) {
  if (!(event.target instanceof Element)) return;
  const button = event.target.closest(".select-button");
  if (!button || !productList.contains(button)) return;
  const product = button.closest(".product");
  if (!product || !productList.contains(product)) return;

  const selected = product.classList.toggle("selected");
  button.setAttribute("aria-pressed", String(selected));
  button.textContent = selected ? "Deselect" : "Select";

  const productName = product.querySelector("h2").textContent;
  status.textContent = productName +
    (selected ? " selected." : " deselected.");
  updateSummary();
}

function clearAllSelections() {
  const products = productList.querySelectorAll(".product");
  for (const product of products) {
    product.classList.remove("selected");
    const button = product.querySelector(".select-button");
    button.setAttribute("aria-pressed", "false");
    button.textContent = "Select";
  }
  status.textContent = "Selection cleared.";
  updateSummary();
}

productList.addEventListener("click", handleProductClick);
clearSelection.addEventListener("click", clearAllSelections);
updateSummary();
```

### Code breakdown and trace

- `productList` is the stable ancestor holding the single delegated listener.
- `closest(".select-button")` finds the intended control, including when a nested child is clicked.
- `classList.toggle("selected")` adds/removes the class and returns whether it is present afterward.
- `aria-pressed` communicates toggle state to assistive technology.
- `querySelectorAll(".product.selected")` returns a static list of selected cards at that moment.
- `replaceChildren()` clears the previous summary before rebuilding it.
- `textContent` safely inserts product names as text.

## 24. Ten interview questions and answers

1. **What is the click event?** An activation event generally associated with primary-button activation or equivalent activation from other input methods.
2. **Is click mouse-only?** No; touch, pen, keyboard, assistive technologies, and programmatic activation can produce it.
3. **How does click differ from mousedown?** `mousedown` represents a mouse button press; `click` represents completed activation.
4. **Which interface represents click?** Usually `PointerEvent` in modern browsers, inheriting from `MouseEvent`; compatibility and synthetic events can differ.
5. **How do button and buttons differ?** `button` identifies the associated button; `buttons` is the pressed-button bitmask.
6. **What does detail represent?** Commonly the repeated click count for pointer clicks; keyboard activation commonly uses zero.
7. **Does preventDefault stop propagation?** No; it cancels permitted default actions. `stopPropagation()` controls propagation.
8. **How does click() differ from dispatchEvent()?** `click()` invokes HTML programmatic activation; `dispatchEvent()` dispatches an explicitly supplied event object.
9. **Why prefer native buttons?** They provide semantics, keyboard activation, focus behavior, and accessibility support.
10. **How do you handle dynamically added buttons?** Use event delegation on a stable ancestor, with a safe `closest()` check.

## 25. Ten exercises with solutions

### Exercise 1 - Register a click listener

**Task:** Log `Clicked` when a button activates.

```javascript
const button = document.getElementById("myButton");
button.addEventListener("click", function () {
  console.log("Clicked");
});
```

**Why:** `addEventListener()` registers the callback without calling it immediately.

### Exercise 2 - Print the event type

```javascript
button.addEventListener("click", function (event) {
  console.log(event.type); // "click"
});
```

**Why:** The event object carries the dispatched type.

### Exercise 3 - Compare target and currentTarget

```javascript
button.addEventListener("click", function (event) {
  console.log("target:", event.target);
  console.log("currentTarget:", event.currentTarget);
});
```

**Why:** Nested content can make `target` differ from the button listener's `currentTarget`.

### Exercise 4 - Log coordinates

```javascript
button.addEventListener("click", function (event) {
  console.log(event.clientX, event.clientY);
});
```

**Why:** These are viewport-relative coordinates; keyboard activation may not have meaningful pointer coordinates.

### Exercise 5 - Prevent link navigation

```javascript
const link = document.getElementById("myLink");
link.addEventListener("click", function (event) {
  event.preventDefault();
  console.log("Navigation prevented");
});
```

**Why:** `preventDefault()` cancels a cancelable default navigation action.

### Exercise 6 - Run a listener once

```javascript
button.addEventListener("click", function () {
  console.log("Only once");
}, { once: true });
```

**Why:** The listener removes itself after its first invocation.

### Exercise 7 - Activate programmatically

```javascript
button.click();
```

**Why:** This invokes programmatic HTML click activation, not a trusted physical click.

### Exercise 8 - Dispatch a synthetic MouseEvent

```javascript
const event = new MouseEvent("click", {
  bubbles: true,
  cancelable: true
});
button.dispatchEvent(event);
```

**Why:** `dispatchEvent()` sends the exact event object you construct.

### Exercise 9 - Delegate button clicks

```javascript
const container = document.getElementById("container");
container.addEventListener("click", function (event) {
  if (!(event.target instanceof Element)) return;
  const button = event.target.closest("button");
  if (!button || !container.contains(button)) return;
  console.log(button.textContent.trim());
});
```

**Why:** One listener can handle multiple existing or future child buttons.

### Exercise 10 - Prevent duplicate async activation

```javascript
const saveButton = document.getElementById("saveButton");

function delay(milliseconds) {
  return new Promise(function (resolve) {
    setTimeout(resolve, milliseconds);
  });
}

saveButton.addEventListener("click", async function (event) {
  const currentButton = event.currentTarget;
  currentButton.disabled = true;
  currentButton.textContent = "Saving...";
  try {
    await delay(1000);
    currentButton.textContent = "Saved";
  } catch (error) {
    console.error(error);
    currentButton.textContent = "Try Again";
  } finally {
    currentButton.disabled = false;
  }
});
```

**Why:** Saving `currentTarget` before `await` preserves the element reference, and `finally` restores button availability. This simulates asynchronous work; it does not replace server-side idempotency.

## 26. Ten quiz questions with explanations

Try answering each before revealing the answer in the text below.

1. **Can a native button's click event be triggered by a keyboard?**  
   A. Yes  B. No  
   **Answer: A.** Enter or Space can activate native buttons and dispatch click events.

2. **Which event normally occurs on a mouse button press?**  
   A. click  B. mousedown  C. dblclick  D. load  
   **Answer: B.** `mousedown` represents the press; `click` generally follows completed activation.

3. **Which property commonly reports click count?**  
   A. button  B. target  C. detail  D. timeStamp  
   **Answer: C.** `UIEvent.detail` commonly contains the repeated pointer click count.

4. **Which property gives viewport-relative X coordinates?**  
   A. screenX  B. pageX  C. clientX  D. offsetX  
   **Answer: C.** `clientX` is viewport-relative.

5. **What is the primary mouse button's `button` value?**  
   A. 0  B. 1  C. 2  D. 4  
   **Answer: A.** The primary button uses `0`.

6. **Does `preventDefault()` stop propagation?**  
   A. Yes  B. No  
   **Answer: B.** It requests default-action cancellation; propagation has separate methods.

7. **Does `element.click()` create a trusted click?**  
   A. Yes  B. No  
   **Answer: B.** Programmatic click activation generates an untrusted click event.

8. **Which HTML element is preferable for a clickable action?**  
   A. div  B. span  C. button  D. p  
   **Answer: C.** A native button supplies semantics, focus, and keyboard activation.

9. **Which listener option automatically removes the listener after first invocation?**  
   A. capture  B. passive  C. once  D. signal  
   **Answer: C.** `{ once: true }` removes the listener after the first invocation.

10. **Which method finds the nearest containing button from a clicked span?**  
    A. closest()  B. getAttribute()  C. replaceChildren()  D. remove()  
    **Answer: A.** `closest("button")` finds the nearest matching ancestor or the element itself.

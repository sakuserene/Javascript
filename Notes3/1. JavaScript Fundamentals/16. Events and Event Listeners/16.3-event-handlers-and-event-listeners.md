## 2. What is an event handler?

An **event handler** is a function that responds to an event.

```javascript
function showMessage() {
  console.log("Button clicked");
}
```

This declaration creates a function named `showMessage`, but it does **not** connect the function to any button. We must register or assign the function:

```html
<button id="myButton" type="button">Click Me</button>
```

```javascript
const button = document.getElementById("myButton");
button.addEventListener("click", showMessage);
```

**Conceptual flow:**

```text
Define showMessage()
       |
       v
Register it for "click" on the button
       |
       v
Browser dispatches a matching click event
       |
       v
Browser invokes showMessage()
       |
       v
Console prints "Button clicked"
```

**Function declaration breakdown:**

| Token | Explanation |
|---|---|
| `function` | Starts a function declaration. |
| `showMessage` | Function identifier; lets other code refer to the function. |
| `()` | Parameter list, empty here. |
| `{` | Begins the function body. |
| `console` | Console object supplied by the environment. |
| `.` | Property access operator. |
| `log` | Method used to print a console message. |
| `("Button clicked")` | Passes one string argument to `log`. |
| `;` | Terminates the statement. |
| `}` | Ends the function body. |

**Execution trace:** (1) The function is available. (2) The script selects the button. (3) The listener is registered. (4) No message is printed yet. (5) When a click event reaches the listener, the function executes and prints the message.

## 3. What is an event listener?

An **event listener** is a registered callback associated with a particular event type on an event target. The **handler** is the response function; the **listener registration** connects it to an event target.

```javascript
function greet() {
  console.log("Hello");
}

button.addEventListener("click", greet);
```

| Concept | Meaning | Example |
|---|---|---|
| Event target | Object receiving events | `button` |
| Event type | Kind of event | `"click"` |
| Handler | Function responding to event | `greet` |
| Listener registration | Connection between target, type, callback | `addEventListener(...)` |
| Event object | Details about dispatched event | `event.type` |

The terms *handler* and *listener* are sometimes used interchangeably. The distinction above helps explain the code precisely.

## 4. Three ways to handle DOM events

### 4.1 Inline HTML event-handler attributes

```html
<button onclick="alert('Hello')">Click Me</button>
```

| Syntax | Explanation |
|---|---|
| `onclick` | HTML event-handler content attribute. |
| `=` | Associates the attribute with its value. |
| Outer `"..."` | HTML attribute value. |
| `alert` | Browser function displaying a modal alert. |
| `(` and `)` | Function call parentheses. |
| `'Hello'` | String passed to `alert`. |

This works in many browser contexts but mixes behavior into markup, is harder to maintain, and can be blocked by strict Content Security Policies. **Avoid it in modern projects.**

### 4.2 Event-handler properties

```javascript
button.onclick = function () {
  console.log("Clicked");
};
```

The function is assigned to the DOM object's `onclick` property. It is **not** called during assignment.

### 4.3 addEventListener()

```javascript
button.addEventListener("click", function () {
  console.log("Clicked");
});
```

This registers an independent listener. More than one callback can be registered for the same event type.

## 5. Event-handler properties

Common properties include `onclick`, `oninput`, `onchange`, `onkeydown`, `onkeyup`, `onfocus`, and `onblur`.

```html
<button id="myButton" type="button">Click Me</button>
```

```javascript
const button = document.getElementById("myButton");
button.onclick = function () {
  console.log("Button clicked");
};
```

**Line-by-line syntax:**

| Piece | Meaning |
|---|---|
| `const` | Declares a binding that cannot be reassigned. |
| `button` | Variable holding a reference to the element. |
| `=` | Assigns a value. |
| `document` | DOM document object. |
| `.getElementById` | Accesses a DOM lookup method. |
| `("myButton")` | Calls that method with an ID string. |
| `button.onclick` | Reads or assigns the button's click handler property. |
| `function () { ... }` | Creates an anonymous function object. |
| `console.log(...)` | Runs later when the handler is invoked. |

**Execution trace:**

```text
Script starts
  -> Select #myButton
  -> Create function object
  -> Assign function to button.onclick
  -> Script continues
User clicks button
  -> Browser dispatches click
  -> Assigned handler executes
  -> Console: Button clicked
```

## 6. Why onclick can be overwritten

```javascript
button.onclick = function () {
  console.log("First handler");
};

button.onclick = function () {
  console.log("Second handler");
};
```

**Output after one click:**

```text
Second handler
```

The second `=` assignment replaces the first handler property's value.

This is similar to:

```javascript
let number = 10;
number = 20;
console.log(number); // 20
```

`=` is the **assignment operator**, not a comparison. The right-hand expression is evaluated and stored in the left-hand variable or property. Reassigning `onclick` does **not** remove independently registered `addEventListener()` callbacks.

## 7. Using addEventListener

**General form:**

```javascript
target.addEventListener(type, callback, options);
```

| Argument | Role | Example |
|---|---|---|
| `type` | Event name, a string | `"click"` |
| `callback` | Function or listener object to invoke | `handleClick` |
| `options` | Optional listener configuration | `{ once: true }` |

**Detailed breakdown:**

```javascript
button.addEventListener("click", function () {
  console.log("Button clicked");
});
```

| Piece | Explanation |
|---|---|
| `button` | Event target reference. |
| `.` | Property access. |
| `addEventListener` | Method for registering an event listener. |
| `(` | Opens method argument list. |
| `"click"` | First argument: event type. |
| `,` | Separates arguments. |
| `function () { ... }` | Second argument: callback function object. |
| `)` | Closes method call. |
| `;` | Terminates statement. |

The callback is **registered, not executed**. `addEventListener()` returns `undefined`.

```javascript
button.addEventListener("click", function () {
  console.log("First");
});
button.addEventListener("click", function () {
  console.log("Second");
});
```

For this example, one click prints `First` and then `Second`.

The method also supports capture, once, passive, and abort-signal options, which we will study in dedicated lessons.

## 8. Comparing the approaches

| Feature | Inline HTML attribute | `onclick` property | `addEventListener()` |
|---|---|---|---|
| Behavior separated from HTML | No | Yes | Yes |
| Multiple independent listeners for same type | Not through one attribute | One property handler | Yes |
| Capturing option | No | No | Yes |
| `once` and `passive` options | No | No | Yes |
| Remove handler | Remove attribute | Set property to `null` | `removeEventListener()` |
| Recommended general approach | Avoid | Sometimes useful | Preferred |

**Practical rule:** Use `addEventListener()` for most event-driven JavaScript applications.

## 9. Named functions

```html
<button id="greetButton" type="button">Greet</button>
```

```javascript
const greetButton = document.getElementById("greetButton");

function greetUser() {
  console.log("Welcome!");
}

greetButton.addEventListener("click", greetUser);
```

Named functions improve readability, reuse, debugging, and listener removal.

**Trace:**

```text
1. Select #greetButton.
2. Define greetUser.
3. Pass greetUser as a function reference.
4. Register click listener.
5. Wait for a click event.
6. Browser calls greetUser.
7. Console prints Welcome!
```

## 10. Function references versus calls

Given:

```javascript
function greet() {
  console.log("Hello");
}
```

**Function reference:**

```javascript
greet
```

This evaluates to the function object. No function body runs.

**Function call:**

```javascript
greet()
```

The `()` invokes the function immediately.

**Correct:**

```javascript
button.addEventListener("click", greet);
```

**Wrong for registering `greet` as the callback:**

```javascript
button.addEventListener("click", greet());
```

**Detailed trace of the wrong version:**

1. JavaScript evaluates the arguments before invoking `addEventListener`.
2. It sees `greet()` and immediately calls `greet`.
3. `greet` prints `Hello`.
4. `greet` reaches the end without `return` and therefore returns `undefined`.
5. The registration receives `undefined`, which is treated as a null callback by this API.
6. No `greet` listener is registered.

| Expression | Meaning | Runs now? |
|---|---|---|
| `greet` | Function reference | No |
| `greet()` | Function call | Yes |
| `greet("Alice")` | Function call with argument | Yes |
| `() => greet("Alice")` | Creates a wrapper that calls `greet` later | No |

## 11. Passing arguments to handlers

Suppose we need to supply a name:

```javascript
function greet(name) {
  console.log("Hello " + name);
}
```

**Incorrect:**

```javascript
button.addEventListener("click", greet("Alice"));
```

This calls `greet` during registration.

**Correct wrapper:**

```javascript
button.addEventListener("click", function () {
  greet("Alice");
});
```

**Correct arrow wrapper:**

```javascript
button.addEventListener("click", () => {
  greet("Alice");
});
```

The wrapper function is registered. When clicked, the browser calls the wrapper, and **then** the wrapper calls `greet("Alice")`.

**Trace:**

```text
Register callback wrapper
       |
       v
Wait for click
       |
       v
Browser invokes wrapper
       |
       v
Wrapper invokes greet("Alice")
       |
       v
Console prints Hello Alice
```

The `+` operator concatenates strings here: `"Hello " + "Alice"` produces `"Hello Alice"`.

## 12. Anonymous functions

```javascript
button.addEventListener("click", function () {
  console.log("Clicked");
});
```

The `function () { ... }` expression does not declare an explicit function name. It is useful for short local handlers. However, if you do not retain the function object, you cannot later remove that exact callback by recreating identical-looking code.

```javascript
// Two different function objects:
function () { console.log("Hi"); } // Example expression only
function () { console.log("Hi"); } // Another expression
```

In actual code, function expressions must appear in valid expression contexts such as an assignment or argument list:

```javascript
const first = function () { console.log("Hi"); };
const second = function () { console.log("Hi"); };
console.log(first === second); // false
```

## 13. Arrow functions

```javascript
button.addEventListener("click", () => {
  console.log("Clicked");
});
```

| Piece | Meaning |
|---|---|
| `()` | No parameters. |
| `=>` | Arrow function syntax. |
| `{ ... }` | Function body. |
| `console.log(...)` | Code executed when invoked. |

With event parameter:

```javascript
button.addEventListener("click", (event) => {
  console.log(event.type);
});
```

`event` is a parameter receiving the browser-supplied event object. With one simple parameter, parentheses may be omitted:

```javascript
button.addEventListener("click", event => {
  console.log(event.type);
});
```

Parentheses are required for zero or multiple parameters.

## 14. Regular versus arrow functions and this

**Regular function:**

```javascript
button.addEventListener("click", function (event) {
  console.log(this === event.currentTarget); // true
});
```

The DOM event system calls a regular listener function with `this` set to the current event target.

**Arrow function:**

```javascript
button.addEventListener("click", (event) => {
  console.log(event.currentTarget);
  // 'this' is inherited from the surrounding scope.
});
```

Arrow functions have **lexical `this`**, so `this` does not automatically become the clicked element. Use `event.currentTarget` when you need the object whose listener is running. `event.target` may differ when events bubble from nested elements.

## 15. Multiple listeners

```javascript
button.addEventListener("click", function () {
  console.log("Listener A");
});
button.addEventListener("click", function () {
  console.log("Listener B");
});
button.addEventListener("click", function () {
  console.log("Listener C");
});
```

For one click, these listeners on the same target and phase normally run in registration order:

```text
Listener A
Listener B
Listener C
```

One element can also listen for different event types:

```javascript
button.addEventListener("click", () => console.log("Clicked"));
button.addEventListener("mouseenter", () => console.log("Entered"));
button.addEventListener("mouseleave", () => console.log("Left"));
```

## 16. Listener identity

```javascript
function showMessage() {
  console.log("Hello");
}
button.addEventListener("click", showMessage);
button.addEventListener("click", showMessage);
```

For the same target, event type, callback object, and capture setting, the duplicate registration is ignored.

But separate anonymous functions are different objects:

```javascript
button.addEventListener("click", function () {
  console.log("Hello");
});
button.addEventListener("click", function () {
  console.log("Hello");
});
```

Both can run.

**Understanding `===`:**

```javascript
const first = function () { console.log("Hello"); };
const second = function () { console.log("Hello"); };
console.log(first === second); // false
```

`===` is the **strict equality operator**. For objects and functions, it checks whether both operands refer to the **same object**. Identical source code does not imply identical function identity.

## 17. Removing listeners

```javascript
function showMessage() {
  console.log("Hello");
}

button.addEventListener("click", showMessage);
button.removeEventListener("click", showMessage);
```

The listener is removed because the same callback reference is used.

**Incorrect:**

```javascript
button.addEventListener("click", function () {
  console.log("Hello");
});
button.removeEventListener("click", function () {
  console.log("Hello");
});
```

The removal does nothing to the first listener because the second function is a different object.

**Correct retained reference:**

```javascript
const handler = function () {
  console.log("Hello");
};
button.addEventListener("click", handler);
button.removeEventListener("click", handler);
```

Removal also requires matching the event type and capture setting. Options such as `passive` are not used to match removals. A removed listener does not run on future matching events; removal during an active dispatch has additional timing rules.

## 18. Handler properties and listeners together

```javascript
button.onclick = function () {
  console.log("Property handler");
};
button.addEventListener("click", function () {
  console.log("Independent listener");
});
```

Both may execute. Their order depends on registration details; in this simple example, the property handler is registered first and normally executes first.

```javascript
button.onclick = function () {
  console.log("First property handler");
};
button.addEventListener("click", function () {
  console.log("Independent listener");
});
button.onclick = function () {
  console.log("Second property handler");
};
```

The new property handler replaces the old property handler. The independent listener remains.

## 19. Common event-handling patterns

**Pattern A - Named handler:**

```javascript
function handleClick() {
  console.log("Clicked");
}
button.addEventListener("click", handleClick);
```

**Pattern B - Anonymous handler:**

```javascript
button.addEventListener("click", function () {
  console.log("Clicked");
});
```

**Pattern C - Arrow handler:**

```javascript
button.addEventListener("click", () => {
  console.log("Clicked");
});
```

**Pattern D - Access event object:**

```javascript
button.addEventListener("click", function (event) {
  console.log(event.type);
});
```

**Pattern E - Separate application logic:**

```javascript
function saveData() {
  console.log("Data saved");
}
button.addEventListener("click", function () {
  saveData();
});
```

Separation makes handler behavior easier to test and reuse.

```javascript
const message = document.getElementById("message");
const helloButton = document.getElementById("helloButton");
const welcomeButton = document.getElementById("welcomeButton");
const resetButton = document.getElementById("resetButton");

function updateMessage(text) {
  message.textContent = text;
}

function showHello() {
  updateMessage("Hello!");
}

function showWelcome() {
  updateMessage("Welcome to JavaScript Events!");
}

function resetMessage() {
  updateMessage("Choose an action.");
}

helloButton.addEventListener("click", showHello);
welcomeButton.addEventListener("click", showWelcome);
resetButton.addEventListener("click", resetMessage);
```

### 20.6 Explain every important expression

`const message = document.getElementById("message");` selects the paragraph and stores its DOM reference. `const` prevents reassignment of the binding, but does **not** freeze the DOM element; changing `message.textContent` is allowed.

`function updateMessage(text) { ... }` declares a function with one parameter. `text` is a local name for the value supplied by its caller. `message.textContent = text` updates the paragraph's text. The assignment operator `=` stores the new string in the property.

`function showHello() { updateMessage("Hello!"); }` declares a named handler. When invoked, it calls `updateMessage` with one string argument.

`helloButton.addEventListener("click", showHello);` registers the function reference. **No parentheses after `showHello`**: otherwise the function would execute immediately.

### 20.7 Execution trace - Say Hello

| Step | Active operation | Effect |
|---|---|---|
| 1 | User clicks Say Hello | Browser dispatches click. |
| 2 | Listener invokes `showHello` | Handler begins. |
| 3 | `showHello` calls `updateMessage("Hello!")` | Argument is passed. |
| 4 | Parameter `text` receives `"Hello!"` | Local value available. |
| 5 | `message.textContent = text` | Paragraph changes to `Hello!`. |
| 6 | `updateMessage` returns | Caller resumes. |
| 7 | `showHello` returns | Handler completes. |

**Try it:** Open `index.html`, click each button, and verify that the message changes to the expected text. Inspect the browser console for errors.

  margin: 6px;
  border: none;
  border-radius: 6px;

  color: white;
  cursor: pointer;

### 21.5 script.js

```javascript
const targetButton = document.getElementById("targetButton");
const enableButton = document.getElementById("enableButton");
const disableButton = document.getElementById("disableButton");
const status = document.getElementById("status");
const countDisplay = document.getElementById("count");

let count = 0;
let listenerEnabled = false;

function handleTargetClick() {
  count = count + 1;
  countDisplay.textContent = count;
}

function enableListener() {
  if (listenerEnabled) {
    return;
  }

  targetButton.addEventListener("click", handleTargetClick);
  listenerEnabled = true;
  status.textContent = "Listener: Enabled";
}

function disableListener() {
  if (!listenerEnabled) {
    return;
  }

  targetButton.removeEventListener("click", handleTargetClick);
  listenerEnabled = false;
  status.textContent = "Listener: Disabled";
}

enableButton.addEventListener("click", enableListener);
disableButton.addEventListener("click", disableListener);
```

### 21.6 Breaking down variables and operators

| Code | Meaning |
|---|---|
| `let count = 0` | Create a reassignable numeric variable, starting at zero. |
| `let listenerEnabled = false` | Track whether the target click handler is registered. |
| `count = count + 1` | Read current count, add one, assign result back. |
| `if (listenerEnabled)` | Execute the block only if the boolean is true. |
| `return` | Exit the current function immediately. |
| `!listenerEnabled` | Logical NOT: converts `true` to `false` and `false` to `true`. |
| `listenerEnabled = true` | Record that listener is now registered. |
| `listenerEnabled = false` | Record that listener is now removed. |
| `removeEventListener("click", handleTargetClick)` | Remove matching callback by original reference. |

### 21.7 Why use `if (listenerEnabled) { return; }`?

```javascript
function enableListener() {
  if (listenerEnabled) {
    return;
  }
  // ... register listener
}
```

**First enable click:** `listenerEnabled` is `false`, so the `if` condition is false; execution continues to register the listener.

**Second enable click:** `listenerEnabled` is `true`, so the condition is true; `return` exits immediately. This prevents unnecessary work. Note that `addEventListener()` itself also ignores an exact duplicate registration for the same type, callback, and capture setting.

### 21.8 Why use `if (!listenerEnabled) { return; }`?

`!` is logical NOT:

| `listenerEnabled` | `!listenerEnabled` | Behavior |
|---|---|---|
| `false` | `true` | Return because already disabled. |
| `true` | `false` | Continue and remove listener. |

### 21.9 Execution trace

| User action | Listener enabled before | Operation | Handled count after |
|---|---|---|---|
| Click Target | No | No target listener runs | 0 |
| Enable Listener | No | Register `handleTargetClick` | 0 |
| Click Target | Yes | Increment count | 1 |
| Click Target | Yes | Increment count | 2 |
| Disable Listener | Yes | Remove `handleTargetClick` | 2 |
| Click Target | No | No target listener runs | 2 |
| Enable Listener | No | Register again | 2 |
| Click Target | Yes | Increment count | 3 |

### 21.10 Practical test cases

1. Click target before enabling: count stays 0.
2. Enable and click target twice: count becomes 2.
3. Click Enable again: count behavior remains one increment per click.
4. Disable and click target: count stays 2.
5. Enable again and click target: count becomes 3.
6. Check the console: there should be no errors.

## 22. Common mistakes

| Mistake | Why it happens | Fix |
|---|---|---|
| `addEventListener("click", greet())` | Calls function during registration. | Pass `greet`. |
| Inline `onclick` everywhere | Behavior mixed into HTML. | Register in JavaScript. |
| Assign `onclick` twice expecting both | Second assignment replaces property handler. | Use separate listeners. |
| Remove using a new anonymous function | Callback identity differs. | Store and reuse original function reference. |
| Assume same function source means same object | `===` compares function references. | Retain the function object. |
| Assume arrow `this` equals element | Arrow functions inherit lexical `this`. | Use `event.currentTarget`. |
| Misspell `"click"` as `"clicked"` | Different event type. | Use documented event names. |
| Register before DOM exists | Selector returns `null`. | Use `defer` or DOM-ready logic. |
| Confuse `target` and `currentTarget` | Events may bubble. | Inspect both properties. |
| Assume listener runs only once | Listeners persist by default. | Remove it or use `{ once: true }`. |

**Debugging tip:** If you see `Cannot read properties of null`, inspect the selector ID and whether the script ran before the element was parsed.

## 23. Ten interview questions and answers

### Q1. What is an event handler?

**Answer:** An event handler is a function containing code that responds to an event. Example: `function handleClick() { console.log("Clicked"); }`.

### Q2. What is an event listener?

**Answer:** An event listener is a callback registration on an event target for an event type, such as `button.addEventListener("click", handleClick)`.

### Q3. What is the difference between a handler and a listener?

**Answer:** A handler is the response function; a listener is the registration connecting a callback to an event target and type. The words are often used interchangeably in casual discussion.

### Q4. What are three common ways to handle DOM events?

**Answer:** Inline HTML attributes (`onclick="..."`), event-handler properties (`button.onclick = fn`), and `addEventListener()` (`button.addEventListener("click", fn)`).

### Q5. Why is addEventListener generally preferred?

**Answer:** It supports multiple independent listeners, listener options, explicit removal, and separation of HTML from JavaScript.

### Q6. What happens when onclick is assigned twice?

**Answer:** The second property assignment replaces the first property handler. It does not remove independent `addEventListener()` registrations.

### Q7. Why pass a function reference instead of calling it?

**Answer:** `handleClick` refers to the function object for later invocation. `handleClick()` calls it immediately and passes its return value.

### Q8. Why are identical-looking anonymous functions different listeners?

**Answer:** Each function expression creates a separate function object. Listener matching uses callback identity, not textual equality.

### Q9. How do you remove a listener correctly?

**Answer:** Call `removeEventListener()` with the matching event type, original callback object, and capture setting.

### Q10. How does `this` differ between regular and arrow handlers?

**Answer:** In a regular function invoked by the DOM event system, `this` is the current event target. In an arrow function, `this` is inherited from its surrounding lexical scope. `event.currentTarget` explicitly identifies the current target.

## 24. Ten coding exercises with solutions

> **Setup:** For each exercise, create the HTML elements with the IDs shown. Put the JavaScript in a deferred script or after the elements in the document. Try solving the exercise before reading the solution.

### Exercise 1 - Create a named event handler

**Task:** Select `#myButton`, create `showMessage`, and log `Hello` on click.

```html
<button id="myButton" type="button">Click</button>
```

**Solution:**

```javascript
const button = document.getElementById("myButton");

function showMessage() {
  console.log("Hello");
}

button.addEventListener("click", showMessage);
```

**Explanation:** `showMessage` is passed without `()` so the browser can invoke it later. **Trace:** select button -> define function -> register listener -> click -> log `Hello`.

### Exercise 2 - Use an anonymous function

**Task:** Log `Clicked` using an anonymous handler.

**Solution:**

```javascript
const button = document.getElementById("myButton");

button.addEventListener("click", function () {
  console.log("Clicked");
});
```

**Explanation:** The anonymous function expression is created as the second argument. The comma separates the event type from the callback.

### Exercise 3 - Use an arrow function

**Task:** Register an arrow function for the button's click event.

**Solution:**

```javascript
const button = document.getElementById("myButton");

button.addEventListener("click", () => {
  console.log("Clicked");
});
```

**Explanation:** `()` means no parameters and `=>` introduces the arrow function. Its body runs when the event is handled.

### Exercise 4 - Pass an argument to a handler

**Task:** Call `greet("Alice")` when clicked, but not during registration.

**Solution:**

```javascript
const button = document.getElementById("myButton");

function greet(name) {
  console.log("Hello " + name);
}

button.addEventListener("click", function () {
  greet("Alice");
});
```

**Explanation:** The wrapper runs on click and calls `greet`. The parameter `name` receives `"Alice"`; `+` concatenates the two strings. **Trace:** register wrapper -> click -> invoke wrapper -> invoke greet -> print `Hello Alice`.

### Exercise 5 - Use an onclick property

**Task:** Assign a handler through the button's `onclick` property.

**Solution:**

```javascript
const button = document.getElementById("myButton");

button.onclick = function () {
  console.log("Clicked");
};
```

**Explanation:** `=` assigns a function object to the property. This is not the same as immediately calling it.

### Exercise 6 - Register multiple listeners

**Task:** Print `First` and `Second` using separate click listeners.

**Solution:**

```javascript
const button = document.getElementById("myButton");

button.addEventListener("click", function () {
  console.log("First");
});

button.addEventListener("click", function () {
  console.log("Second");
});
```

**Explanation:** Two distinct function objects are registered. A click invokes both in this example, printing `First` and then `Second`.

### Exercise 7 - Remove a named listener

**Task:** Register `handleClick` and then remove it.

**Solution:**

```javascript
const button = document.getElementById("myButton");

function handleClick() {
  console.log("Clicked");
}

button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

**Explanation:** Both methods receive the **same** callback object and event type. After removal, clicking does not invoke `handleClick`.

### Exercise 8 - Compare function identities

**Task:** Create two separate functions with identical bodies and compare with `===`.

**Solution:**

```javascript
const first = function () {
  console.log("Hello");
};

const second = function () {
  console.log("Hello");
};

console.log(first === second);
```

**Output:** `false`.

**Explanation:** `===` is strict equality. Two separate function expressions create different function objects even when the source code is identical.

### Exercise 9 - Use event.currentTarget

**Task:** Print the object whose listener is executing.

**Solution:**

```javascript
const button = document.getElementById("myButton");

button.addEventListener("click", (event) => {
  console.log(event.currentTarget);
});
```

**Explanation:** `event` receives the event object; `.currentTarget` refers to the event target currently handling the event. It works in both regular and arrow callbacks.

### Exercise 10 - Build a listener toggle

**Task:** Use Enable and Disable buttons to register and remove a click handler from a target button.

**HTML:**

```html
<button id="target" type="button">Target</button>
<button id="enable" type="button">Enable</button>
<button id="disable" type="button">Disable</button>
```

**Solution:**

```javascript
const target = document.getElementById("target");
const enable = document.getElementById("enable");
const disable = document.getElementById("disable");

function handleClick() {
  console.log("Target clicked");
}

enable.addEventListener("click", function () {
  target.addEventListener("click", handleClick);
});

disable.addEventListener("click", function () {
  target.removeEventListener("click", handleClick);
});
```

**Explanation:** The stable `handleClick` reference is used for both registration and removal. Repeated registrations with the same target, type, callback, and capture setting do not create duplicates. **Trace:** click Enable -> register target handler -> click Target -> log message -> click Disable -> remove handler -> click Target -> no message.

## 26. Summary

| Concept | Main takeaway |
|---|---|
| Handler | Function that responds to an event. |
| Listener | Registration connecting callback, event type, and target. |
| Inline attribute | Works but mixes markup and behavior. |
| `onclick` | Property that can be overwritten by assignment. |

| Named function | Reusable reference useful for cleanup. |

| Function reference | `greet` - do not execute now. |

| Listener identity | Matching uses object identity, not source text. |
| `removeEventListener()` | Requires same callback, type, and capture setting. |
| `event.currentTarget` | Target whose listener is currently running. |

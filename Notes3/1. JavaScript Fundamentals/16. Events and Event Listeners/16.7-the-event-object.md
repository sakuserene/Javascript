## 2. What is an Event object?

An **event object** is an object representing an event that is being dispatched or has been dispatched. It carries information about what happened and provides methods that influence dispatch and default behavior.

```html
<button id="myButton" type="button">Click me</button>
<script>
  const button = document.getElementById("myButton");

  button.addEventListener("click", function (event) {
    console.log(event.type);         // "click"
    console.log(event.target);       // Event target
    console.log(event.currentTarget); // Button during this callback
  });
</script>
```

**Breakdown:** `button` refers to a DOM element. `addEventListener` registers a function. `"click"` is the event type. `event` is the callback parameter receiving the event object. `event.type` reads a property of that object. The event object is **not** the button; the button is an event target.

```text
User interaction
       |
       v
Browser dispatches Event object
       |
       v
Matching listener callback runs
       |
       v
Callback inspects event.type, target, phase, etc.
```

## 3. How browsers create and dispatch events

Events can originate from user interaction, browser lifecycle changes, media, networking, application code, and other platform features.

**Browser-generated example:**

```javascript
button.addEventListener("click", function (event) {
  console.log(event.isTrusted);
});
```

**Application-generated example:**

```javascript
const target = new EventTarget();
const event = new Event("hello"); // Construct; does not dispatch

target.addEventListener("hello", function (receivedEvent) {
  console.log(receivedEvent.type);
});

target.dispatchEvent(event); // Dispatch now
```

The event type string determines which listener registrations are eligible, but does not determine the object's JavaScript class: `new Event("click")` and `new MouseEvent("click")` both have type `"click"`, while only the latter carries mouse-specific API members.

## 4. Understanding the event callback parameter

```javascript
button.addEventListener("click", function (event) {
  console.log(event.type);
});
```

| Syntax | Meaning |
|---|---|
| `button` | Target that owns the listener |
| `.` | Property access operator |
| `addEventListener` | `EventTarget` registration method |
| `"click"` | Case-sensitive event type |
| `function` | Ordinary function expression |
| `(event)` | Parameter receiving the event object |
| `{ ... }` | Function body |
| `event.type` | Property lookup on the received event |
| `console.log(...)` | Debug output |

The parameter name is arbitrary:

```javascript
button.addEventListener("click", function (e) {
  console.log(e.type);
});
```

You can omit it if unused. The standard listener callback receives one event argument; an extra declared parameter is not automatically populated:

```javascript
button.addEventListener("click", function (event, name) {
  console.log(name); // undefined
});
```

Use a closure when you need application data:

```javascript
const name = "Alice";
button.addEventListener("click", function (event) {
  console.log(name, event.type);
});
```

## 5. The Event interface and inheritance

The DOM Standard defines the base `Event` interface. Specialized interfaces extend it with properties related to particular interactions.

```text
Event
|-- UIEvent
|   |-- MouseEvent
|   |   |-- PointerEvent
|   |   |-- DragEvent
|   |-- KeyboardEvent
|   |-- FocusEvent
|   |-- InputEvent
|   |-- WheelEvent
|   \-- CompositionEvent
|-- CustomEvent
|-- SubmitEvent
|-- ClipboardEvent
\-- Many additional interfaces
```

This is a simplified selection, not a complete platform inheritance diagram. For example, `ClipboardEvent` is a direct `Event` subtype; `SubmitEvent` is also a direct subtype. The exact interface hierarchy matters when using `instanceof`.

```javascript
const generic = new Event("click");
const mouse = new MouseEvent("click", { clientX: 42 });

console.log(generic.type); // "click"
console.log(mouse.type);   // "click"
console.log(generic instanceof MouseEvent); // false
console.log(mouse instanceof MouseEvent);   // true
console.log(mouse.clientX);                 // 42
```

`instanceof` tests an object's prototype relationship. We will study prototype mechanics in the later OOP curriculum.

## 6. Complete Event constructor syntax

```javascript
new Event(type)
new Event(type, options)
```

| Parameter | Expected type | Required? | Purpose |
|---|---|---|---|
| `type` | String (Web IDL `DOMString`) | Yes | Event name |
| `options` | `EventInit` dictionary | No | Event initialization |

**Every base `EventInit` member:**

| Option | Type | Default | Meaning |
|---|---|---|---|
| `bubbles` | Boolean | `false` | Participates in bubbling |
| `cancelable` | Boolean | `false` | Default action may be canceled |
| `composed` | Boolean | `false` | May cross shadow-root boundary |

```javascript
const event = new Event("notification", {
  bubbles: true,
  cancelable: true,
  composed: false
});
```

**Syntax breakdown:** `new` constructs an object. `Event` is the constructor. `"notification"` supplies the type. The second argument is an object literal containing named option values. `true` and `false` are Boolean literals. A trailing comma is allowed in object literals.

Specialized constructors such as `MouseEvent` and `CustomEvent` accept dictionaries with additional members; they do not change the three base defaults.

## 7. Constructor defaults, validation, and edge cases

```javascript
const event = new Event("hello");
console.log(event.bubbles);    // false
console.log(event.cancelable); // false
console.log(event.composed);   // false
```

These are defaults for **constructed generic events**, not universal values for native events. Native clicks typically bubble and are cancelable.

The type argument undergoes string conversion:

```javascript
console.log(new Event(123).type); // "123"
```

The constructor can produce an empty type, but dispatching it fails:

```javascript
const target = new EventTarget();
const event = new Event("");

try {
  target.dispatchEvent(event);
} catch (error) {
  console.log(error.name); // "InvalidStateError"
}
```

An event already being dispatched cannot be dispatched again until that dispatch finishes. `dispatchEvent()` also requires an `Event` object; passing the wrong argument results in a `TypeError`. Web IDL converts dictionary members according to their declared types; use an ordinary options object to avoid surprises.

## 8. Creating and dispatching events

```javascript
const target = new EventTarget();

function handleHello(event) {
  console.log("Received:", event.type);
}

target.addEventListener("hello", handleHello);
const event = new Event("hello");
const result = target.dispatchEvent(event);
console.log(result); // true
```

**Execution trace:**

| Step | Operation | Effect |
|---|---|---|
| 1 | `new EventTarget()` | Creates a target |
| 2 | Define `handleHello` | Creates callback |
| 3 | `addEventListener` | Registers callback |
| 4 | `new Event("hello")` | Creates event, no dispatch yet |
| 5 | `dispatchEvent(event)` | Starts synchronous dispatch |
| 6 | Matching callback runs | Logs `Received: hello` |
| 7 | Dispatch finishes | Returns `true` |

**Return value:** `dispatchEvent()` returns `false` if the dispatched event is cancelable and its default was prevented. Otherwise it returns `true`.

```javascript
const target = new EventTarget();
target.addEventListener("save", e => e.preventDefault());

const event = new Event("save", { cancelable: true });
console.log(target.dispatchEvent(event)); // false
console.log(event.defaultPrevented);       // true
```

`dispatchEvent()` is a method of **EventTarget**, not a method of the `Event` object. It invokes applicable listeners synchronously; it does not await promises returned by async listeners.

| Property | Type | Meaning | Notes |
|---|---|---|---|
| `type` | String | Event type | Read-only |
| `target` | `EventTarget` or `null` | Event target | Retargeting may apply |
| `currentTarget` | `EventTarget` or `null` | Target whose listener is running | Usually `null` outside dispatch |
| `eventPhase` | Number | Current phase | 0, 1, 2, or 3 |
| `bubbles` | Boolean | Bubbling enabled | Read-only |
| `cancelable` | Boolean | Cancelable event | Read-only |

## 10. Understanding event.type

`event.type` is the case-sensitive string naming the event:

```javascript
button.addEventListener("click", event => {
  console.log(event.type); // "click"
});
```

It is read-only and does not determine the object's interface:

```javascript
console.log(new Event("click").type);      // "click"
console.log(new MouseEvent("click").type); // "click"
```

Application-defined names such as `"user:logged-in"` are permitted. Prefer descriptive names and avoid reusing native event names for unrelated behavior.

## 11. Understanding event.target

`event.target` identifies the target of the event, subject to retargeting rules.

```html
<button id="outerButton"><span id="label">Click label</span></button>
<script>
  const button = document.getElementById("outerButton");
  button.addEventListener("click", event => {
    console.log(event.target.id);
  });
</script>
```

Clicking the span normally logs `label`; clicking exposed button space normally logs `outerButton`.

```text
BUTTON (listener here)
  |
  \-- SPAN (click here)
        |
        \-- event.target = SPAN
```

Before first dispatch, a new event's `target` is `null`. After ordinary dispatch it typically retains the target, though shadow DOM retargeting and path-cleanup rules can affect what observers see.

```javascript
const target = new EventTarget();
const event = new Event("hello");
console.log(event.target); // null
target.dispatchEvent(event);
console.log(event.target === target); // true
```

## 12. Understanding event.currentTarget

`currentTarget` is the event target **whose listener is currently being invoked**.

```html
<div id="parent"><button id="child">Click</button></div>
<script>
  const parent = document.getElementById("parent");
  parent.addEventListener("click", event => {
    console.log(event.target.id);        // "child" when child clicked
    console.log(event.currentTarget.id); // "parent"
  });
</script>
```

**Execution trace:**

| Listener | `target` | `currentTarget` |
|---|---|---|
| Child listener | Child | Child |
| Parent bubbling listener | Child | Parent |
| After dispatch | Usually Child | `null` |

Save `currentTarget` before an `await`:

```javascript
button.addEventListener("click", async event => {
  const current = event.currentTarget;
  await Promise.resolve();
  console.log(current === button); // true
  console.log(event.currentTarget); // normally null
});
```

The event callback's async continuation runs after the synchronous dispatch finishes; the event system does not await it.

## 13. Understanding event.eventPhase

`eventPhase` identifies the phase of event propagation.

```text
Document
   |
   v  CAPTURING (1)
Parent
   |
   v
Button   AT_TARGET (2)
   |
   ^  BUBBLING (3)
Parent
   |
   ^
Document
```

A capturing listener **on the target itself** runs with phase `AT_TARGET` (2), not `CAPTURING_PHASE` (1):

```javascript
button.addEventListener("click", event => {
  console.log(event.eventPhase); // 2 when button is target
}, true);
```

`eventPhase` is `NONE` (0) outside active dispatch.

## 14. Event phase constants

| Constant | Value | Meaning |
|---|---:|---|
| `Event.NONE` | 0 | No active phase |
| `Event.CAPTURING_PHASE` | 1 | Capturing |
| `Event.AT_TARGET` | 2 | At target |
| `Event.BUBBLING_PHASE` | 3 | Bubbling |

```javascript
if (event.eventPhase === Event.BUBBLING_PHASE) {
  console.log("Bubbling");
}
```

Prefer named constants over unexplained numeric literals.

## 15. Understanding event.bubbles

`bubbles` indicates whether an event participates in bubbling:

```javascript
const parent = document.getElementById("parent");
const child = document.getElementById("child");
parent.addEventListener("hello", () => console.log("Parent"));

child.dispatchEvent(new Event("hello", { bubbles: true }));
// Parent

child.dispatchEvent(new Event("hello", { bubbles: false }));
// No output from parent's non-capturing listener
```

**Important:** A non-bubbling event can still reach ancestor **capturing** listeners. The `bubbles` flag controls the bubbling phase, not capturing.

## 16. Understanding event.cancelable

`cancelable` indicates whether an event's default action can be canceled:

```javascript
const event = new Event("hello", { cancelable: true });
console.log(event.cancelable);       // true
console.log(event.defaultPrevented); // false
event.preventDefault();
console.log(event.defaultPrevented); // true
```

`cancelable` describes capability. `defaultPrevented` describes state. The properties are not interchangeable.

```javascript
const nonCancelable = new Event("hello");
nonCancelable.preventDefault();
console.log(nonCancelable.defaultPrevented); // false
```

## 17. Understanding event.composed

`composed` controls whether the event may propagate across a shadow-root boundary.

```javascript
const event = new Event("hello", {
  bubbles: true,
  composed: true
});
```

For an application event intended to bubble out of a shadow root, both `bubbles: true` and `composed: true` are generally needed. A composed non-bubbling event can nevertheless be observed by a host capturing listener at the host's at-target handling. Shadow DOM retargeting may hide internal nodes from outside listeners.

## 18. Understanding event.defaultPrevented

`defaultPrevented` is a read-only Boolean reporting whether cancellation has been requested successfully:

```html
<form id="form"><input required><button>Submit</button></form>
<script>
  document.getElementById("form").addEventListener("submit", event => {
    event.preventDefault();
    console.log(event.defaultPrevented); // true
  });
</script>
```

The `submit` listener runs only when the form submission reaches that event stage; native constraint validation can block submission before it occurs. `preventDefault()` does not stop propagation, and it does not necessarily cancel all browser or OS actions.

## 19. Understanding event.isTrusted

`isTrusted` is `true` for events generated by the user agent and `false` for events dispatched by application code using `dispatchEvent()`:

```javascript
console.log(new Event("hello").isTrusted); // false
```

A real user-generated click commonly has `isTrusted === true`. Calling `button.click()` programmatically creates a click event with `isTrusted === false`.

**Security caution:** `isTrusted` is not proof of user intent, permission, or transaction authorization. Security-sensitive decisions require appropriate application and server-side checks.

## 20. Understanding event.timeStamp

`timeStamp` is a number associated with event creation. Modern browsers generally express it in milliseconds relative to a performance time origin, not the Unix epoch.

```javascript
let previous = null;
button.addEventListener("click", event => {
  if (previous !== null) {
    console.log("Elapsed ms:", event.timeStamp - previous);
  }
  previous = event.timeStamp;
});
```

**Trace:** If the previous timestamp is 3000 and the next is 4500, the difference is 1500 ms. Timestamp precision may be reduced for privacy; do not treat `new Date(event.timeStamp)` as the event's wall-clock time.

## 21. Complete Event method inventory

| Method | Arguments | Return value | Purpose |
|---|---|---|---|
| `preventDefault()` | None | `undefined` | Request default-action cancellation |
| `stopPropagation()` | None | `undefined` | Stop propagation to later targets |
| `stopImmediatePropagation()` | None | `undefined` | Also stop later listeners on current target |
| `composedPath()` | None | Array of `EventTarget`s | Exposed propagation path |
| `initEvent(type, bubbles, cancelable)` | Three legacy arguments | `undefined` | Legacy event initialization |

**Related but not `Event` methods:** `addEventListener()`, `removeEventListener()`, and `dispatchEvent()` belong to `EventTarget`. `new Event(...)` is a constructor, not an instance method.

## 22. preventDefault and default actions

Many browser actions have cancelable events: link navigation, form submission, and certain scrolling or control behaviors.

```html
<a id="link" href="https://example.com">Example</a>
<script>
  document.getElementById("link").addEventListener("click", event => {
    if (event.cancelable) {
      event.preventDefault();
    }
    console.log(event.defaultPrevented);
  });
</script>
```

`preventDefault()` returns `undefined`, not a success flag. Check `defaultPrevented`. In a passive listener, the browser ignores attempts to cancel default behavior:

```javascript
window.addEventListener("wheel", event => {
  event.preventDefault(); // Ignored because listener is passive
}, { passive: true });
```

## 23. Propagation-stopping methods

`stopPropagation()` stops movement to later targets, but does not stop later listeners on the **same** target:

```javascript
button.addEventListener("click", event => {
  console.log("First");
  event.stopPropagation();
});
button.addEventListener("click", () => console.log("Second"));
// Click output: First, Second
```

`stopImmediatePropagation()` also prevents subsequent listeners on the same target:

```javascript
button.addEventListener("click", event => {
  console.log("First");
  event.stopImmediatePropagation();
});
button.addEventListener("click", () => console.log("Second"));
// Click output: First
```

| Behavior | `stopPropagation()` | `stopImmediatePropagation()` |
|---|---|---|
| Stops propagation to later targets | Yes | Yes |
| Stops later listeners on current target | No | Yes |
| Prevents default action | No | No |
| Removes listener registrations | No | No |
| Returns | `undefined` | `undefined` |

Neither method is equivalent to `return`, `preventDefault()`, or `removeEventListener()`.

## 24. composedPath and Shadow DOM

`composedPath()` returns an array of event targets along the **exposed** propagation path:

```javascript
document.addEventListener("click", event => {
  console.log(event.composedPath());
});
```

A typical open-DOM path might be:

```text
[button, div, body, html, document, window]
```

**Shadow DOM example:**

```html
<div id="host"></div>
<script>
  const host = document.getElementById("host");
  const shadow = host.attachShadow({ mode: "open" });
  const inner = document.createElement("button");
  inner.textContent = "Inner";
  shadow.appendChild(inner);

  host.addEventListener("demo", event => {
    console.log("Outside target:", event.target); // host
    console.log("Exposed path:", event.composedPath());
  });

  inner.dispatchEvent(new Event("demo", {
    bubbles: true,
    composed: true
  }));
</script>
```

With an **open** shadow root, an outside listener may see internal nodes in `composedPath()`; with a **closed** root, internal nodes are hidden from outside observers. Do not assume `composedPath()[0]` always reveals the original internal node. After dispatch, `composedPath()` is generally empty.

## 25. Legacy properties and deprecated APIs

| Legacy API | Modern preference | Notes |
|---|---|---|
| `srcElement` | `target` | Legacy alias |
| `cancelBubble = true` | `stopPropagation()` | Setting false does not undo stopping |
| `returnValue = false` | `preventDefault()` | Subject to cancellation rules |
| `initEvent()` | `new Event(...)` | Legacy initialization |
| `document.createEvent()` | Event constructor | Legacy creation pattern |
| `originalTarget`, `explicitOriginalTarget` | Standard target/path APIs | Nonstandard, browser-specific |
| `event.path` | `composedPath()` | Nonstandard |

```javascript
// Legacy:
const oldEvent = document.createEvent("Event");
oldEvent.initEvent("hello", true, true);

// Modern:
const newEvent = new Event("hello", {
  bubbles: true,
  cancelable: true
});
```

`initEvent()` cannot reinitialize an event during dispatch. Prefer constructors for new code.

## 26. Specialized event subclasses

The base `Event` interface is complete above. Specialized event interfaces add more properties and sometimes methods. This inventory introduces the relevant APIs; dedicated lessons cover complete constructor dictionaries, defaults, exceptions, and compatibility.

### 26.1 UIEvent

- `detail`: event-specific numeric detail, often click count for clicks.
- `view`: associated `Window` where applicable.
- `which`: legacy, deprecated in many contexts.

### 26.2 MouseEvent

- Coordinates: `clientX`, `clientY`, `screenX`, `screenY`, `pageX`, `pageY`, `offsetX`, `offsetY`, `movementX`, `movementY`.
- Buttons: `button` (changed button), `buttons` (currently pressed button bitmask).
- Modifiers: `ctrlKey`, `shiftKey`, `altKey`, `metaKey`.
- Other: `relatedTarget`.
- Method: `getModifierState(keyArg)` returns a Boolean.

```javascript
button.addEventListener("click", event => {
  console.log(event.clientX, event.clientY, event.button);
});
```

### 26.3 KeyboardEvent

- `key`, `code`, `location`, `repeat`, `isComposing`.
- `ctrlKey`, `shiftKey`, `altKey`, `metaKey`.
- `getModifierState(keyArg)`.
- Legacy: `keyCode`, `charCode`, `which`.

```javascript
document.addEventListener("keydown", event => {
  console.log(event.key, event.code, event.repeat);
});
```

### 26.4 PointerEvent

- Identity: `pointerId`, `pointerType`, `isPrimary`.
- Geometry: `width`, `height`.
- Pressure: `pressure`, `tangentialPressure`.
- Stylus orientation: `tiltX`, `tiltY`, `twist`, `altitudeAngle`, `azimuthAngle`.
- Additional specialized properties and coalesced/predicted event APIs exist; availability varies.
- Related **Element** methods: `setPointerCapture()`, `releasePointerCapture()`, `hasPointerCapture()`; these are not `PointerEvent` methods.

### 26.5 WheelEvent

- `deltaX`, `deltaY`, `deltaZ`, `deltaMode`.
- `WheelEvent.DOM_DELTA_PIXEL` = 0.
- `WheelEvent.DOM_DELTA_LINE` = 1.
- `WheelEvent.DOM_DELTA_PAGE` = 2.

Wheel deltas are not necessarily pixels; inspect `deltaMode`.

### 26.6 FocusEvent

- `relatedTarget`: the other element in a focus transition, or `null`.

### 26.7 InputEvent

- `data`, `inputType`, `isComposing`, `dataTransfer`.
- `getTargetRanges()`: returns static ranges for certain editing operations.

### 26.8 CompositionEvent

- `data`: composition text.

### 26.9 DragEvent

- `dataTransfer`: drag-and-drop transfer data.
- Inherits mouse-event properties.

### 26.10 ClipboardEvent

- `clipboardData`: clipboard transfer data, subject to browser permissions and security rules.

### 26.11 SubmitEvent

- `submitter`: the submitter responsible for submission, when applicable.

```javascript
form.addEventListener("submit", event => {
  console.log(event.submitter);
});
```

### 26.12 CustomEvent

- `detail`: arbitrary application-defined payload.

```javascript
const event = new CustomEvent("message", {
  detail: { text: "Hello" },
  bubbles: true
});
```

### 26.13 TouchEvent

- `touches`, `targetTouches`, `changedTouches`: `TouchList` collections.
- Individual `Touch` objects contain coordinates and identifiers.
- Touch Events support varies across platforms; Pointer Events provide a unified alternative for many interactions.

### 26.14 Other specialized interfaces

| Interface | Typical purpose |
|---|---|
| `AnimationEvent` | CSS animations |
| `TransitionEvent` | CSS transitions |
| `HashChangeEvent` | Fragment navigation |

## 27. Advanced dispatch and propagation edge cases

### 27.1 Non-bubbling does not mean non-capturing

An event created with `{ bubbles: false }` may still reach ancestor capturing listeners.

### 27.2 Stopping propagation is not returning

```javascript
function handler(event) {
  event.stopPropagation();
  console.log("This still executes");
}
```

### 27.3 Removing a listener during dispatch

```javascript
const target = new EventTarget();
function first() {
  target.removeEventListener("test", second);
}
function second() {
  console.log("Second");
}
target.addEventListener("test", first);
target.addEventListener("test", second);
target.dispatchEvent(new Event("test"));
// No "Second": listener removed before its turn
```

### 27.4 Reusing events

An event may generally be dispatched again **after** a dispatch completes. Redispatching the same event while it is still being dispatched throws `InvalidStateError`.

### 27.5 Nested dispatch with another event

```javascript
const target = new EventTarget();
target.addEventListener("first", () => {
  console.log("First begins");
  target.dispatchEvent(new Event("second"));
  console.log("First ends");
});
target.addEventListener("second", () => console.log("Second"));
target.dispatchEvent(new Event("first"));
```

Output:

```text
First begins
Second
First ends
```

Nested `dispatchEvent()` is synchronous. The browser does not await async listeners' promises.

### 27.6 Exceptions thrown in listeners

Listener exceptions are normally reported as uncaught; they do not ordinarily propagate to the caller of `dispatchEvent()` in the same way as a direct function call. Catch expected errors inside listeners.

### 27.7 Synthetic events and browser actions

`target.dispatchEvent(new Event("click"))` does not generally provide the same capabilities as genuine user interaction. Some privileged browser actions require user activation. `button.click()` also does not create trusted user activation.

### 29.4 Complete `script.js`

```javascript
const parentBox = document.getElementById("parentBox");
const inspectButton = document.getElementById("inspectButton");
const textInput = document.getElementById("textInput");
const customButton = document.getElementById("customButton");
const clearButton = document.getElementById("clearButton");
const eventOutput = document.getElementById("eventOutput");
const eventHistory = document.getElementById("eventHistory");

let eventCount = 0;

function describeTarget(target) {
  if (target === null) {
    return "null";
  }

  if (target instanceof Element) {
    const id = target.id ? "#" + target.id : "";
    return target.tagName.toLowerCase() + id;
  }

  return String(target);
}

function getPhaseName(phase) {
  switch (phase) {
    case Event.NONE:
      return "NONE";
    case Event.CAPTURING_PHASE:
      return "CAPTURING_PHASE";
    case Event.AT_TARGET:
      return "AT_TARGET";
    case Event.BUBBLING_PHASE:
      return "BUBBLING_PHASE";
    default:
      return "UNKNOWN";
  }
}

function inspectEvent(event) {
  eventCount = eventCount + 1;

  const details = {
    count: eventCount,
    interfaceName: event.constructor.name,
    type: event.type,
    target: describeTarget(event.target),
    currentTarget: describeTarget(event.currentTarget),
    eventPhase: event.eventPhase,
    phaseName: getPhaseName(event.eventPhase),
    bubbles: event.bubbles,
    cancelable: event.cancelable,
    composed: event.composed,
    defaultPrevented: event.defaultPrevented,
    isTrusted: event.isTrusted,
    timeStamp: event.timeStamp,
    path: event.composedPath().map(describeTarget)
  };

  if (event instanceof MouseEvent) {
    details.clientX = event.clientX;
    details.clientY = event.clientY;
    details.button = event.button;
    details.buttons = event.buttons;
  }

  if (event instanceof KeyboardEvent) {
    details.key = event.key;
    details.code = event.code;
    details.repeat = event.repeat;
    details.ctrlKey = event.ctrlKey;
    details.shiftKey = event.shiftKey;
  }

  if (event instanceof InputEvent) {
    details.data = event.data;
    details.inputType = event.inputType;
    details.isComposing = event.isComposing;
  }

  if (event instanceof CustomEvent) {
    details.detail = event.detail;
  }

  eventOutput.textContent = JSON.stringify(details, null, 2);

  const item = document.createElement("li");
  item.textContent = eventCount + ". " + event.type +
    " on " + describeTarget(event.target);
  eventHistory.prepend(item);
}

function dispatchCustomEvent() {
  const event = new CustomEvent("inspector:custom", {
    bubbles: true,
    cancelable: true,
    detail: {
      message: "Hello from a custom event",
      source: "Custom Event Button"
    }
  });

  customButton.dispatchEvent(event);
}

function clearOutput() {
  eventCount = 0;
  eventOutput.textContent = "No event inspected yet.";
  eventHistory.replaceChildren();
}

parentBox.addEventListener("click", inspectEvent);
inspectButton.addEventListener("focus", inspectEvent);
textInput.addEventListener("keydown", inspectEvent);
textInput.addEventListener("input", inspectEvent);
customButton.addEventListener("inspector:custom", inspectEvent);
customButton.addEventListener("click", dispatchCustomEvent);
clearButton.addEventListener("click", clearOutput);
```

### 29.5 Beginner-friendly code breakdown

**A. `document.getElementById("...")`:** Looks up an element by ID. Each constant stores the returned element reference. `defer` ensures the script executes after HTML parsing.

**B. `describeTarget(target)`:** Converts an event target into a readable string. `target === null` checks for the absence of a target. `instanceof Element` checks whether the target is a DOM element. `target.id ? ... : ...` is the conditional (ternary) operator: choose the ID suffix when an ID exists, otherwise use an empty string. `tagName.toLowerCase()` produces a lowercase tag name.

**C. `switch (phase)`:** Compares a value to the event phase constants. Each `return` exits the function with a readable phase label.

**D. `eventCount = eventCount + 1`:** Increments the counter. `let` allows reassignment; `const` would not permit reassignment of the binding.

**E. Object literal `details`:** Stores an event snapshot. This is important because `currentTarget`, `eventPhase`, and `composedPath()` describe the active dispatch and can change after the callback returns.

**F. `instanceof`:** Checks the event interface before reading subclass-specific properties. A generic `Event` does not necessarily provide mouse or keyboard properties.

**G. `.map(describeTarget)`:** Calls `describeTarget` for each entry in the array returned by `composedPath()` and creates a new array of descriptions.

**H. `JSON.stringify(details, null, 2)`:** Converts the details object to formatted JSON text. The first argument is the value, the second is a replacer (`null` means none), and the third is indentation width (`2` spaces). JSON receives its own comprehensive later module.

**I. `.textContent`:** Inserts text safely rather than interpreting strings as HTML. `.prepend(item)` inserts a new history entry first. `.replaceChildren()` removes existing children.

**J. `CustomEvent`:** Creates an event with application data in `detail`. Its `"inspector:custom"` type is separate from the original click event used to trigger it.

## 31. Ten interview questions with answers

### Question 1. What is an Event object?

**Answer:** An object representing an event that can expose information such as `type`, `target`, `currentTarget`, `eventPhase`, `bubbles`, `cancelable`, `composed`, `defaultPrevented`, `isTrusted`, and `timeStamp`.

### Question 2. How do `target` and `currentTarget` differ?

**Answer:** `target` identifies the event's target, subject to retargeting. `currentTarget` identifies the target whose listener is currently executing. During bubbling they can differ.

### Question 3. What are the propagation phases?

**Answer:** Capturing (`Event.CAPTURING_PHASE` = 1), at-target (`Event.AT_TARGET` = 2), and bubbling (`Event.BUBBLING_PHASE` = 3). `Event.NONE` = 0 represents no active phase.

### Question 4. How do `bubbles` and `composed` differ?

**Answer:** `bubbles` controls whether the event participates in bubbling. `composed` controls whether it can cross a shadow-root boundary. They are independent flags.

### Question 5. What does `preventDefault()` do?

**Answer:** Requests cancellation of a cancelable event's default action when permitted. It does not stop propagation.

### Question 6. How do the propagation-stopping methods differ?

**Answer:** `stopPropagation()` stops movement to later targets but allows other listeners on the same current target. `stopImmediatePropagation()` also stops later listeners on the current target.

### Question 7. What does `dispatchEvent()` return?

**Answer:** `false` when the cancelable event was canceled; otherwise `true`. It synchronously invokes applicable listeners.

### Question 8. What does `isTrusted` indicate?

**Answer:** Whether the event was generated by the user agent rather than application dispatch. It is not a general-purpose authorization or security guarantee.

### Question 9. How does `MouseEvent` differ from `Event`?

**Answer:** `Event` defines the common event API. `MouseEvent` extends it with mouse-specific information, including coordinates, button states, and modifier keys.

### Question 10. Why can `currentTarget` become null after `await`?

**Answer:** `currentTarget` is set during listener invocation and normally reset when dispatch finishes. An async continuation often resumes after dispatch; save the reference before awaiting.

**Task:** Dispatch a cancelable event and inspect `dispatchEvent()`'s return value.


### Exercise 10. Preserve currentTarget across await

**Task:** Write an async listener that retains its current target.

**Complete solution:**

```javascript
button.addEventListener("click", async event => {
  const current = event.currentTarget;
  await Promise.resolve();

  console.log(current === button);  // true
  console.log(event.currentTarget); // normally null
});
```

**Explanation:** The reference saved in `current` remains available after the event's synchronous dispatch completes.

### 34.4 Final lesson summary

- `event.target` identifies the event's target, subject to retargeting.
- `event.currentTarget` identifies the event target currently invoking the listener.
- `event.eventPhase` identifies the current propagation phase.
- `event.bubbles` controls bubbling, while `event.composed` controls shadow-boundary propagation.
- `event.cancelable` describes cancelability; `event.defaultPrevented` reports cancellation state.
- `event.preventDefault()` requests default-action cancellation.
- `event.stopPropagation()` stops propagation to later targets.
- `event.stopImmediatePropagation()` also stops later listeners on the current target.
- `event.composedPath()` exposes the available event propagation path.
- `event.isTrusted` is useful context but not an authorization guarantee.
- `EventTarget.dispatchEvent()` dispatches synchronously and returns a Boolean indicating whether cancellation occurred.

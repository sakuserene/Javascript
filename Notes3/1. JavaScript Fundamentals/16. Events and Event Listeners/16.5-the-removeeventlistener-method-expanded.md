## 2. What removeEventListener() does

`removeEventListener()` removes a matching event listener registration from a particular `EventTarget`. It does **not** delete the callback function, remove an element, suppress the event itself, remove every listener of the same type, or cancel browser defaults.

```html
<button id="myButton" type="button">Click me</button>
<script src="script.js" defer></script>
```

```javascript
const button = document.getElementById("myButton");
function handleClick() { console.log("Clicked"); }
button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

After removal, clicking the button no longer invokes **this registration**. Other click listeners, if any, continue to run.

```text
Before: button --click--> handleClick()
After:  button --click--> no handleClick registration
```

---

## 3. The EventTarget interface

`removeEventListener()` is a method of `EventTarget`, not of an `Event` object. The standard `EventTarget` methods are:

| Method | Meaning | Return |
|---|---|---|
| `addEventListener(type, callback, options?)` | Register a listener | `undefined` |
| `removeEventListener(type, callback, options?)` | Remove a matching listener | `undefined` |
| `dispatchEvent(event)` | Synchronously dispatch an event | Boolean |

Targets include `window`, `document`, DOM elements, `AbortSignal`, `Worker`, `WebSocket`, and `new EventTarget()`.

```javascript
const target = new EventTarget();
function greet() { console.log("Hello"); }
target.addEventListener("greet", greet);
target.dispatchEvent(new Event("greet")); // Hello
target.removeEventListener("greet", greet);
target.dispatchEvent(new Event("greet")); // no output
```

A plain object (`{}`) does not automatically implement `EventTarget`. Calling its nonexistent `removeEventListener` method throws a `TypeError`.

## 4. Complete syntax and overloads

```javascript
target.removeEventListener(type, callback);
target.removeEventListener(type, callback, useCapture);
target.removeEventListener(type, callback, options);
```

| Argument | Standard meaning | Required? | Default / omission |
|---|---|---|---|
| `type` | Event type, converted to a string | Yes | No default |
| `callback` | EventListener function, object with `handleEvent`, or null | Yes | No default; explicit `null` is a no-op |
| `useCapture` | Boolean shorthand for `capture` | No | `false` |
| `options` | `EventListenerOptions` dictionary | No | `capture: false` |

The third argument is **either** a boolean or an options dictionary. The method returns `undefined` whether or not anything was removed. There is no standard listener ID or success boolean. JavaScript argument conversion may coerce values; use documented types instead of relying on coercion.

## 5. Every syntax token explained

```javascript
button.removeEventListener("click", handleClick, false);
```

| Token | Meaning |
|---|---|
| `button` | Variable containing a target reference |
| `.` | Property/member access operator |
| `removeEventListener` | Method name |
| `(` and `)` | Begin and end the call arguments |
| `"click"` | String literal naming the event type |
| `,` | Argument separator |
| `handleClick` | Callback reference, **not** a call |
| `false` | Boolean capture flag |
| `;` | Statement terminator |

**Critical contrast:** `handleClick` passes the function; `handleClick()` runs it immediately and passes its return value. If that value is `undefined`, no matching callback is removed.

```javascript
function handleClick() { console.log("RUN"); }
button.removeEventListener("click", handleClick());
// Prints RUN immediately; does not remove the original listener.
```

## 6. Matching rules: target, type, callback, capture

The removal algorithm searches **the specified target's listener list** for a registration whose **type**, **callback identity**, and **capture** match. All must agree.

```text
Target: same object? ------ no --> no removal
             |
            yes
             v
Type: same string? -------- no --> no removal
             |
            yes
             v
Callback: same identity? -- no --> no removal
             |
            yes
             v
Capture: same boolean? ---- no --> no removal
             |
            yes
             v
       Remove registration
```

| Registered | Removed using | Result |
|---|---|---|
| `button`, `"click"`, `fn`, `false` | same target/type/`fn`/`false` | Removed |
| `button`, `"click"`, `fn` | `otherButton`/`"click"`/`fn` | Not removed |
| `button`, `"click"`, `fn` | `button`/`"Click"`/`fn` | Not removed |
| `button`, `"click"`, `fn` | `button`/`"click"`/`otherFn` | Not removed |
| `button`, `"click"`, `fn`, `true` | `button`/`"click"`/`fn`, `false` | Not removed |

Event types are case-sensitive. Removing an absent listener is a silent no-op.

## 7. Function identity versus identical source

Two functions can have the same body but be different objects.

```javascript
const a = function () { console.log("Hello"); };
const b = function () { console.log("Hello"); };
console.log(a === b); // false

const c = a;
console.log(a === c); // true
```

`===` compares function object identity, not the text of their implementations.

```text
a --> Function object #1 <-- c
b --> Function object #2
```

`removeEventListener()` matches the callback object itself, not its name or printed source. Renaming a variable does not change the referenced object; creating a new function does.

## 8. Named functions and stable references

```javascript
const button = document.getElementById("myButton");
function onClick(event) {
  console.log("Clicked", event.type);
}
button.addEventListener("click", onClick);
button.removeEventListener("click", onClick);
```

The same function object is referenced twice. A stable variable works equally well:

```javascript
const onClick = function (event) { console.log(event.type); };
button.addEventListener("click", onClick);
button.removeEventListener("click", onClick);
```

An arrow function is removable if its reference is preserved:

```javascript
const onClick = (event) => console.log(event.type);
button.addEventListener("click", onClick);
button.removeEventListener("click", onClick);
```

Arrow syntax: `(event)` declares a parameter, `=>` separates parameters from the body, and the expression after the arrow is evaluated when invoked.

## 9. Anonymous functions and arrow-function traps

**Incorrect:**

```javascript
button.addEventListener("click", function () { console.log("Hi"); });
button.removeEventListener("click", function () { console.log("Hi"); });
```

Each expression creates a new function object. The removal callback does not match the registered one.

The same problem occurs with inline arrows:

```javascript
button.addEventListener("click", () => console.log("Hi"));
button.removeEventListener("click", () => console.log("Hi"));
```

**Correct:**

```javascript
const listener = () => console.log("Hi");
button.addEventListener("click", listener);
button.removeEventListener("click", listener);
```

**Rule:** Anonymous is not inherently unremovable; *losing the reference* makes later removal difficult.

## 10. Wrappers, closures, and callback arguments

A callback that needs additional arguments can use a wrapper, but keep the wrapper reference.

```javascript
function greet(name) { console.log("Hello, " + name); }
const onClick = () => greet("Alice");
button.addEventListener("click", onClick);
button.removeEventListener("click", onClick);
```

`+` concatenates strings when an operand is a string. The arrow function executes `greet("Alice")` **later**, when the event occurs.

A closure retains values from the scope in which it was created:

```javascript
function makeHandler(name) {
  return function () { console.log("Hello, " + name); };
}
const aliceHandler = makeHandler("Alice");
button.addEventListener("click", aliceHandler);
button.removeEventListener("click", aliceHandler);
```

Do not call `makeHandler("Alice")` a second time for removal: it creates a different function.

## 11. The capture flag and exact matching

`capture` defaults to `false` for both registration and removal. Boolean and dictionary forms are equivalent:

```javascript
button.addEventListener("click", handler, true);
button.removeEventListener("click", handler, { capture: true });
```

Two registrations can coexist if their capture flags differ:

```javascript
button.addEventListener("click", handler, true);
button.addEventListener("click", handler, false);
button.removeEventListener("click", handler, true); // only capture=true removed
button.removeEventListener("click", handler);       // removes capture=false
```

| Registered capture | Removal capture | Match? |
|---|---|---|
| `false` | omitted | Yes |
| `false` | `false` | Yes |
| `false` | `true` | No |
| `true` | `true` | Yes |
| `true` | omitted | No |

On a target element, both capture and non-capture listeners may execute at `Event.AT_TARGET` (phase 2). The capture flag still matters for removal.

## 12. Complete removal options inventory

The standard removal options dictionary is **`EventListenerOptions`**, whose relevant member is `capture`.

| Option | Accepted on registration | Used to match removal? |
|---|---|---|
| `capture` | Yes | **Yes** |
| `once` | Yes | No |
| `passive` | Yes | No |
| `signal` | Yes | No |

`once`, `passive`, and `signal` belong to the registration options, not the removal matching algorithm. Extra dictionary properties are ignored for removal matching.

```javascript
button.addEventListener("click", handler, {
  capture: true, once: true, passive: true
});
button.removeEventListener("click", handler, { capture: true });
```

This works even though `once` and `passive` are omitted in the removal call. A supplied `signal` on a removal options object does **not** select a registration.

## 13. Return value, no-op behavior, and observability and related cases

`removeEventListener()` always returns `undefined` after a normal call.

```javascript
const result = button.removeEventListener("click", handler);
console.log(result); // undefined
```

It does not report whether a registration existed. This is incorrect:

```javascript
if (button.removeEventListener("click", handler)) {
  console.log("Removed!"); // never runs based on the return value
}
```

Calling removal twice is safe; the second call is a no-op. A standard `EventTarget` has no `getEventListeners()`, `removeAllEventListeners()`, listener-count API, or subscription ID. Track state yourself if needed, or use a shared abort signal for groups of listeners.

### Complete errors and edge-case catalog

| Situation | Behavior / correction |
|---|---|
| Target is `null` | Calling method throws `TypeError`; check element exists |
| Target lacks method | Throws `TypeError`; use an `EventTarget` |
| Callback is `null` | No matching listener; no-op |
| Callback is an invalid primitive | Web IDL conversion can throw `TypeError` |
| Callback not registered | Silent no-op |
| Called twice | Second call is no-op |
| Wrong case in type | Does not match |
| Wrong target | Does not match |
| Wrong callback object | Does not match |
| Wrong capture | Does not match |
| `once` differs | Does not matter to removal |
| `passive` differs | Does not matter to removal |
| `signal` differs | Does not matter to removal |
| Callback currently running | Current invocation continues |
| Listener already invoked and auto-removed | Removal is no-op |
| Function returns value | Does not influence removal |
| Listener throws | Generally remains registered unless separately removed/`once` |
| Event target removed from DOM | Does not itself call `removeEventListener()` |

**Defensive code:**

```javascript
const button = document.getElementById("myButton");
if (button !== null) {
  button.removeEventListener("click", handler);
}
```

The standard API provides no general listener enumeration or removal-all method.

## 14. Removing a listener from inside itself

```javascript
function onClick() {
  console.log("Once, by manual cleanup");
  button.removeEventListener("click", onClick);
}
button.addEventListener("click", onClick);
```

**Trace:**

| Step | Registration | Output |
|---|---|---|
| Register callback | Present | None |
| First click invokes callback | Present initially | `Once, by manual cleanup` |
| Callback removes itself | Removed | None |
| Second click | Absent | None |

Removing the registration does not terminate code that is already running. The current callback continues to its next statement.

```javascript
function onClick() {
  button.removeEventListener("click", onClick);
  console.log("Still runs after removal");
}
```

That message prints during the first invocation.

## 15. Removing another listener during dispatch

```javascript
const target = new EventTarget();
function second() { console.log("Second"); }
function first() {
  console.log("First");
  target.removeEventListener("hello", second);
}
target.addEventListener("hello", first);
target.addEventListener("hello", second);
target.dispatchEvent(new Event("hello"));
```

Output:

```text
First
```

The second registration is marked removed before it is reached, so it is skipped. If `second` were registered first, it would execute before `first` removed it; removal cannot undo a callback that already ran.

**Subtlety:** The event dispatch algorithm may work with a snapshot of listeners for a target, but it checks removed flags. A listener removed before its turn is not invoked.

## 16. Removal during capture, target, and bubble phases

```html
<div id="parent"><button id="child" type="button">Click</button></div>
```

```javascript
const parent = document.getElementById("parent");
const child = document.getElementById("child");
function onParentBubble() { console.log("Parent bubble"); }
parent.addEventListener("click", onParentBubble);
child.addEventListener("click", function () {
  console.log("Child");
  parent.removeEventListener("click", onParentBubble);
});
```

Clicking the child logs only `Child`: the parent bubble listener was removed before the event reached the parent in bubbling.

**Important:** This does not stop propagation itself. Other listeners on the parent can still run. `event.stopPropagation()` and `event.stopImmediatePropagation()` control propagation; `removeEventListener()` controls registration.

The relevant phases are `Event.CAPTURING_PHASE` (1), `Event.AT_TARGET` (2), and `Event.BUBBLING_PHASE` (3).

## 17. Listener order and remove-then-readd and related cases

For listeners on the same target in the same applicable phase, registration order generally determines invocation order.

```javascript
function a() { console.log("A"); }
function b() { console.log("B"); }
function c() { console.log("C"); }
button.addEventListener("click", a);
button.addEventListener("click", b);
button.addEventListener("click", c);
// First click: A B C
button.removeEventListener("click", b);
// Next click: A C
button.removeEventListener("click", a);
button.addEventListener("click", a);
// Next click: C A
```

Re-adding creates a new registration at the end of the remaining registrations for that target. Duplicate registration with identical type/callback/capture does **not** change the existing listener's order or options.

### Execution traces and debugging workflow

**Trace A: wrong capture**

```javascript
button.addEventListener("click", handler, true);
button.removeEventListener("click", handler); // defaults false
```

| Step | Stored capture | Requested capture | Result |
|---|---:|---:|---|
| Register | `true` | N/A | Present |
| Remove | `true` | `false` | No match |
| Click | `true` | N/A | Callback still runs |

**Trace B: correct cleanup**

```javascript
button.removeEventListener("click", handler, true);
```

| Step | Stored capture | Requested capture | Result |
|---|---:|---:|---|
| Remove | `true` | `true` | Registration removed |
| Click | N/A | N/A | Callback absent |

**Debug checklist:** Confirm DOM selection, event type spelling/case, target object, callback identity, capture value, registration order, whether removal actually ran, and whether another independent listener produces similar output. Browser DevTools may expose listener inspection utilities; they are not portable standard JavaScript APIs.

## 18. Comparison with once: true

```javascript
button.addEventListener("click", handler, { once: true });
```

The browser removes this listener **before invoking** it on its first matching event. Compare manual self-removal:

```javascript
function handler() {
  button.removeEventListener("click", handler);
}
button.addEventListener("click", handler);
```

Manual removal happens when the callback reaches that line. If the callback dispatches a nested event **before** the removal statement, it may be invoked again. `{ once: true }` avoids this re-entrancy difference.

You may remove a `once` listener manually before it fires. Removing it after it has already fired is a harmless no-op.

## 19. Passive listeners and removal

The `passive` option affects whether a listener may cancel the event's default action; it does **not** affect removal matching.

```javascript
function onWheel(event) { console.log(event.deltaY); }
window.addEventListener("wheel", onWheel, { passive: true });
window.removeEventListener("wheel", onWheel);
```

No need to repeat `passive: true`. For certain touch/wheel events on particular high-level targets, browsers may choose passive defaults; those defaults still do not affect removal matching. A passive listener cannot cancel a default action through `preventDefault()` even if the event is cancelable.

## 20. AbortController and AbortSignal cleanup

A registration can be tied to an `AbortSignal`:

```javascript
let controller = new AbortController();
button.addEventListener("click", onClick, { signal: controller.signal });
document.addEventListener("keydown", onKeyDown, { signal: controller.signal });
controller.abort(); // removes both registrations
```

| Member | Meaning |
|---|---|
| `new AbortController()` | Create controller |
| `controller.signal` | Signal used during registration |
| `controller.abort(reason)` | Abort signal; removes associated listeners |
| `signal.aborted` | Boolean aborted state |
| `signal.reason` | Reason for abortion |
| `signal.throwIfAborted()` | Throws when aborted |
| `signal.addEventListener("abort", fn)` | Observe abort event |
| `AbortSignal.abort(reason)` | Already-aborted signal |
| `AbortSignal.timeout(ms)` | Signal that aborts after a timeout |
| `AbortSignal.any(signals)` | Signal that aborts when one input aborts |

An aborted controller cannot be reset. Create a new controller for a new lifecycle. Registering with an already-aborted signal does not add a listener. `AbortController` is explored more deeply in Lesson 16.48.

## 21. Listener objects and handleEvent()

A listener may be an object with a callable `handleEvent` method:

```javascript
const listener = {
  handleEvent(event) { console.log(event.type); }
};
button.addEventListener("click", listener);
button.removeEventListener("click", listener);
```

Removal matches the **listener object's identity**, not the identity of its `handleEvent` method. A different object with identical source code will not match.

```javascript
const other = { handleEvent(event) { console.log(event.type); } };
console.log(listener === other); // false
```

The original object remains the same even if you replace its `handleEvent` property. This lesson uses object literals without introducing classes or inheritance.

## 22. bind(), factory functions, and identity pitfalls

`Function.prototype.bind()` returns a **new** function each time.

```javascript
function greet() { console.log("Hello"); }
const a = greet.bind(null);
const b = greet.bind(null);
console.log(a === b); // false
```

**Wrong:**

```javascript
button.addEventListener("click", greet.bind(null));
button.removeEventListener("click", greet.bind(null));
```

**Right:**

```javascript
const bound = greet.bind(null);
button.addEventListener("click", bound);
button.removeEventListener("click", bound);
```

Likewise, calling a function factory twice creates two distinct callbacks:

```javascript
function makeHandler(label) { return () => console.log(label); }
const saved = makeHandler("Hello");
button.addEventListener("click", saved);
button.removeEventListener("click", saved);
```

Store and reuse the **returned** callback reference.

## 23. Property handlers, inline HTML, and removal

Three mechanisms must be distinguished:

```javascript
button.onclick = handler;                    // event-handler property
button.addEventListener("click", handler); // listener registration
```

```html
<button onclick="handleClick()">Inline attribute handler</button>
```

| Registration style | Correct cleanup |
|---|---|
| `button.onclick = handler` | `button.onclick = null` |
| `button.addEventListener("click", handler)` | `button.removeEventListener("click", handler)` |
| HTML `onclick="..."` attribute | `button.removeAttribute("onclick")` |

`removeEventListener()` does not clear `onclick`, and setting `onclick = null` does not remove a listener registered with `addEventListener()`. Inline attributes are generally discouraged for maintainability and Content Security Policy compatibility.

## 24. Event cancellation versus listener removal

| API | Effect | Removes registration? |
|---|---|---|
| `removeEventListener()` | Remove matching callback registration | Yes |
| `event.preventDefault()` | Request cancellation of default action | No |
| `event.stopPropagation()` | Stop further propagation to later targets | No |
| `event.stopImmediatePropagation()` | Stop later same-target listeners and propagation | No |

```javascript
function handler(event) {
  event.preventDefault(); // may cancel link navigation
  // handler is still registered for the next click
}
```

The standard `Event` methods relevant here include `preventDefault()`, `stopPropagation()`, `stopImmediatePropagation()`, and `composedPath()`. `Event` properties such as `type`, `target`, `currentTarget`, `eventPhase`, `bubbles`, `cancelable`, `defaultPrevented`, `composed`, `isTrusted`, and `timeStamp` describe the event, not listener-registration state.

## 25. DOM removal, garbage collection, and memory

```javascript
const button = document.getElementById("myButton");
button.addEventListener("click", handler);
button.remove(); // removes element from DOM, not its registration
```

The variable still references the element. Its listener can still exist and be invoked by a programmatic dispatch. If the element and associated references later become unreachable, garbage collection may reclaim them; manually removing every listener from every short-lived element is not always necessary.

**Higher-risk pattern:** a temporary UI attaches listeners to long-lived targets such as `document` or `window`, then disappears without cleanup. Those registrations may retain references and continue handling events.

```javascript
function mount() { document.addEventListener("keydown", handler); }
function unmount() { document.removeEventListener("keydown", handler); }
```

A persistent page-level listener may intentionally live for the entire page. Cleanup should reflect intended lifecycle, not a blanket rule that every listener must be removed.

## 27. Project 1: line-by-line concepts and trace

**DOM selection:** `document.getElementById("targetButton")` retrieves an element by ID; each `const` stores a stable reference.

**State:** `let listenerEnabled = false` starts disabled. `let` allows reassignment. `handledClicks` and `ignoredClicks` are numbers incremented with `count = count + 1`.

**UI rendering:** `textContent` updates text safely. `listenerEnabled ? "Enabled" : "Disabled"` is a conditional expression: choose the left result if the condition is truthy, otherwise the right. `!listenerEnabled` negates the boolean.

**Stable callback:** `handleTargetClick` is defined once and passed by reference to both registration and removal.

**Early return:** `if (listenerEnabled) return;` prevents repeating an enable operation. `return;` exits the function without a value.

**Permanent observer:** `trackIgnoredClick` stays registered to count target clicks while the managed callback is disabled. This is intentional; disabling the managed listener does not disable every click listener.

**Log:** `document.createElement("li")` makes a list item, `appendChild` inserts it, and `replaceChildren()` removes previous children.

| Page loads | No | 0 | 0 |
| Click Enable | Yes | 0 | 0 |
| Click target | Yes | 1 | 0 |
| Click target | Yes | 2 | 0 |
| Click Disable | No | 2 | 0 |
| Click target | No | 2 | 1 |
| Click Reset | No | 0 | 0 |

const disableButton = document.getElementById("disableButton");

const shortcutStatus = document.getElementById("shortcutStatus");

  const item = document.createElement("li");
  item.textContent = message;
  shortcutLog.appendChild(item);
  lastShortcut.textContent = message;

  disableButton.disabled = !shortcutsEnabled;

  searchInput.value = "";
  addShortcutLog("Search cleared");

function handleShortcut(event) {
  if (event.isComposing) return;
  const key = event.key.toLowerCase();
  const commandPressed = event.ctrlKey || event.metaKey;

  if (commandPressed && key === "k") {
    if (event.cancelable) event.preventDefault();
    searchInput.focus();
    addShortcutLog("Search focused");
    return;
  }

  if (event.key === "Escape" && document.activeElement === searchInput) {
    searchInput.value = "";
    addShortcutLog("Escape cleared search");
  }
}

  document.addEventListener("keydown", handleShortcut);
  shortcutsEnabled = true;
  addShortcutLog("Shortcuts enabled");
  updateShortcutStatus();
}

function disableShortcuts() {

  document.removeEventListener("keydown", handleShortcut);
  shortcutsEnabled = false;
  addShortcutLog("Shortcuts disabled");
  updateShortcutStatus();
}

## 29. Project 2: complete breakdown and trace

**`keydown`:** fires when a key is pressed. We attach it to `document`, which is long-lived, so explicit cleanup matters.

**`event.key`:** gives the logical key value. `.toLowerCase()` normalizes `"K"` to `"k"` for this shortcut.

**`event.ctrlKey || event.metaKey`:** logical OR returns `true` if Control or Meta/Command is pressed. `||` short-circuits: if the left operand is truthy, the right need not be evaluated.

**`commandPressed && key === "k"`:** logical AND requires both conditions. `===` is strict equality; `"k"` must match exactly.

**`event.isComposing`:** indicates an input-method composition session. We skip shortcuts while composition is active to avoid interfering with text entry.

**`event.cancelable`:** checks whether the default action can be canceled before calling `preventDefault()`. Some system/browser shortcuts are reserved despite cancellation requests.

**`searchInput.focus()`:** requests keyboard focus. **`document.activeElement === searchInput`** checks whether the search input is focused before Escape clears it.

**Stable reference:** `handleShortcut` is the same function in both `addEventListener()` and `removeEventListener()`.

**Trace: Ctrl + K after enabling**

| Step | Expression or action | Result |
|---|---|---|
| 1 | Click Enable | `enableShortcuts()` runs |
| 2 | Register `keydown` | Active on `document` |
| 3 | Press Ctrl + K | Keyboard event dispatched |
| 4 | `event.isComposing` | Usually `false` |
| 5 | `event.key.toLowerCase()` | `"k"` |
| 6 | `event.ctrlKey || event.metaKey` | `true` |
| 7 | Combined condition | `true` |
| 8 | `preventDefault()` | Requests cancellation |
| 9 | `searchInput.focus()` | Focuses input |
| 10 | `addShortcutLog()` | Logs focus action |
| 11 | Click Disable | Removes `keydown` listener |
| 12 | Press Ctrl + K again | App handler no longer runs |

**Accessibility notes:** Provide a visible alternative; do not trap focus or intercept ordinary typing; respect browser, OS, and assistive-technology shortcuts. A production app should test keyboard layouts, composition, shortcut conflicts, and platform behavior.

## 30. Ten interview questions with detailed answers

### Question 1. What is removeEventListener() and where is it defined?

**Answer:** It is an EventTarget method that removes a matching listener registration from a target. It does not delete the function or element.

**Follow-up:** Explain or demonstrate this behavior with a short browser-console example.

### Question 2. What are its signatures, parameters, and return value?

**Answer:** removeEventListener(type, callback[, optionsOrCapture]). The event type is a string, callback is a function/listener object or null, and the optional third argument sets capture. It returns undefined.

**Follow-up:** Explain or demonstrate this behavior with a short browser-console example.

### Question 3. What must match for successful removal?

**Answer:** The same EventTarget, the same case-sensitive type string, the same callback object identity, and the same capture boolean.

**Follow-up:** Explain or demonstrate this behavior with a short browser-console example.

### Question 4. Why can two identical anonymous functions fail to match?

**Answer:** Each function expression creates a distinct function object. The algorithm compares identity, not source code.

**Follow-up:** Explain or demonstrate this behavior with a short browser-console example.

### Question 5. How do capture: true and capture: false affect removal?

**Answer:** They identify separate registrations. Removing one does not remove the other; omitted capture means false.

**Follow-up:** Explain or demonstrate this behavior with a short browser-console example.

### Question 6. Do once, passive, and signal affect removal matching?

**Answer:** No. Only capture among the options affects matching. once/passive/signal can affect registration or lifecycle but are not matching criteria.

**Follow-up:** Explain or demonstrate this behavior with a short browser-console example.

### Question 7. What happens when you remove a listener during its own callback?

**Answer:** The current callback continues executing. Later dispatches do not invoke that removed registration.

**Follow-up:** Explain or demonstrate this behavior with a short browser-console example.

### Question 8. Can removing a listener during dispatch prevent another listener from running?

**Answer:** Yes, if that registration has not yet been invoked and it is removed before its turn. It cannot undo an invocation that already happened.

**Follow-up:** Explain or demonstrate this behavior with a short browser-console example.

### Question 9. How does AbortController compare with manual removal?

**Answer:** Manual removal identifies each listener by type/callback/capture on a target. A shared AbortSignal allows one abort() call to remove multiple associated registrations.

**Follow-up:** Explain or demonstrate this behavior with a short browser-console example.

### Question 10. What is the difference between onclick = null and removeEventListener()?

**Answer:** onclick = null clears the event-handler property. removeEventListener() removes a matching addEventListener registration. They do not substitute for each other.

**Follow-up:** Explain or demonstrate this behavior with a short browser-console example.

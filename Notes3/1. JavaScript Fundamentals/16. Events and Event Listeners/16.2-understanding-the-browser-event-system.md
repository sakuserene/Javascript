## 1. Learning objectives

By the end, you should explain browser event processing, browser versus JavaScript engine, EventTarget, registration versus dispatch, event objects, target versus currentTarget, the call stack, synchronous execution, tasks, microtasks, propagation, synthetic events, and default actions. You should be able to predict execution order and build event-driven applications.

## 2. What is the browser event system?

The browser event system connects occurrences such as clicks, typing, resource loads, and browser state changes to JavaScript callbacks. A simplified user-input sequence is:

```text
User interaction
  |
  v
Browser processes input and identifies a target
  |
  v
Browser dispatches an event
  |
  v
Applicable registered listeners execute
  |
  v
Application updates; browser may perform default action
```

The sequence is conceptual, not an exact browser implementation. Not every input causes every event, and default-action timing depends on the event. JavaScript does not need a polling loop to detect clicks.

---

## 3. Browser versus JavaScript engine

The **browser** parses HTML, constructs the DOM, renders the page, handles user input, and exposes web APIs. The **JavaScript engine** executes JavaScript language constructs. Browser APIs such as `document` are not part of ECMAScript itself.

```javascript
const age = 25; // JavaScript language feature
const button = document.getElementById("myButton"); // Browser DOM API
```

| Component | Responsibility |
| --- | --- |
| Browser | DOM, rendering, user input, browser APIs, scheduling |
| JavaScript engine | Execute JavaScript, manage function calls and language behavior |
| Event loop | Coordinate tasks, microtask checkpoints, and rendering opportunities |

Browser architecture can include multiple processes and threads; this is a learning model.

## 4. Understanding EventTarget

`EventTarget` is the interface for objects that can receive events and register listeners. Examples: `window`, `document`, DOM elements, and `new EventTarget()`.

| Method | Purpose |
| --- | --- |
| `addEventListener(type, callback)` | Register a listener |
| `removeEventListener(type, callback)` | Remove a matching listener |
| `dispatchEvent(event)` | Dispatch an event synchronously |

```javascript
const target = new EventTarget();
target.addEventListener("hello", function () {
  console.log("Hello event received");
});
target.dispatchEvent(new Event("hello"));
// Hello event received
```

**Token breakdown:** `const` declares a binding; `target` names it; `=` assigns; `new` constructs an object; `EventTarget()` creates an event-capable object; `.` accesses a method; `"hello"` is the event-type string; `function () {}` creates a callback; `new Event("hello")` constructs an event; `dispatchEvent(...)` sends it to the target.

A plain object (`const person = { name: "Alice" };`) does not automatically implement `EventTarget`. Calling `person.addEventListener(...)` throws a TypeError.

## 5. Listener registration: detailed syntax

```html
<button id="myButton" type="button">Click Me</button>
<script src="script.js" defer></script>
```

```javascript
const button = document.getElementById("myButton");
button.addEventListener("click", function () {
  console.log("Button clicked");
});
```

| Token | Explanation |
| --- | --- |
| `button` | Reference to DOM element |
| `.` | Access method on the object |
| `addEventListener` | Register an event listener |
| `(` and `)` | Surround arguments |
| `"click"` | First argument: event type |
| `,` | Separate first and second arguments |
| `function` | Define a function expression |
| `()` | Empty parameter list |
| `{` and `}` | Function body boundaries |
| `console.log(...)` | Print when callback is invoked |
| `;` | End statement |

**Execution trace:** (1) look up button; (2) create callback function object; (3) call `addEventListener` with type and callback; (4) browser retains registration; (5) method returns `undefined`; (6) next statement executes. The callback body does **not** run at registration time.

Conceptual listener registry:

```text
button#myButton
|-- click -> callback A (capture: false)
`-- mouseenter -> callback B (capture: false)
```

This is an explanatory diagram, not a browser-exposed data structure.

## 6. Event dispatch lifecycle

Event dispatch delivers an event to applicable listeners on an event target and, for DOM events, potentially along a propagation path. A simplified lifecycle:

1. An occurrence or script initiates dispatch.
2. The event object and target are established.
3. The propagation path is determined.
4. Applicable listeners are invoked in phase/order.
5. Relevant default behavior may occur if not canceled.

**Registration** stores listener information; **dispatch** invokes listeners. A browser-generated user event may involve task scheduling; `dispatchEvent()` is synchronous.

## 7. Event object: properties and parameter breakdown

```javascript
button.addEventListener("click", function (event) {
  console.log(event.type);
  console.log(event.target);
  console.log(event.currentTarget);
  console.log(event.isTrusted);
});
```

`event` is a **parameter name**, not a reserved word. The browser passes the event object as the callback argument. You may name it `e` instead. `event.type` uses `.` to access the `type` property.

| Property | Meaning |
| --- | --- |
| `type` | Event type, e.g. `click` |
| `target` | Original event target |
| `currentTarget` | Object whose listener is executing |
| `timeStamp` | Event timestamp |
| `bubbles` | Whether the event bubbles |
| `cancelable` | Whether default action can be canceled |
| `defaultPrevented` | Whether cancellation occurred |
| `isTrusted` | Whether event was generated by user agent |

`isTrusted` is not proof of a human identity or intent.

## 8. event.target versus event.currentTarget

```html
<div id="container"><button id="myButton">Click Me</button></div>
```

```javascript
const container = document.getElementById("container");
container.addEventListener("click", function (event) {
  console.log(event.target);        // button when button clicked
  console.log(event.currentTarget); // container during this listener
});
```

```text
DIV#container    <-- currentTarget (listener registered here)
`-- BUTTON      <-- target (original click target)
```

The event bubbles from the button to the container. `target` and `currentTarget` are equal only in some circumstances.

## 9. The JavaScript call stack

The call stack tracks currently active function calls. Each function invocation pushes an execution context; returning removes it.

```javascript
function first() { second(); }
function second() { third(); }
function third() { console.log("Hello"); }
first();
```

```text
Top of stack while logging:
|-- third()   <-- active
|-- second()
|-- first()
`-- script
```

Trace: script calls `first`, `first` calls `second`, `second` calls `third`, `third` logs `Hello`, then returns; `second` returns; `first` returns. An event listener is **not** permanently on the stack while waiting.

---

## 10. Event handlers and the call stack

```javascript
console.log("A");
button.addEventListener("click", function () {
  console.log("B");
});
console.log("C");
```

Before any click: `A`, `C`. After a click: `B`. Registering the listener does not push an executing callback context. When dispatch invokes it, it runs on the call stack, then returns.

---

## 11. Synchronous execution

```javascript
console.log("One");
console.log("Two");
console.log("Three");
```

Output is `One`, `Two`, `Three`. The statements execute in order. Listener **registration** is synchronous, while an ordinary user-generated event is handled when dispatched later. Do not confuse a callback's future execution with registration being asynchronous.

---

## 12. The event loop: a conceptual model

The event loop coordinates tasks, microtask checkpoints, and opportunities for browser rendering.

```text
Browser APIs / user input / timers
               |
               v
          Task queues
               |
               v
         Event loop ----> JavaScript call stack
               |
               v
        Microtask checkpoint
               |
               v
       Rendering opportunity
```

This is simplified. HTML specifies task sources and multiple task queues; microtasks are processed at checkpoints. Not every event dispatch queues a task.

---

## 13. Task queues and setTimeout

```javascript
console.log("A");
setTimeout(function () {
  console.log("B");
}, 0);
console.log("C");
```

Output:

```text
A
C
B
```

`setTimeout` is a browser timer API; `function () { ... }` is the callback; the comma separates arguments; `0` is the requested delay in milliseconds, **not** a guarantee of immediate execution. Trace: log A, schedule timer, log C, script finishes, eligible timer task runs and logs B.

---

## 14. Microtasks and Promise reactions

```javascript
console.log("A");
Promise.resolve().then(function () {
  console.log("B");
});
console.log("C");
```

Output is A, C, B. `Promise.resolve()` produces a fulfilled promise; `.then(callback)` registers a reaction; that reaction runs as a microtask after current synchronous execution. Microtasks are processed at microtask checkpoints, generally before the next task. Microtasks scheduled during a checkpoint are also processed before that checkpoint completes; unbounded scheduling can starve other work.

---

## 15. Execution order: synchronous, microtask, timer

```javascript
console.log("1");
setTimeout(function () { console.log("2"); }, 0);
Promise.resolve().then(function () { console.log("3"); });
console.log("4");
```

Output:

```text
1
4
3
2
```

| Step | Operation | Output so far |
| --- | --- | --- |
| 1 | Run first log | 1 |
| 2 | Schedule timer | 1 |
| 3 | Queue Promise microtask | 1 |
| 4 | Run last log | 1, 4 |
| 5 | Run microtask checkpoint | 1, 4, 3 |
| 6 | Run timer task | 1, 4, 3, 2 |

**Why not `1, 2, 3, 4`?** `setTimeout` schedules a callback rather than calling it inline. The Promise reaction also runs later, but at a microtask checkpoint before the timer task.

## 16. dispatchEvent() is synchronous

```javascript
const button = document.getElementById("myButton");
button.addEventListener("click", function () {
  console.log("Listener executed");
});
console.log("Before dispatch");
button.dispatchEvent(new Event("click"));
console.log("After dispatch");
```

Output:

```text
Before dispatch
Listener executed
After dispatch
```

**Breakdown:** `new` constructs an object; `Event` is the constructor; `"click"` sets the type; `button.dispatchEvent(...)` invokes applicable listeners synchronously. A synthetic event is not necessarily equivalent to genuine user input. `new Event("click")` defaults to `bubbles: false` and `cancelable: false`. You can configure them with `new Event("click", { bubbles: true, cancelable: true })`.

`dispatchEvent()` returns `false` if a cancelable event's default was prevented; otherwise it returns `true`. Exceptions thrown by listeners are reported as uncaught exceptions and do not propagate through the `dispatchEvent()` caller in the usual way.

---

## 17. Trusted and synthetic events

```javascript
button.addEventListener("click", function (event) {
  console.log(event.isTrusted);
});
button.dispatchEvent(new Event("click")); // listener logs false
```

`isTrusted` is false for events dispatched via `dispatchEvent()`. Genuine browser-generated input events are generally trusted, but this property is not an identity check. Browser capabilities requiring transient user activation cannot be unlocked simply by dispatching synthetic events.

## 18. Introduction to event propagation

Events can travel through the DOM hierarchy in **capturing**, **target**, and (if bubbling is enabled) **bubbling** phases.

```html
<div id="outer">
  <div id="inner">
    <button id="button">Click</button>
  </div>
</div>
```

```javascript
const outer = document.getElementById("outer");
const inner = document.getElementById("inner");
const button = document.getElementById("button");
outer.addEventListener("click", function () { console.log("Outer"); });
inner.addEventListener("click", function () { console.log("Inner"); });
button.addEventListener("click", function () { console.log("Button"); });
```

Clicking the button prints `Button`, `Inner`, `Outer` with these default non-capturing listeners.

```text
Capturing: ancestors --> target
Target:    button
Bubbling:  target --> ancestors
```

We will cover phases, stopping propagation, and delegation in dedicated lessons.

## 19. Default browser actions

Some events are associated with browser default behavior: link navigation, form submission, checkbox toggling, and certain key interactions. When an event is cancelable, `event.preventDefault()` requests cancellation.

```javascript
const link = document.getElementById("myLink");
link.addEventListener("click", function (event) {
  event.preventDefault();
  console.log("Navigation prevented");
});
```

`preventDefault()` **does not** stop event propagation. `stopPropagation()` and `stopImmediatePropagation()` are separate methods. Passive listeners cannot cancel default actions through `preventDefault()`.

## 20. Practical project 1: Browser event logger

Build three files in one directory and open `index.html`.

**index.html**

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Browser Event Logger</title>
  <link rel="stylesheet" href="styles.css">
  <script src="script.js" defer></script>
</head>
<body>
  <h1>Browser Event Logger</h1>
  <button id="actionButton" type="button">Click Me</button>
  <label for="textInput">Type something</label>
  <input id="textInput" type="text">
  <button id="clearButton" type="button">Clear Log</button>
  <h2>Event Log</h2>
  <ul id="eventLog" aria-live="polite"></ul>
</body>
</html>
```

**styles.css**

```css
body { font-family: Arial, sans-serif; padding: 24px; }
button, input { padding: 10px; margin: 8px 0; }
#eventLog { padding: 16px; border: 1px solid #ccc; min-height: 100px; }
#eventLog li { margin-bottom: 8px; }
```

**script.js**

```javascript
const actionButton = document.getElementById("actionButton");
const textInput = document.getElementById("textInput");
const clearButton = document.getElementById("clearButton");
const eventLog = document.getElementById("eventLog");

function logEvent(message) {
  const item = document.createElement("li");
  item.textContent = message;
  eventLog.appendChild(item);
}

actionButton.addEventListener("click", function (event) {
  logEvent("Event: " + event.type);
});

textInput.addEventListener("input", function (event) {
  logEvent("Input value: " + event.target.value);
});

clearButton.addEventListener("click", function () {
  eventLog.replaceChildren();
});
```

**Step-by-step walkthrough:**

1. `document.getElementById` obtains references to the controls.
2. `function logEvent(message)` declares a reusable function with parameter `message`.
3. `document.createElement("li")` creates a new DOM element.
4. `item.textContent = message` safely sets its text.
5. `appendChild(item)` inserts it into the list.
6. The click listener passes `"Event: " + event.type` to `logEvent`. `+` concatenates strings; if the type is `click`, the result is `Event: click`.
7. The input listener reads `event.target.value`, the current input value.
8. The clear listener calls `replaceChildren()` with no arguments, removing all log entries.
9. `defer` ensures the external classic script runs after HTML parsing, so element lookup succeeds.

**Trace:** Click the action button -> browser dispatches click -> listener receives event -> `logEvent` creates li -> text assigned -> li appended -> event log changes.

## 21. Practical project 2: Event propagation explorer

Create these two files and open `index.html`.

**index.html**

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Event Propagation Explorer</title>
  <script src="script.js" defer></script>
</head>
<body>
  <div id="outer" style="padding:30px;background:lightblue">
    Outer
    <div id="inner" style="padding:30px;background:lightgreen">
      Inner
      <button id="button" type="button">Click Me</button>
    </div>
  </div>
  <pre id="output"></pre>
</body>
</html>
```

**script.js**

```javascript
const outer = document.getElementById("outer");
const inner = document.getElementById("inner");
const button = document.getElementById("button");
const output = document.getElementById("output");

function log(message) {
  output.textContent += message + "\n";
}

outer.addEventListener("click", function () { log("Outer listener"); });
inner.addEventListener("click", function () { log("Inner listener"); });
button.addEventListener("click", function () { log("Button listener"); });
```

Clicking the button displays:

```text
Button listener
Inner listener
Outer listener
```

**Understanding `+=`:** `output.textContent += message + "\n"` is equivalent to `output.textContent = output.textContent + message + "\n"`. `+` concatenates strings. `"\n"` is a newline character. The `<pre>` element preserves line breaks. Each listener calls `log`; the click bubbles upward from button to inner to outer.

**Try it:** Click the inner background (not the button) and predict the output: `Inner listener`, then `Outer listener`. Click the outer background: only `Outer listener`.

## 22. Common beginner mistakes

| Mistake | Why it fails | Better approach |
| --- | --- | --- |
| JavaScript constantly polls for clicks | Browser manages input and dispatch | Register event listeners |
| Listener runs at registration | Callback is stored, not invoked | Distinguish registration and dispatch |
| Browser and JS engine are identical | Browser exposes APIs; engine executes code | Understand separate responsibilities |
| Every object has addEventListener | Plain objects do not implement EventTarget | Use EventTarget or DOM object |
| Every event callback is queued | dispatchEvent invokes synchronously | Distinguish dispatch mechanisms |
| setTimeout(0) means immediate | Timer executes in a later task | Account for event loop |
| Promise callback runs inline | Promise reactions are microtasks | Finish current synchronous code first |
| target always equals currentTarget | Propagation can change currentTarget | Inspect listener registration location |
| preventDefault stops bubbling | Default action and propagation differ | Use correct method |
| isTrusted proves a human clicked | It only indicates user-agent generation | Do not treat as authentication |
| Script executes before elements exist | DOM lookup returns null | Use defer or suitable load timing |
| new Event always bubbles | bubbles defaults to false | Supply `{ bubbles: true }` when needed |

## 23. Ten interview questions with detailed answers

### Interview 1. What is the browser event system?

**Answer:** The browser infrastructure and APIs that create, dispatch, and handle events, connecting occurrences such as user interactions to JavaScript callbacks.

### Interview 2. What is EventTarget?

**Answer:** An interface implemented by event-capable objects, providing addEventListener(), removeEventListener(), and dispatchEvent().

### Interview 3. What happens when addEventListener() is called?

**Answer:** A callback is registered for a given event type. The callback is not executed simply because it was registered.

### Interview 4. What is event dispatch?

**Answer:** The process of delivering an event along its applicable propagation path and invoking matching listeners.

### Interview 5. What is the JavaScript call stack?

**Answer:** A mechanism that tracks active function execution contexts; calls push contexts and returns remove them.

### Interview 6. What is the event loop?

**Answer:** The mechanism that coordinates task execution, microtask checkpoints, and rendering opportunities.

### Interview 7. How do tasks differ from microtasks?

**Answer:** Tasks include timer callbacks and browser-scheduled work. Promise reactions are microtasks processed at microtask checkpoints before the next task.

### Interview 8. Is dispatchEvent() synchronous?

**Answer:** Yes. It invokes applicable listeners during the dispatchEvent() call, before the next statement.

### Interview 9. How do event.target and event.currentTarget differ?

**Answer:** target is the event target; currentTarget is the object whose listener is currently running.

### Interview 10. What is event propagation?

**Answer:** Movement of an event through capturing, target, and potentially bubbling phases along a DOM propagation path.

**Task:** Schedule a timer printing 2, Promise printing 3, and synchronous 1 and 4.

**Step-by-step explanation:** Output Before, Listener, After. dispatchEvent is synchronous.

**Step-by-step explanation:** When the child is clicked, output is Child then Parent because a genuine click bubbles.

```javascript

  event.preventDefault();

```

**Step-by-step explanation:** preventDefault cancels the default action if the event is cancelable and cancellation is permitted.

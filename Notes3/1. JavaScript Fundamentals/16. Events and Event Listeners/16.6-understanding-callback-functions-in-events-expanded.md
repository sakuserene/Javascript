## 2. What is a callback function?

A **callback** is a function passed to another function or API so that the receiving code can invoke it when appropriate. It is not necessarily asynchronous.

```javascript
function greet() { console.log("Hello"); }
greet();                 // Direct invocation, now
setTimeout(greet, 1000); // Pass reference; timer schedules it later

const button = document.querySelector("button");
button.addEventListener("click", greet); // Browser invokes on click
```

**Trace:** define `greet` -> evaluate `button` -> register `greet` -> wait for event -> dispatch event -> invoke callback. Registration alone does not run the callback. `setTimeout` delay is a minimum scheduling delay, not a guarantee of exact timing.

## 3. Function references versus function invocation

`handleClick` evaluates to a function object; `handleClick()` **calls** that function and evaluates to its return value.

```javascript
function greet(name) { console.log("Hello, " + name); }
// Incorrect: executes during registration, returns undefined
button.addEventListener("click", greet("Alice"));
// Correct: creates a callback that calls greet later
const handler = () => greet("Alice");
button.addEventListener("click", handler);
```

**Syntax:** `()` after an expression invokes it; `=>` creates an arrow function; `{}` encloses a block; `"Alice"` is a string literal; `const` creates a binding; `,` separates arguments.

**Trace:** `greet("Alice")` prints immediately; the arrow expression creates a function without printing; when a click is dispatched the arrow callback calls `greet` and prints.

## 4. Complete callback syntax inventory

| Form | Example | Key behavior |
|---|---|---|
| Declaration | `function f(e) {}` | Named function declaration |
| Expression | `const f = function(e) {};` | Function assigned to binding |
| Named expression | `const f = function named(e) {};` | Internal name useful in debugging |
| Arrow | `const f = (e) => {};` | Lexical `this` |
| Concise arrow | `const f = e => e.type;` | Expression implicitly returned |
| Async function | `async function f(e) { await work(); }` | Returns a Promise |
| Async arrow | `const f = async e => await work();` | Promise-returning arrow |
| Listener object | `{ handleEvent(e) {} }` | EventListener object, not a function |

Generator functions (`function*`) are normally unsuitable as direct listeners: invoking one produces an iterator without executing its body. `async` callbacks require explicit rejection handling.

```javascript
function named(event) { console.log(event.type); }
const expression = function (event) { console.log(event.type); };
const arrow = event => console.log(event.type);
const listener = { handleEvent(event) { console.log(event.type); } };
```

## 5. Anatomy of an event callback

```javascript
function handleClick(event) {
  console.log(event.type);
}
```

- `function`: declaration keyword.
- `handleClick`: identifier used to reference the function.
- `(event)`: formal parameter list; `event` receives the first supplied argument.
- `{ ... }`: function body.
- `console.log(...)`: calls the console logging method.
- `event.type`: member access (`.`) to the event's `type` property.
- `;`: statement terminator.

A **parameter** is declared in a function definition; an **argument** is supplied when the function is called. The parameter name can be `event`, `e`, or any valid identifier.

## 6. Callback arguments and return values

`addEventListener()` supplies one event object as the callback's first argument. You may omit the formal parameter, but adding another formal parameter does not cause the browser to supply extra application data.

```javascript
button.addEventListener("click", function (event, extra) {
  console.log(event.type); // click
  console.log(extra);      // undefined
  return false;            // Does not cancel a DOM listener's default action
});
```

The return value of an ordinary DOM listener is ignored by event dispatch. To request default-action cancellation, call `event.preventDefault()` on a cancelable event in a non-passive listener. The `Event` object may be a `MouseEvent`, `PointerEvent`, `KeyboardEvent`, `InputEvent`, or another subclass depending on the event.

## 7. Named, anonymous, and arrow callbacks

Named, anonymous, and arrow callbacks can all be registered. The important difference for removal is retaining **the same function object**.

```javascript
function named(e) { console.log(e.type); }
const anonymous = function (e) { console.log(e.type); };
const arrow = e => console.log(e.type);
button.addEventListener("click", named);
button.addEventListener("click", anonymous);
button.addEventListener("click", arrow);
button.removeEventListener("click", arrow);
```

Regular functions receive `this` from invocation; arrow functions inherit `this` lexically. Ordinary functions have their own `arguments`; arrow functions do not. A named function is often easiest to reuse, remove, test and debug.

## 8. Function identity and event registration

Two identical function expressions create different objects:

```javascript
const a = () => console.log("Hi");
const b = () => console.log("Hi");
console.log(a === b); // false
const c = a;
console.log(a === c); // true
```

`removeEventListener` matches target, type, callback identity, and capture setting. Repeating `addEventListener` with the same target/type/callback/capture does not create an identical duplicate; creating new inline functions does.

```javascript
const handler = () => console.log("Hi");
button.addEventListener("click", handler);
button.removeEventListener("click", handler); // works
```

## 9. Higher-order functions

A **higher-order function** accepts or returns another function.

```javascript
function execute(callback) { callback(); }
execute(() => console.log("Hello"));

function createGreetingHandler(name) {
  return function () { console.log("Hello, " + name); };
}
const aliceHandler = createGreetingHandler("Alice");
button.addEventListener("click", aliceHandler);
```

**Trace:** call factory with `"Alice"` -> create inner function -> return its reference -> register it -> click -> inner function reads captured `name` -> prints greeting. The factory is called immediately; the returned callback is called later.

## 10. Lexical scope

**Lexical scope** means that variable access follows the locations where functions are written.

```javascript
function setup() {
  const message = "Hello from setup";
  function handleClick() { console.log(message); }
  button.addEventListener("click", handleClick);
}
setup();
```

The callback can access `message` from the surrounding scope even after `setup()` has returned. Name resolution searches local scope, then enclosing scopes. This does not make `message` global.

## 11. Closures in event callbacks

A **closure** is a function together with access to its lexical environment.

```javascript
function createCounter() {
  let count = 0;
  return function () {
    count = count + 1;
    console.log(count);
  };
}
const first = createCounter();
const second = createCounter();
first();  // 1
first();  // 2
second(); // 1
```

Each factory call creates a separate `count` binding. A long-lived listener can retain captured objects; clean up temporary listeners when no longer needed.

## 12. Capturing variables correctly

Closures capture **bindings**, not frozen snapshots of mutable values.

```javascript
let message = "First";
const callback = () => console.log(message);
message = "Second";
callback(); // Second
```

Loop behavior:

```javascript
for (let i = 1; i <= 3; i++) {
  document.getElementById("button" + i)
    .addEventListener("click", () => console.log(i));
}
```

`let` creates an appropriate per-iteration binding. Replacing `let` with `var` causes the callbacks to share the function-scoped `i`; after the loop they print `4`. `i++` increments the number by one; `i <= 3` controls when the loop continues.

## 13. Understanding this inside event callbacks

For a **regular function** registered via `addEventListener`, `this` refers to the current event target:

```javascript
button.addEventListener("click", function (event) {
  console.log(this === button);               // true
  console.log(this === event.currentTarget); // true
});
```

Arrow callbacks do not have their own `this`:

```javascript
button.addEventListener("click", event => {
  console.log(event.currentTarget === button); // true
});
```

`event.target` identifies the event's target (possibly retargeted across shadow boundaries); `event.currentTarget` identifies the target whose listener is executing. When clicking a span inside a button, these may differ.

## 14. Arrow functions versus regular functions

| Characteristic | Regular function | Arrow function |
|---|---|---|
| Syntax | `function (e) {}` | `(e) => {}` |
| Own `this` | Yes | No, lexical |
| Own `arguments` | Yes | No |
| Can be `async` | Yes | Yes |
| Can be called with `new` | Ordinary constructible functions can | No |
| Can be listener | Yes | Yes |

```javascript
button.addEventListener("click", function () { this.disabled = true; });
button.addEventListener("click", event => {
  event.currentTarget.textContent = "Clicked";
});
```

Do not assume arrow-function `this` is the button. `event.currentTarget` is often clearer.

## 15. Listener objects and handleEvent()

The standard listener callback can be a function or an object with callable `handleEvent`.

```javascript
const counterListener = {
  count: 0,
  handleEvent(event) {
    this.count += 1;
    console.log(event.type, this.count);
  }
};
button.addEventListener("click", counterListener);
button.removeEventListener("click", counterListener);
```

The object identity is matched for removal; its `handleEvent` method can be changed without changing the listener object's identity. In normal object-listener invocation, `this` inside `handleEvent` is the listener object. OOP as a broad topic remains deferred.

## 17. Function.prototype.call()

`Function.prototype.call()` invokes a function immediately with a specified `this` and individually supplied arguments.

```javascript
function greet(name) { console.log("Hello, " + name); }
greet.call(null, "Alice"); // Hello, Alice
```

Syntax: `functionReference.call(thisArg, arg1, arg2, ...)`. `thisArg` is the requested `this`; in non-strict functions `null` or `undefined` can be substituted with the global object. Calling a callback with `.call()` does not dispatch a DOM event.

## 18. Function.prototype.apply()

`apply()` invokes a function immediately with a `this` value and an array-like argument list.

```javascript
function fullName(first, last) { console.log(first + " " + last); }
fullName.apply(null, ["Alice", "Smith"]);
fullName.call(null, "Alice", "Smith");
```

Both print `Alice Smith`. `apply` takes arguments in one array-like object; `call` takes them individually. Both return whatever the invoked function returns.

## 19. Function.prototype.bind()

`bind()` **creates a new function** with a bound `this` and optionally initial arguments. It does not invoke the original function immediately.

```javascript
function greet(name) { console.log("Hello, " + name); }
const bound = greet.bind(null, "Alice");
button.addEventListener("click", bound);
button.removeEventListener("click", bound);
```

**Mistake:** calling `greet.bind(null, "Alice")` separately during registration and removal creates two distinct bound functions; removal fails. Store the bound function once.

## 20. Callback execution order

```javascript
console.log("A");
button.addEventListener("click", () => console.log("B"));
console.log("C");
```

Before clicking: `A`, `C`. After clicking: `B`.

```javascript
const target = new EventTarget();
target.addEventListener("hello", () => console.log("Listener"));
console.log("Before");
target.dispatchEvent(new Event("hello"));
console.log("After");
```

Output: `Before`, `Listener`, `After`. `dispatchEvent` synchronously invokes applicable listeners; registration does not. For same target and same applicable capture grouping, listeners normally run in registration order; propagation adds further ordering rules.

## 21. Asynchronous callbacks and the event loop

A timer callback runs in a later task; a promise reaction runs as a microtask.

```javascript
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// Typical isolated output: A, D, C, B
```

**Trace:** synchronous `A` -> schedule timer task -> schedule promise microtask -> synchronous `D` -> microtask `C` -> timer task `B`.

```javascript
button.addEventListener("click", async function () {
  console.log("Start");
  await Promise.resolve();
  console.log("Continuation");
});
```

The listener starts synchronously, then suspends at `await`. The browser does not wait for its returned Promise when completing event dispatch. Microtask checkpoints and event-loop scheduling are studied more deeply later.

## 22. Errors in event callbacks

Synchronous errors can be handled with `try...catch` inside callbacks. Async callback rejections should be caught inside the async function or otherwise handled.

```javascript
button.addEventListener("click", async function () {
  try {
    const result = await loadData();
    console.log(result);
  } catch (error) {
    console.error("Load failed:", error);
  }
});
```

Exceptions thrown by listeners during `dispatchEvent` are generally reported as uncaught; they do not ordinarily propagate to the code calling `dispatchEvent`. Throwing does not automatically remove the listener.

## 23. Common callback mistakes and edge cases

1. **Immediate invocation:** `addEventListener("click", callback())` passes a return value, not the callback.
2. **Identity loss:** two identical inline arrow expressions are not the same function.
3. **Wrong `this`:** arrow functions inherit `this` lexically.
4. **Wrong arguments:** DOM listeners get one event argument, not arbitrary custom arguments.
5. **Returning false:** does not cancel default action in `addEventListener` listeners.
6. **Repeated setup:** recreating anonymous callbacks can accumulate listeners.
7. **Uncaught async errors:** rejected promises may be reported as unhandled.
8. **Timer confusion:** `setTimeout(fn, 0)` does not invoke `fn` immediately.
9. **Missing cleanup:** long-lived `document` or `window` listeners can outlive a temporary UI.
10. **Already-aborted signal:** adding a listener with an aborted signal does not register it.

Use stable references, explicit state, meaningful names, error handling and cleanup.

## 24. Advanced callback patterns

### Logging wrapper

```javascript
function withLogging(callback) {
  return function (event) {
    console.log("Before");
    try { return callback.call(this, event); }
    finally { console.log("After"); }
  };
}
const wrapped = withLogging(event => console.log(event.type));
button.addEventListener("click", wrapped);
```

`try...finally` runs the `finally` block even if the callback throws synchronously; it does not swallow the error.

### Compose callbacks

```javascript
function combine(a, b) {
  return function (event) { a(event); b(event); };
}
```

### Generic once wrapper

```javascript
function runOnce(callback) {
  let called = false;
  return function (...args) {
    if (called) return;
    called = true;
    return callback.apply(this, args);
  };
}
```

`...args` is a rest parameter collecting arguments into an array. `{ once: true }` is simpler for DOM event listeners.

### Complete script.js

```javascript
const namedTarget = document.getElementById("namedTarget");
const namedToggle = document.getElementById("namedToggle");
const namedStatus = document.getElementById("namedStatus");
const greetingName = document.getElementById("greetingName");
const createGreeting = document.getElementById("createGreeting");
const greetingTarget = document.getElementById("greetingTarget");
const greetingStatus = document.getElementById("greetingStatus");
const onceTarget = document.getElementById("onceTarget");
const resetOnce = document.getElementById("resetOnce");
const onceStatus = document.getElementById("onceStatus");
const logElement = document.getElementById("log");
const clearLog = document.getElementById("clearLog");

let namedEnabled = false;
let namedCount = 0;
let greetingHandler = null;
let onceArmed = false;
let logSequence = 0;

function log(message) {
  logSequence = logSequence + 1;
  const item = document.createElement("li");
  item.textContent = logSequence + ". " + message;
  logElement.appendChild(item);
}

function handleNamedClick(event) {
  namedCount = namedCount + 1;
  log("Named callback: " + event.type + " (count " + namedCount + ")");
}

function toggleNamedCallback() {
  if (namedEnabled) {
    namedTarget.removeEventListener("click", handleNamedClick);
    namedEnabled = false;
    namedStatus.textContent = "Disabled";
    namedToggle.textContent = "Enable Named Callback";
    log("Named callback removed");
  } else {
    namedTarget.addEventListener("click", handleNamedClick);
    namedEnabled = true;
    namedStatus.textContent = "Enabled";
    namedToggle.textContent = "Disable Named Callback";
    log("Named callback registered");
  }
}

function makeGreetingHandler(name) {
  let count = 0;
  return function (event) {
    count = count + 1;
    const message = "Hello, " + name + "! Event: " + event.type +
      ". Callback count: " + count;
    greetingStatus.textContent = message;
    log(message);
  };
}

function replaceGreetingHandler() {
  if (greetingHandler !== null) {
    greetingTarget.removeEventListener("click", greetingHandler);
  }
  const name = greetingName.value.trim() || "Guest";
  greetingHandler = makeGreetingHandler(name);
  greetingTarget.addEventListener("click", greetingHandler);
  greetingStatus.textContent = "Callback created for " + name;
  log("Greeting callback replaced");
}

function handleOnce(event) {
  onceArmed = false;
  onceStatus.textContent = "Executed once: " + event.type;
  log("One-time callback executed");
}

function armOnceListener() {
  if (onceArmed) {
    onceTarget.removeEventListener("click", handleOnce);
  }
  onceTarget.addEventListener("click", handleOnce, { once: true });
  onceArmed = true;
  onceStatus.textContent = "Ready";
  log("One-time callback armed");
}

function clearActivityLog() {
  logElement.replaceChildren();
  logSequence = 0;
}

namedToggle.addEventListener("click", toggleNamedCallback);
createGreeting.addEventListener("click", replaceGreetingHandler);
resetOnce.addEventListener("click", armOnceListener);
clearLog.addEventListener("click", clearActivityLog);
armOnceListener();
```

### Code breakdown

- `getElementById` returns a reference to a specific element; `defer` delays script execution until parsing is complete.
- `namedEnabled` tracks whether the named callback is registered. The toggle registers or removes the **same** `handleNamedClick` reference.
- `makeGreetingHandler(name)` is a function factory: `return function (event)` returns a callback. Its closure remembers `name` and its own `count`.
- `greetingHandler !== null` checks whether a prior callback exists. Removing it before replacing prevents accumulation.
- `greetingName.value.trim() || "Guest"` reads the input, removes surrounding whitespace, and supplies a fallback for empty strings.
- `{ once: true }` removes the one-time listener before invoking it; rearming registers it again.
- `textContent` sets plain text; `appendChild` inserts a new list item; `replaceChildren()` empties the log.

| Enable named | Registered | Unchanged | Armed |

### Complete script.js

```javascript
const alphaButton = document.getElementById("alpha");
const betaButton = document.getElementById("beta");
const customButton = document.getElementById("custom");
const subscribeButton = document.getElementById("subscribe");
const removeAlphaButton = document.getElementById("removeAlpha");
const removeAllButton = document.getElementById("removeAll");
const subscriptionCount = document.getElementById("subscriptionCount");
const logElement = document.getElementById("log");
const clearLogButton = document.getElementById("clearLog");
const customTarget = new EventTarget();

function log(message) {
  const item = document.createElement("li");
  item.textContent = message;
  logElement.appendChild(item);
}

function createSubscriptionManager() {
  const subscriptions = new Map();

  function subscribe(id, target, type, callback, capture = false) {
    if (subscriptions.has(id)) return false;
    target.addEventListener(type, callback, { capture });
    subscriptions.set(id, { target, type, callback, capture });
    return true;
  }

  function unsubscribe(id) {
    const record = subscriptions.get(id);
    if (record === undefined) return false;
    record.target.removeEventListener(
      record.type, record.callback, record.capture
    );
    subscriptions.delete(id);
    return true;
  }

  function unsubscribeAll() {
    const ids = Array.from(subscriptions.keys());
    for (const id of ids) unsubscribe(id);
  }

  function count() { return subscriptions.size; }
  return { subscribe, unsubscribe, unsubscribeAll, count };
}

const manager = createSubscriptionManager();
function handleAlpha(event) { log("Alpha callback: " + event.type); }
function handleBeta(event) { log("Beta callback: " + event.type); }
function handleCustom(event) {
  log("Custom callback: " + event.detail.message);
}
function updateCount() {
  subscriptionCount.textContent =
    "Active subscriptions: " + manager.count();
}
function subscribeAll() {
  const alphaAdded = manager.subscribe(
    "alpha", alphaButton, "click", handleAlpha
  );
  const betaAdded = manager.subscribe(
    "beta", betaButton, "click", handleBeta
  );
  const customAdded = manager.subscribe(
    "custom", customTarget, "notification", handleCustom
  );
  log(alphaAdded || betaAdded || customAdded
    ? "Missing subscriptions registered"
    : "All subscriptions already exist");
  updateCount();
}
function removeAlpha() {
  const removed = manager.unsubscribe("alpha");
  log(removed ? "Alpha subscription removed" : "Alpha not found");
  updateCount();
}
function removeAll() {
  manager.unsubscribeAll();
  log("All managed subscriptions removed");
  updateCount();
}
function dispatchCustom() {
  const event = new CustomEvent("notification", {
    detail: { message: "Hello from CustomEvent" }
  });
  customTarget.dispatchEvent(event);
}
subscribeButton.addEventListener("click", subscribeAll);
removeAlphaButton.addEventListener("click", removeAlpha);
removeAllButton.addEventListener("click", removeAll);
customButton.addEventListener("click", dispatchCustom);
clearLogButton.addEventListener("click", function () {
  logElement.replaceChildren();
});
updateCount();
```

### Code breakdown

- `new Map()` creates a key-value collection. `has(id)` checks for an existing managed subscription; `set(id, record)` stores one; `get(id)` retrieves it; `delete(id)` removes it; `.size` counts entries.
- `capture = false` is a default parameter. The value is stored so the correct capture registration can later be removed.
- `{ target, type, callback, capture }` is object property shorthand, equivalent to `{ target: target, type: type, callback: callback, capture: capture }`.
- `return false` from `subscribe` means that **this manager** did not add a new record. It is not the return value of `addEventListener`.
- `Array.from(subscriptions.keys())` snapshots the keys into an array; `for (const id of ids)` iterates through them and removes subscriptions.
- The returned object exposes four functions that retain access to the private map through closure. This is encapsulation without classes.
- `new CustomEvent("notification", {detail: {...}})` creates an event carrying data. `dispatchEvent` synchronously dispatches it to the custom EventTarget.
- `alphaAdded || betaAdded || customAdded` checks whether at least one subscription was newly added.

### Map API reference

| API | Role |
|---|---|
| `new Map()` | Create map |
| `set`, `get`, `has`, `delete`, `clear` | Manage entries |
| `size` | Entry count |
| `keys`, `values`, `entries` | Iterators |
| `forEach`, `[Symbol.iterator]` | Visit entries |

### Execution trace

| Action | Managed subscription count | Observable result |
|---|---:|---|
| Page load | 0 | No managed callbacks |
| Subscribe All | 3 | Three registrations |
| Click Alpha | 3 | Alpha logged |
| Dispatch Custom | 3 | Custom message logged |
| Remove Alpha | 2 | Alpha no longer logged |

**Limitations:** this educational manager tracks only registrations it controls; external removal, `{ once: true }` and signal-driven automatic removal are not reflected automatically. Production managers need richer lifecycle tracking and error handling.

## 27. Ten interview questions with answers

### Question 1: What is a callback function?

**Answer:** A function passed to another function or API for invocation at an appropriate time. Event listeners use callbacks to respond to dispatched events.

### Question 2: What is the difference between handleClick and handleClick()?

**Answer:** handleClick is the function reference; handleClick() immediately invokes it and yields its return value.

### Question 3: Are callbacks always asynchronous?

**Answer:** No. Callbacks can run synchronously; dispatchEvent synchronously invokes applicable listeners.

### Question 4: Why are identical anonymous functions not interchangeable for removal?

**Answer:** Each function expression creates a distinct function object. Listener removal uses identity, not source text.

### Question 5: What is a closure?

**Answer:** A function together with access to its lexical environment, useful for remembering counters and configuration.

### Question 6: How does this differ for regular and arrow listeners?

**Answer:** Regular addEventListener callbacks have this set to currentTarget; arrow functions inherit this lexically.

### Question 7: What does a DOM event callback receive?

**Answer:** An Event object as its first argument. Extra application arguments are not automatically supplied.

### Question 8: Does return false cancel a normal addEventListener callback?

**Answer:** No. Use preventDefault on a cancelable event when cancellation is appropriate.

### Question 9: What happens when an async listener rejects?

**Answer:** The event system does not await its promise. An unhandled rejection may be reported unless caught.

### Question 10: What is a higher-order function?

**Answer:** A function that accepts or returns a function; it can create wrappers, factories, logging and composition.

## 28. Ten coding exercises with complete solutions

### Exercise 1: Register a named callback

**Task:** Create a button `startButton` and log Started on click.

**Solution:**

```html
<button id="startButton">Start</button>
<script>
const button = document.getElementById("startButton");
function handleStart(event) { console.log("Started"); }
button.addEventListener("click", handleStart);
</script>
```

**Explanation:** The browser receives `handleStart`, not `handleStart()`. It invokes the callback when clicked.

### Exercise 2: Fix immediate invocation

**Task:** Fix `button.addEventListener("click", greet("Alice"));`.

**Solution:**

```javascript
function greet(name) { console.log("Hello, " + name); }
function handleClick() { greet("Alice"); }
button.addEventListener("click", handleClick);
```

**Explanation:** The wrapper delays calling greet until the event.

### Exercise 3: Create a closure counter

**Task:** Create a callback that remembers how many times it has run.

**Solution:**

```javascript
function createCounterHandler() {
  let count = 0;
  return function () { count = count + 1; console.log(count); };
}
const handler = createCounterHandler();
button.addEventListener("click", handler);
```

**Explanation:** The returned function closes over the private `count` binding.

### Exercise 4: Remove an arrow callback

**Task:** Register an arrow callback and remove it correctly.

**Solution:**

```javascript
const handler = event => console.log(event.type);
button.addEventListener("click", handler);
button.removeEventListener("click", handler);
```

**Explanation:** The same function object is used for both calls.

### Exercise 5: Build a callback factory

**Task:** Make Alice and Bob buttons print different greetings.

**Solution:**

```javascript
function createGreeting(name) {
  return function () { console.log("Hello, " + name); };
}
const alice = createGreeting("Alice");
const bob = createGreeting("Bob");
document.getElementById("alice").addEventListener("click", alice);
document.getElementById("bob").addEventListener("click", bob);
```

**Explanation:** Each factory invocation creates a callback capturing a different name.

### Exercise 6: Use a listener object

**Task:** Create an object that counts clicks via handleEvent.

**Solution:**

```javascript
const counter = {
  count: 0,
  handleEvent(event) {
    this.count += 1;
    console.log(event.type, this.count);
  }
};
button.addEventListener("click", counter);
```

**Explanation:** The browser invokes the object method with `this` bound to the listener object.

### Exercise 7: Use bind correctly

**Task:** Pre-fill a message and retain removal identity.

**Solution:**

```javascript
function show(message) { console.log(message); }
const handler = show.bind(null, "Clicked");
button.addEventListener("click", handler);
button.removeEventListener("click", handler);
```

**Explanation:** Calling bind once and saving the returned function preserves identity.

### Exercise 8: Predict execution order

**Task:** Predict A, B, C, D with timer and Promise.

**Solution:**

```javascript
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// A, D, C, B
```

**Explanation:** Synchronous statements run first; the Promise microtask precedes the later timer task.

### Exercise 9: Handle async errors

**Task:** Catch a rejection inside an async event listener.

**Solution:**

```javascript
async function loadData() { throw new Error("Unavailable"); }
async function handleClick() {
  try { await loadData(); }
  catch (error) { console.error(error.message); }
}
button.addEventListener("click", handleClick);
```

**Explanation:** The try/catch handles the rejection from the awaited promise.

### Exercise 10: Write a logging wrapper

**Task:** Log before and after an event callback, including when it throws synchronously.

**Solution:**

```javascript
function withLogging(callback) {
  return function (event) {
    console.log("Before");
    try { return callback.call(this, event); }
    finally { console.log("After"); }
  };
}
function handleClick(event) { console.log(event.type); }
const wrapped = withLogging(handleClick);
button.addEventListener("click", wrapped);
```

**Explanation:** `call` forwards this and event; `finally` executes after a synchronous return or throw.

## 30. Debugging event callbacks

| Symptom | Diagnostic step |
|---|---|
| Never runs | Check target, event type, registration timing |
| Runs too early | Look for `callback()` at registration |
| Runs multiple times | Check repeated setup and callback identities |
| Cannot remove | Compare target/type/callback/capture |
| Wrong `this` | Compare regular and arrow callbacks |
| `undefined` extra parameter | Browser supplies only event argument |
| Stale/unexpected state | Inspect closure bindings |
| Async failure | Catch awaited promise rejection |
| Runs after UI closed | Remove temporary listeners |

```javascript
function handleClick(event) {
  debugger;
  console.log(event.type, event.target, event.currentTarget);
}
```

In developer tools, inspect the call stack, scope/closures, `this`, and event object. For a small test use `new EventTarget()`, `dispatchEvent(new Event("test"))`, and `console.assert(...)`. Browser debugging helpers such as `getEventListeners()` are not portable standard APIs.

## 34. Lesson summary and navigation

Callbacks are functions supplied to other code for controlled invocation. Registering a listener is not invoking it. The browser supplies an event object, callback identity determines cleanup, closures preserve access to lexical bindings, and ordinary versus arrow functions differ in `this`. Synchronous dispatch does not wait for promises returned by async listeners.

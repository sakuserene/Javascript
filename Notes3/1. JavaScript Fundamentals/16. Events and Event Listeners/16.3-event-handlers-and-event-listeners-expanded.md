## 1. Learning objectives

By the end, you should be able to distinguish an event, handler function, event-handler property, and registered listener; use all three DOM event handling styles; explain callback identity and `this`; reason about return values, event propagation, duplicate registration, and cleanup; identify relevant interfaces and event-handler property families; and build accessible, testable interactions.

## 2. What is an event?

An **event** is an object representing an occurrence, such as a click, key press, form submission, network message, or custom notification. In the browser, event targets expose ways to register code to react when events are dispatched.

```html
<button id="saveButton" type="button">Save</button>
<script src="script.js" defer></script>
```

```javascript
const button = document.getElementById("saveButton");
button.addEventListener("click", function (event) {
  console.log("Event type:", event.type);
});
```

**Line-by-line:** `const` creates a binding that cannot be reassigned; `document` is the page's `Document` object; `getElementById` finds the element with the given ID or returns `null`; `.` accesses a member; `addEventListener` registers a listener; `"click"` is a case-sensitive event type; `function (event) { ... }` is a function expression; the browser supplies `event` when the callback runs. The registration call returns `undefined`.

**Trace:** (1) browser parses the button; (2) deferred script executes; (3) variable references button; (4) listener is registered; (5) no callback output yet; (6) user clicks; (7) click event is dispatched; (8) callback prints the event type.

## 3. Handler vs listener: precise terminology

- **Handler function:** the callable code that reacts to an event.
- **Event-handler property:** a property such as `button.onclick` whose assigned value specifies event-handling behavior.
- **Event-handler content attribute:** HTML syntax such as `onclick="..."`.
- **Event listener:** a callback or listener object registered on an `EventTarget`, commonly using `addEventListener()`.
- **Event listener registration:** the browser's internal association of target, event type, callback, capture, and other options.

In everyday usage, people often call all callback functions "event handlers." That is understandable, but distinguish the API mechanism from the function itself.

```text
Event occurs
    |
    v
EventTarget dispatches Event
    |
    +-- handler property callback (if present)
    |
    +-- registered addEventListener callbacks
    |
    v
Applicable callbacks run according to propagation and registration rules
```

The property-based handler participates in the event listener system; it is not a completely separate browser event pipeline.

## 4. EventTarget and the registration model

The standard `EventTarget` interface exposes three core methods:

| Method | Purpose | Return value |
|---|---|---|
| `addEventListener(type, callback, options?)` | Register listener | `undefined` |
| `removeEventListener(type, callback, options?)` | Remove matching registration | `undefined` |
| `dispatchEvent(event)` | Dispatch event synchronously | Boolean: `false` if cancelable event was canceled, otherwise `true` |

Common targets: `window`, `document`, DOM elements, `AbortSignal`, `WebSocket`, `Worker`, and custom `new EventTarget()` objects. Plain object literals are not EventTargets.

```javascript
const bus = new EventTarget();
function respond(event) {
  console.log(event.type);
}
bus.addEventListener("notice", respond);
bus.dispatchEvent(new Event("notice")); // notice
bus.removeEventListener("notice", respond);
```

**Syntax breakdown:** `new` constructs an object; `EventTarget()` is a constructor; `respond` without parentheses is a reference; `new Event("notice")` constructs an event; `//` begins a comment. The event type can be a developer-defined string.

## 5. Three ways to handle DOM events

### A. HTML content attribute

```html
<button type="button" onclick="console.log('Clicked')">Click</button>
```

### B. JavaScript event-handler property

```javascript
button.onclick = function (event) {
  console.log("Clicked", event.type);
};
```

### C. addEventListener()

```javascript
button.addEventListener("click", function (event) {
  console.log("Clicked", event.type);
});
```

| Feature | HTML content attribute | `onclick` property | `addEventListener()` |
|---|---|---|---|
| Location | HTML markup | JavaScript | JavaScript |
| Reassignment | Replaces attribute handler code | Replaces property callback | Adds another registration if not duplicate |
| Multiple independent callbacks | Not via one attribute handler slot | One handler value per property | Yes |
| Capture and once options | No | No | Yes |
| AbortSignal cleanup | No | No | Yes |
| Recommended for modern apps | Usually avoid | Valid for simple cases | Usually preferred |

`addEventListener()` does not overwrite an existing `onclick` handler. Both may run. Their relative execution position can depend on when the property handler was first activated and when other listeners were registered.

## 6. HTML event-handler content attributes

Example:

```html
<button onclick="showMessage(event)" type="button">Show</button>
```

This HTML attribute contains JavaScript source text. The browser creates event-handler behavior from that source. The special `event` argument is available in HTML event-handler code in relevant contexts. Inline handlers have historically unusual name resolution and `this` behavior, making them harder to reason about and secure.

**Why generally avoid inline handlers:** mixes markup with executable code; complicates Content Security Policy (CSP); harder to test and maintain; relies on globals or unusual handler scope; encourages code duplication. Inline handlers can be blocked by CSP policies that disallow inline script.

Do not confuse an HTML attribute with the JavaScript property:

```javascript
button.setAttribute("onclick", "console.log('Clicked')");
button.onclick = function () { console.log("Clicked"); };
```

The first sets executable text in a content attribute; the second assigns a function object to an IDL property. The behavior is related but the representations are not the same.

**Important exception:** Certain handler attributes such as `onerror` and `onload` can be exposed on particular elements, and handler support is defined by the relevant HTML and other web specifications. There is no single short list of every `on...` event name that applies uniformly to all targets.

## 7. Event-handler IDL properties

An event-handler IDL property is a JavaScript property, such as `element.onclick`, whose value is usually `null` or a callback. Some special event handlers, notably `window.onerror` and `window.onbeforeunload`, have additional historical semantics.

```javascript
const button = document.querySelector("button");
console.log(button.onclick); // Usually null if no handler assigned
button.onclick = function () { console.log("A"); };
button.onclick = function () { console.log("B"); };
```

Click output: `B`. The second assignment replaces the property value.

To clear a property handler:

```javascript
button.onclick = null;
```

The property handler is not an array of callbacks. The same event type may also have many listeners added with `addEventListener()`.

**IDL terminology:** IDL stands for Interface Definition Language. In browser standards, an IDL attribute is a property exposed to JavaScript. The historical term `GlobalEventHandlers` appears in older documentation; modern HTML specifications define handler attributes through interfaces such as `GlobalEventHandlers`-related mixins and target-specific handler sets. Treat names in historical documentation as context, not as an exhaustive list of all event sources.

## 8. EventTarget.addEventListener() overview

```javascript
target.addEventListener(type, callback);
target.addEventListener(type, callback, options);
target.addEventListener(type, callback, useCapture);
```

| Parameter | Type | Details |
|---|---|---|
| `type` | String | Case-sensitive event name; omit `on` prefix |
| `callback` | Function, object with `handleEvent`, or null | Invoked when event is handled |
| `options.capture` | Boolean | Default false; choose capture registration |
| `options.once` | Boolean | Default false; auto-remove after first invocation |
| `options.passive` | Boolean | Generally false but special browser defaults for certain touch/wheel listeners on root targets |
| `options.signal` | `AbortSignal` | Optional; abort removes registration |
| `useCapture` | Boolean | Legacy-style alternative to options object |

Return: `undefined`. The callback may be a regular function, arrow function, or listener object. Duplicate registrations with the same target, type, callback identity, and capture setting are ignored, even if `once` or `passive` differs.

```javascript
const controller = new AbortController();
button.addEventListener("click", handleClick, {
  once: false,
  capture: false,
  passive: true,
  signal: controller.signal
});
controller.abort(); // Removes this listener
```

`AbortController` is explained further in Lesson 16.48. Lesson 16.4 provides exhaustive detail on the `addEventListener()` method itself.

**Inspect a target safely:**

```javascript
const button = document.querySelector("button");

```

`in` checks whether a property exists on the object or its prototype chain. `typeof null` returns `"object"` due to a historical JavaScript quirk.

## 10. Callbacks and listener objects

**Named function:**

```javascript
function report(event) {
  console.log(event.type);
}
button.addEventListener("click", report);
```

**Anonymous function expression:**

```javascript
button.addEventListener("click", function (event) {
  console.log(event.type);
});
```

**Arrow function:**

```javascript
button.addEventListener("click", (event) => {
  console.log(event.type);
});
```

**Object listener:**

```javascript
const listener = {
  handleEvent(event) {
    console.log("Object listener:", event.type);
  }
};
button.addEventListener("click", listener);
```

`handleEvent` is the expected method name for a listener object. An object listener is different from an event-handler IDL property; assigning an arbitrary listener object to `onclick` is not the same API as passing it to `addEventListener()`.

## 11. Function references vs calls

```javascript
function greet(name) {
  console.log("Hello, " + name);
}
```

`greet` evaluates to the function object. `greet("Alice")` **invokes** the function and evaluates to its return value, which is `undefined` here.

**Incorrect for delayed execution:**

```javascript
button.addEventListener("click", greet("Alice"));
```

Trace: (1) evaluate `greet("Alice")`; (2) print `Hello, Alice` immediately; (3) get `undefined`; (4) pass that as callback; (5) no working listener registered.

**Correct:**

```javascript
button.addEventListener("click", function () {
  greet("Alice");
});
```

Now the wrapper function is registered and calls `greet` only when a click is handled.

**Alternative using a closure:**

```javascript
const name = "Alice";
button.addEventListener("click", () => greet(name));
```

`=>` defines an arrow function; the arrow callback closes over the variable `name`.

## 12. Arguments and the event object

The browser passes an event object to listener callbacks. The parameter name can be `event`, `e`, or another valid identifier.

```javascript
button.addEventListener("click", function (e) {
  console.log(e.type);
  console.log(e.target);
  console.log(e.currentTarget);
});
```

Core `Event` interface members:

| Member | Meaning |
|---|---|
| `type` | Case-sensitive event type |
| `target` | Original target, subject to retargeting rules |
| `currentTarget` | Target whose listener is executing |
| `eventPhase` | `0` none, `1` capture, `2` target, `3` bubble |
| `bubbles` | Whether event bubbles |
| `cancelable` | Whether default action can be canceled |
| `composed` | Whether event can cross shadow boundary |
| `defaultPrevented` | Whether default was prevented |
| `isTrusted` | Whether generated by user agent rather than script dispatch |
| `timeStamp` | Event timestamp |
| `preventDefault()` | Request default-action cancellation |
| `stopPropagation()` | Stop propagation to later targets |
| `stopImmediatePropagation()` | Also stop later same-target listeners |
| `composedPath()` | Get propagation path (shadow DOM rules apply) |

Legacy members: `cancelBubble`, `returnValue`, `srcElement`, `initEvent()`. Prefer modern equivalents. Specialized event classes such as `MouseEvent`, `KeyboardEvent`, `PointerEvent`, `InputEvent`, `FocusEvent`, and `CustomEvent` add their own members; see Lessons 16.7 and the relevant event-family lessons.

## 13. this, lexical scope, and closures

### Regular listener function

```javascript
button.addEventListener("click", function (event) {
  console.log(this === event.currentTarget); // true
});
```

In an ordinary regular function registered through `addEventListener()`, `this` refers to the current target. `===` tests strict equality.

### Arrow listener

```javascript
button.addEventListener("click", (event) => {
  console.log(event.currentTarget);
});
```

Arrow functions capture `this` lexically from their surrounding context. They do not create their own `this` binding. Use `event.currentTarget` when you need the target regardless of callback form.

### Property handler

```javascript
button.onclick = function (event) {
  console.log(this === button); // true for ordinary DOM handler invocation
};
```

### Closure

```javascript
function makeCounterHandler() {
  let count = 0;
  return function () {
    count = count + 1;
    console.log(count);
  };
}
const counterHandler = makeCounterHandler();
button.addEventListener("click", counterHandler);
```

The returned function remembers the `count` variable even after `makeCounterHandler()` returns. Each click increases it. `let` allows reassignment; `count = count + 1` reads the old value, adds one, and assigns the result.

## 14. Handler return values and default actions

For `addEventListener()` callbacks, returned values are ignored:

```javascript
button.addEventListener("click", function () {
  return false; // Does not cancel a default action
});
```

For **event-handler properties** and **HTML event-handler attributes**, legacy `return false` behavior can cancel default actions for certain cancelable events. Do not assume it works like jQuery's handler conventions or that it stops propagation. Prefer explicit `event.preventDefault()` where cancellation is required.

```javascript
const link = document.querySelector("a");
link.addEventListener("click", function (event) {
  event.preventDefault();
});
```

`preventDefault()` does nothing if the event is not cancelable, or when cancellation is disallowed (for example, inside a passive listener). Special handlers such as `window.onerror` have distinct legacy return-value semantics; do not generalize their behavior to all event handlers.

## 15. Assignment, replacement, and multiple listeners

```javascript
button.onclick = () => console.log("Property A");
button.onclick = () => console.log("Property B");
button.addEventListener("click", () => console.log("Listener C"));
button.addEventListener("click", () => console.log("Listener D"));
```

Click output is `Property B`, `Listener C`, `Listener D` in this simple example because the property handler was activated before the `addEventListener()` registrations. The first property callback was replaced. The property-based handler retains its original listener slot when the callback is changed rather than being moved to the end of the listener list.

**Important nuance:** If you first register an `addEventListener()` callback and only later activate `onclick`, their order can be reversed. Propagation phase and `stopImmediatePropagation()` can also affect what runs.

## 16. Listener identity and duplicate registrations

```javascript
function handler() { console.log("A"); }
button.addEventListener("click", handler);
button.addEventListener("click", handler); // Duplicate: ignored
```

One click prints `A` once.

```javascript
button.addEventListener("click", () => console.log("B"));
button.addEventListener("click", () => console.log("B"));
```

One click prints `B` twice because each arrow expression creates a different function object.

```javascript
const first = () => 1;
const second = () => 1;
console.log(first === second); // false
```

On the same target, matching uses event type, callback identity, and capture setting. Different capture settings allow two registrations. Changing `once`, `passive`, or `signal` in a later duplicate registration does not update the existing registration.

## 17. Order of execution and dispatch

```javascript
console.log("A");
button.addEventListener("click", () => console.log("B"));
console.log("C");
```

Before any click: `A`, `C`. After a click: `B`.

```text
Script execution
|-- print A
|-- register callback B (do not invoke)
\-- print C

Later event dispatch
\-- invoke callback B
```

`dispatchEvent()` is synchronous:

```javascript
const target = new EventTarget();
target.addEventListener("ping", () => console.log("Inside"));
console.log("Before");
target.dispatchEvent(new Event("ping"));
console.log("After");
```

Output: `Before`, `Inside`, `After`.

Native user events are dispatched by the browser at appropriate times. The JavaScript event loop, tasks, microtasks, and async handlers have their own scheduling rules; see later asynchronous programming lessons and Lesson 16.76.

## 18. Propagation and cancellation introduction

```html
<div id="parent"><button id="child" type="button">Click</button></div>
```

```javascript
const parent = document.getElementById("parent");
const child = document.getElementById("child");
parent.addEventListener("click", () => console.log("Capture"), true);
child.addEventListener("click", () => console.log("Target"));
parent.addEventListener("click", () => console.log("Bubble"));
```

Click child: `Capture`, `Target`, `Bubble`.

| Operation | Stops default action? | Stops propagation? | Stops other same-target listeners? |
|---|---|---|---|
| `preventDefault()` | If permitted | No | No |
| `stopPropagation()` | No | Yes | No |
| `stopImmediatePropagation()` | No | Yes | Yes |

`Event.CAPTURING_PHASE` is 1; `Event.AT_TARGET` is 2; `Event.BUBBLING_PHASE` is 3; `Event.NONE` is 0. A capture listener on the target executes at the target phase, not necessarily with phase value 1.

## 19. Lifecycle and cleanup

### Named listener cleanup

```javascript
function handleClick() { console.log("Clicked"); }
button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

For removal, the type, callback identity, and capture setting must match. The method returns `undefined` even when no matching registration exists.

### AbortController cleanup

```javascript
const controller = new AbortController();
button.addEventListener("click", handleClick, {
  signal: controller.signal
});
controller.abort();
```

Aborting removes listeners associated with that signal. A signal that is already aborted prevents a new registration from being added.

### One-time listener

```javascript
button.addEventListener("click", handleClick, { once: true });
```

The listener is removed when invoked the first time. This still happens if the callback throws.

**Memory note:** Listeners and their closures can retain referenced objects. A listener is not automatically a leak; problems arise when long-lived targets retain callbacks and large object graphs that are no longer needed. Clean up when components or views are retired.

## 20. DOM readiness and null references

```javascript
const button = document.getElementById("missing");
button.addEventListener("click", handleClick); // TypeError if null
```

A defensive check:

```javascript
const button = document.getElementById("saveButton");
if (button !== null) {
  button.addEventListener("click", handleClick);
}
```

`!==` means strict inequality. If the element exists, register; otherwise, skip.

Use a deferred classic script:

```html
<script src="script.js" defer></script>
```

Or wait for `DOMContentLoaded` when necessary. Note that `DOMContentLoaded` may already have fired before dynamically loaded code runs; checking `document.readyState` is useful in reusable initialization code.

## 21. Errors, exceptions, and debugging

| Symptom | Likely cause | Check |
|---|---|---|
| `Cannot read properties of null` | Selector found nothing | Element ID, DOM readiness |
| Handler runs during setup | Used `handler()` instead of `handler` | Function reference |
| Handler runs twice | Distinct callbacks or duplicate setup | Listener identity, setup path |
| Handler never runs | Wrong target or event type | Case-sensitive type, target |
| `this` is unexpected | Arrow callback | Use `event.currentTarget` |
| `removeEventListener()` does not work | Different callback identity or capture flag | Preserve reference |
| Default action still happens | Event not cancelable or passive listener | `event.cancelable`, options |
| Some callbacks do not run | Propagation stopped or listener removed | `stopImmediatePropagation`, cleanup |

An exception thrown by a listener is typically reported as an uncaught exception in the browser; it does not ordinarily propagate to a surrounding `try...catch` around `dispatchEvent()`.

**Debugging pattern:**

```javascript
button.addEventListener("click", function (event) {
  console.log({
    type: event.type,
    target: event.target,
    currentTarget: event.currentTarget,
    phase: event.eventPhase,
    trusted: event.isTrusted
  });
});
```

`{ type: ..., target: ... }` creates an object literal for readable console inspection.

## 22. Security, accessibility, and performance

**Security:** Avoid interpolating untrusted strings into inline event-handler attributes or `innerHTML`; prefer `textContent` for user-provided text. Content Security Policy can disallow inline JavaScript. `event.isTrusted` indicates the event's origin, but is not a complete authorization or anti-abuse security control. Browser default actions and user-activation requirements still matter.

**Accessibility:** Use semantic `<button>` elements for actions and `<label>` elements for inputs. Buttons support keyboard activation and focus automatically; clickable `<div>` elements need additional keyboard and semantic work. Do not rely solely on hover. Keep focus visible and announce important status changes using appropriate live regions.

**Performance:** Avoid attaching a huge number of redundant listeners unnecessarily. Use event delegation where appropriate, especially for dynamic lists; use throttling or debouncing for high-frequency events when needed. `passive: true` can help scrolling-related interactions but does not make slow callbacks fast.

## 23. Project 1 - Accessible message controller

### Goal

Build a complete message panel with three buttons and a text input. Demonstrate named callbacks, the event object, input handling, a property handler, `textContent`, and accessible status updates.

```html

  <main class="panel">
```

```javascript
const nameInput = document.getElementById("nameInput");
const message = document.getElementById("message");
const eventInfo = document.getElementById("eventInfo");
const helloButton = document.getElementById("helloButton");
const welcomeButton = document.getElementById("welcomeButton");
const resetButton = document.getElementById("resetButton");

function getName() {
  return nameInput.value.trim() || "Guest";
}

function updateMessage(text, event) {
  message.textContent = text;
  eventInfo.textContent = "Last event: " + event.type +
    " on " + event.currentTarget.id;
}

function sayHello(event) {
  updateMessage("Hello, " + getName() + "!", event);
}

function sayWelcome(event) {
  updateMessage("Welcome, " + getName() + "!", event);
}

function resetMessage(event) {
  nameInput.value = "";
  updateMessage("Ready.", event);
}

helloButton.addEventListener("click", sayHello);
welcomeButton.addEventListener("click", sayWelcome);
resetButton.onclick = resetMessage;

nameInput.addEventListener("input", function (event) {
  eventInfo.textContent = "Last event: " + event.type +
    " on " + event.currentTarget.id;
});
```

### Complete walkthrough

1. `getElementById` returns DOM references. `const` prevents reassignment of those bindings, not mutation of the referenced DOM elements.
2. `getName()` reads `nameInput.value`, a string. `.trim()` removes leading/trailing whitespace. `|| "Guest"` returns the fallback if the trimmed string is empty (falsy).
3. `updateMessage(text, event)` has two parameters. `textContent` inserts plain text safely. `event.type` identifies the event, and `event.currentTarget.id` identifies the element currently handling it.
4. `sayHello(event)` and `sayWelcome(event)` are named callbacks. They call `updateMessage()` with different strings.
5. `resetMessage(event)` clears the input and resets the message.
6. `helloButton.addEventListener("click", sayHello)` registers the function reference. `welcomeButton` does likewise.
7. `resetButton.onclick = resetMessage` demonstrates the event-handler property form. Assigning another function to `resetButton.onclick` would replace this property handler.
8. The input listener is an anonymous function that updates the event description without changing the greeting.
9. The HTML `role="status"` and `aria-live="polite"` help assistive technologies announce message changes.

### script.js

```javascript
const targetButton = document.getElementById("targetButton");
const enableButton = document.getElementById("enableButton");
const disableButton = document.getElementById("disableButton");
const onceButton = document.getElementById("onceButton");
const abortButton = document.getElementById("abortButton");
const stopButton = document.getElementById("stopButton");
const clearButton = document.getElementById("clearButton");
const status = document.getElementById("status");
const countDisplay = document.getElementById("count");
const log = document.getElementById("log");

let count = 0;
let extraEnabled = false;
let onceEnabled = false;
let controller = null;

function record(text) {
  const item = document.createElement("li");
  item.textContent = text;
  log.appendChild(item);
}

function propertyHandler() {
  record("Property handler: latest assignment");
}

function primaryHandler(event) {
  count = count + 1;
  countDisplay.textContent = count;
  record("Primary listener: " + event.type + " #" + count);
}

function extraHandler() {
  record("Extra named listener executed");
}

function onceHandler() {
  record("One-time listener executed");
  onceEnabled = false;
  updateStatus();
}

function abortableHandler() {
  record("Abortable listener executed");
}

function updateStatus() {
  status.textContent = "Extra: " + (extraEnabled ? "on" : "off") +
    " | Once: " + (onceEnabled ? "armed" : "off") +
    " | Abortable: " + (controller !== null ? "on" : "off");
}

function enableExtra() {
  targetButton.addEventListener("click", extraHandler);
  extraEnabled = true;
  updateStatus();
}

function disableExtra() {
  targetButton.removeEventListener("click", extraHandler);
  extraEnabled = false;
  updateStatus();
}

function enableOnce() {
  if (onceEnabled) {
    record("One-time listener is already armed");
    return;
  }
  targetButton.addEventListener("click", onceHandler, { once: true });
  onceEnabled = true;
  updateStatus();
}

function enableAbortable() {
  disableAbortable();
  controller = new AbortController();
  targetButton.addEventListener("click", abortableHandler, {
    signal: controller.signal
  });
  updateStatus();
}

function disableAbortable() {
  if (controller !== null) {
    controller.abort();
    controller = null;
    record("Abortable listener removed");
  }
  updateStatus();
}

// Demonstrate property replacement: only the latest property callback remains.
targetButton.onclick = function () { record("Old property handler"); };
targetButton.onclick = propertyHandler;

// An independent addEventListener callback coexists with onclick.
targetButton.addEventListener("click", primaryHandler);

enableButton.addEventListener("click", enableExtra);
disableButton.addEventListener("click", disableExtra);
onceButton.addEventListener("click", enableOnce);
abortButton.addEventListener("click", enableAbortable);
stopButton.addEventListener("click", disableAbortable);
clearButton.addEventListener("click", function () {
  log.replaceChildren();
});

updateStatus();
```

### Complete walkthrough

1. `count` tracks how many times the permanent primary listener executes. `count = count + 1` increases it by one.
2. `extraEnabled` and `onceEnabled` are booleans. `controller` is either an `AbortController` or `null`.
3. `record(text)` creates an `<li>`, sets its safe `textContent`, and appends it to the log.
4. `targetButton.onclick` is assigned twice. The old callback is replaced by `propertyHandler`; the old message never appears on subsequent clicks.
5. `primaryHandler` is registered independently using `addEventListener()`. It remains active even when extra listeners are disabled.
6. `enableExtra()` registers `extraHandler` using a stable function reference. Calling Enable repeatedly does not create duplicate registrations with the same type, callback, and capture setting.
7. `disableExtra()` removes the matching registration. It can be called repeatedly without throwing.
8. `enableOnce()` uses an `if` guard and an early `return`. This prevents repeated setup while a one-time listener is armed.
9. `onceHandler()` sets `onceEnabled` to false when invoked. The browser removes its one-time registration automatically.
10. `enableAbortable()` creates a fresh controller and passes its signal to the listener. `disableAbortable()` calls `abort()` to remove it and then clears the controller reference.
11. `condition ? a : b` is the conditional (ternary) operator. It evaluates the condition and returns `a` if truthy, otherwise `b`.
12. `log.replaceChildren()` removes existing child nodes and clears the log.

|---|---|---|
| Click target initially | Property + primary | Property handler; Primary listener |
| Enable Extra, click | Property + primary + extra | Property; Primary; Extra |
| Enable Extra again, click | Same callbacks, no duplicate | Property; Primary; Extra |

The browser does not expose a standardized `getEventListeners()` method on DOM elements; browser developer tools may offer nonstandard inspection helpers.

## 26. Ten interview questions and answers

### 1. What is the difference between an event handler and an event listener?

An event handler is the callback logic that responds to an event. An event listener is a callback or listener object registered through the event system. A property such as `onclick` is a handler slot; `addEventListener()` registers independent listeners. Everyday terminology often overlaps.

### 2. What are the three common DOM event handling approaches?

HTML event-handler content attributes, JavaScript event-handler properties, and `addEventListener()`. Modern applications generally favor `addEventListener()` because it supports multiple registrations, options, and explicit cleanup.

### 3. Why is `button.onclick = handler()` usually wrong?

It immediately invokes `handler()` and assigns the return value to the property. To assign the function itself, use `button.onclick = handler`.

### 4. Can `onclick` and `addEventListener("click", ...)` coexist?

Yes. They use the same event dispatch system but different registration mechanisms. A property handler and one or more added listeners can all execute, subject to order and propagation rules.

### 5. What happens if you assign `onclick` twice?

The second assignment replaces the property callback. It does not create two independent property handlers. An existing property handler's listener position is generally retained when its value changes.

### 6. How are duplicate addEventListener registrations detected?

For a given target, the event type, callback object identity, and capture setting must match. Different anonymous function expressions are different callbacks even if their code is identical.

### 7. What is the difference between `event.target` and `event.currentTarget`?

`target` identifies the event target (with retargeting caveats). `currentTarget` identifies the EventTarget whose listener is currently executing. They can differ during propagation.

### 8. How does `this` differ between regular and arrow event callbacks?

An ordinary regular function registered with `addEventListener()` receives `this` as the current target. An arrow function inherits `this` lexically. `event.currentTarget` avoids ambiguity.

### 9. Does returning `false` from an addEventListener callback cancel an event?

No. The return value is ignored. Use `event.preventDefault()` when cancellation is allowed. Some event-handler properties and inline handlers have special legacy return-value semantics.

### 10. How should event listeners be cleaned up?

Keep a stable callback reference for `removeEventListener()`, use `{ once: true }` for one-time work, or use an `AbortController` signal for grouped cleanup. Cleanup is important when long-lived targets otherwise retain no-longer-needed callbacks and closures.

### Exercise 1: Register a named click callback

**Task:** Print `Clicked` on a button click.

**Solution:**

```javascript
const button = document.getElementById("myButton");
function handleClick() {
  console.log("Clicked");
}
button.addEventListener("click", handleClick);
```

**Why:** `handleClick` is passed by reference. The browser invokes it on click; it does not run during registration.

### Exercise 2: Use an event-handler property

**Task:** Set a button's `onclick` property.

**Solution:**

```javascript
const button = document.getElementById("myButton");
button.onclick = function (event) {
  console.log(event.type);
};
```

**Why:** The property receives a function. The event object is passed when the property handler runs.

### Exercise 3: Demonstrate replacement

**Task:** Assign two different `onclick` functions and predict the output.

**Solution:**

```javascript
const button = document.getElementById("myButton");
button.onclick = () => console.log("First");
button.onclick = () => console.log("Second");
```

**Answer:** One click prints `Second` because the property value was replaced.

### Exercise 4: Register two independent listeners

**Task:** Print `A` and `B` on one click.

**Solution:**

```javascript
const button = document.getElementById("myButton");
button.addEventListener("click", () => console.log("A"));
button.addEventListener("click", () => console.log("B"));
```

**Why:** The callbacks are distinct and both are registered.

### Exercise 5: Pass a custom argument to a callback

**Task:** Print `Hello, Ada` only after a click.

**Solution:**

```javascript
const button = document.getElementById("myButton");
function greet(name) {
  console.log("Hello, " + name);
}
button.addEventListener("click", () => greet("Ada"));
```

**Why:** The arrow wrapper delays the call to `greet` until the event is handled.

### Exercise 6: Inspect event properties

**Task:** Print event type, target, and current target.

**Solution:**

```javascript
const button = document.getElementById("myButton");
button.addEventListener("click", function (event) {
  console.log(event.type);
  console.log(event.target);
  console.log(event.currentTarget);
});
```

**Why:** The event object supplies information about the dispatch and current listener.

### Exercise 7: Use a closure for a click counter

**Task:** Count clicks without using a global variable.

**Solution:**

```javascript
const button = document.getElementById("myButton");
function makeCounter() {
  let count = 0;
  return function () {
    count = count + 1;
    console.log(count);
  };
}
button.addEventListener("click", makeCounter());
```

**Why:** `makeCounter()` runs once during setup and returns a function. That returned function is registered; it retains access to `count`. This is an important exception to the simplistic rule that parentheses are always wrong: a function *factory* may intentionally return the callback.

### Exercise 8: Remove a named listener

**Task:** Add and remove a click listener using the same reference.

**Solution:**

```javascript
const button = document.getElementById("myButton");
function handleClick() { console.log("Clicked"); }
button.addEventListener("click", handleClick);
button.removeEventListener("click", handleClick);
```

**Why:** Matching type, callback identity, and capture setting allows removal.

### Exercise 9: Use a one-time listener

**Task:** Run a callback only once.

**Solution:**

```javascript
const button = document.getElementById("myButton");
button.addEventListener("click", function () {
  console.log("Only once");
}, { once: true });
```

**Why:** The browser automatically removes the listener after its first invocation.

### Exercise 10: Group cleanup with AbortController

**Task:** Register two listeners and remove both together.

**Solution:**

```javascript
const button = document.getElementById("myButton");
const controller = new AbortController();
button.addEventListener("click", () => console.log("One"), {
  signal: controller.signal
});
button.addEventListener("click", () => console.log("Two"), {
  signal: controller.signal
});
function disableBoth() {
  controller.abort();
}
```

**Why:** Both registrations share the same `AbortSignal`. Calling `disableBoth()` removes both. An aborted controller cannot be reused to register new listeners; create a new controller when re-enabling.

## 29. Common mistakes checklist

- [ ] Do not accidentally call a callback during registration (`handler()` vs `handler`).
- [ ] Remember that a factory function returning a callback is a valid special case.
- [ ] Use quoted event type strings (`"click"`, not an undefined `click` variable).
- [ ] Event type strings are case-sensitive.
- [ ] Do not assume `onclick` and `addEventListener()` behave identically.
- [ ] Do not expect a second `onclick = ...` assignment to preserve the first callback.
- [ ] Do not assume two anonymous functions with identical source are the same object.
- [ ] Preserve function references when cleanup is required.
- [ ] Do not assume returning `false` from an added listener prevents default behavior.
- [ ] Use `event.currentTarget` when the current listener target is needed.
- [ ] Check for `null` when DOM selectors may fail.
- [ ] Avoid inline JavaScript when CSP, maintainability, and testing matter.
- [ ] Use semantic controls and keyboard-accessible interactions.
- [ ] Clean up listeners when long-lived targets outlive the relevant view.

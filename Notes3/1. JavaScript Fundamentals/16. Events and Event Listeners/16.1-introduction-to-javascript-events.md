## 1. What is a JavaScript event?

An **event** is a notification that something happened in a web page, browser, or another event-capable system. Events may originate from user interactions, browser operations, or programmatic dispatch.

Examples:
- A user clicks a button.
- A user types into a field.
- A form is submitted.
- The pointer moves.
- A keyboard key is pressed.
- An image finishes loading.
- A video starts playing.
- The browser reports a network status change.

HTML:

```html
<button id="myButton" type="button">Click Me</button>
```

JavaScript:

```javascript
const button = document.getElementById("myButton");

button.addEventListener("click", function () {
  console.log("Button clicked!");
});
```

**Execution:** When the page script runs, the listener is registered. It does not log anything yet. When a click event is dispatched to the button, the browser invokes the callback, printing `Button clicked!`.

### Try it yourself

Create `index.html` with the button and `script.js` with the JavaScript, or paste the code into an HTML page's script after the button. Open DevTools > Console and click the button several times. Each handled click logs one message.

## 2. Why do we need JavaScript events?

HTML provides structure; CSS provides presentation; JavaScript provides behavior. Event handlers let JavaScript respond to user and browser actions instead of modifying a page only when the script initially loads.

```html
<h1 id="heading">Welcome</h1>
<button id="changeButton" type="button">Change Heading</button>
```

```javascript
const heading = document.getElementById("heading");
const button = document.getElementById("changeButton");

button.addEventListener("click", function () {
  heading.textContent = "Heading Changed!";
});
```

Event flow (ASCII):

```text
User activates button
        |
        v
Browser dispatches click event
        |
        v
Registered listener runs
        |
        v
heading.textContent changes
        |
        v
Page displays new heading
```

Events enable interactive forms, menus, media players, games, dashboards, editors, and accessible controls.

## 3. Event-driven programming

In ordinary sequential code, statements run in order:

```javascript
console.log("Step 1");
console.log("Step 2");
console.log("Step 3");
```

Output:

```text
Step 1
Step 2
Step 3
```

In event-driven code, callbacks are registered for later execution:

```javascript
console.log("Program started");

const button = document.querySelector("button");

button.addEventListener("click", function () {
  console.log("Button clicked");
});

console.log("Program ready");
```

Before any click:

```text
Program started
Program ready
```

After one click, an additional line appears:

```text
Button clicked
```

### Execution trace

| Step | Operation | Result |
| --- | --- | --- |
| 1 | First `console.log()` | Prints `Program started` |
| 2 | `querySelector("button")` | Returns button or `null` |
| 3 | Evaluate `function () {...}` | Creates callback function object |
| 4 | `addEventListener(...)` | Registers callback for click events |
| 5 | Last `console.log()` | Prints `Program ready` |
| 6 | A click is dispatched | Event delivery begins |
| 7 | Callback executes | Prints `Button clicked` |

**Key distinction:** Registering a callback does not call it. The browser does not continually rerun the whole script to check for clicks.

## 4. Components of an event

| Concept | Meaning |
| --- | --- |
| Event | Notification that something occurred |
| Event type | Category, such as `click` |
| Event target | Object on which an event was dispatched |
| Event listener | Registered callback for an event type |
| Event handler | Function responding to an event |
| Event object | Data describing the event |
| Event dispatch | Delivery of an event through the event system |

```javascript
const button = document.getElementById("myButton");

button.addEventListener("click", function (event) {
  console.log(event.type);
});
```

For a click, `event.type` is the string `"click"`. The browser supplies `event` when invoking the callback.

## 6. Line-by-line JavaScript breakdown

### Line 1: select the heading

```javascript
const heading = document.getElementById("heading");
```

| Token | Explanation |
| --- | --- |
| `const` | Declares a binding that cannot be reassigned |
| `heading` | Variable name |
| `=` | Assignment operator |
| `document` | Browser-provided document object |
| `.` | Accesses a property or method |
| `getElementById` | Method that looks up an element by ID |
| `(` | Starts argument list |
| `"heading"` | String argument specifying the ID |
| `)` | Ends argument list |
| `;` | Ends statement |

**Trace:** Read `document` -> access method -> pass ID string -> look up element -> return element or `null` -> assign reference to `heading`.

### Line 2: select the button

```javascript
const button = document.getElementById("changeButton");
```

The same steps select the button. If no matching element exists, `button` becomes `null`, and calling `button.addEventListener(...)` would throw a `TypeError`.

### Line 3: register the listener

```javascript
button.addEventListener("click", function () {
  heading.textContent = "Heading Changed!";
});
```

| Token | Explanation |
| --- | --- |
| `button` | DOM element reference |
| `.` | Property/method access |
| `addEventListener` | Registers an event listener |
| `(` | Starts method arguments |
| `"click"` | First argument: event type string |
| `,` | Separates arguments |
| `function` | Creates a regular function |
| `()` | Empty parameter list |
| `{` | Opens function body |
| `heading.textContent` | Heading's text content property |
| `=` | Assigns a replacement value |
| `"Heading Changed!"` | New string value |
| `;` | Ends inner statement |
| `}` | Closes function body |
| `)` | Closes method call |
| `;` | Ends registration statement |

**Registration-time trace:** JavaScript creates the callback function and passes it to `addEventListener`. The assignment to `textContent` has **not** happened yet.

**Click-time trace:** Browser dispatches `click` -> registered callback executes -> evaluates `heading.textContent` assignment -> heading updates.

### Why does `"click"` need quotes?

`"click"` is a string literal. Without quotes, `click` would be treated as a variable name and usually cause `ReferenceError` if no such binding exists.

### Why is there a comma?

The comma separates the first argument (`"click"`) from the second argument (the function object). It does not join strings or run the callback.

## 7. What is an event listener?

An event listener is a callback registered on an `EventTarget` for a given event type.

```javascript
element.addEventListener(eventType, callback);
```

Example:

```javascript
button.addEventListener("click", function () {
  console.log("Hello");
});
```

The callback can run repeatedly on later matching events. `addEventListener()` does **not** invoke the callback during registration.

**Important nuance:** Calling `addEventListener()` again with the *same callback object*, same type, and same capture setting does not create a duplicate listener. Two distinct anonymous function objects are distinct callbacks and can both be registered.

---

## 8. What is an event handler?

An event handler is a function that responds to an event.

```javascript
function showMessage() {
  console.log("Hello World");
}

button.addEventListener("click", showMessage);
```

### Function reference vs function call

Correct:

```javascript
button.addEventListener("click", showMessage);
```

`showMessage` evaluates to the function object. It is passed as the listener.

Incorrect for this goal:

```javascript
button.addEventListener("click", showMessage());
```

`showMessage()` immediately invokes the function. In this example it prints `Hello World` immediately and returns `undefined`. The `undefined` callback does not register `showMessage` as a click listener.

| Expression | What happens now? | What happens on click? |
| --- | --- | --- |
| `showMessage` | Passes function reference | Handler runs |
| `showMessage()` | Calls function immediately | No `showMessage` listener registered here |

### Callback terminology

A **callback** is a function supplied to other code so that other code can invoke it at an appropriate time. In event handling, the browser event system invokes the registered callback.

## 9. Ways to handle events

### 9.1 Inline HTML handler attribute

```html
<button onclick="alert('Hello')">Click Me</button>
```

It works but mixes behavior into markup. Inline handler attributes are generally discouraged for maintainability and can conflict with strict Content Security Policies.

### 9.2 Event handler property

```javascript
const button = document.querySelector("button");

button.onclick = function () {
  console.log("Clicked");
};
```

Assigning a new function to `onclick` replaces the previous property handler:

```javascript
button.onclick = function () { console.log("First"); };
button.onclick = function () { console.log("Second"); };
```

The second assignment replaces the first property handler.

### 9.3 addEventListener()

```javascript
button.addEventListener("click", function () {
  console.log("First");
});

button.addEventListener("click", function () {
  console.log("Second");
});
```

Both distinct callbacks are registered and normally run in registration order for this simple example.

| Approach | Multiple independent listeners? | General guidance |
| --- | --- | --- |
| Inline attribute | Not via one attribute | Usually avoid |
| `onclick` property | One property handler | Fine for simple cases |
| `addEventListener()` | Yes | Preferred for most applications |

## 11. Understanding the event object

The browser passes an event object to an event listener when it invokes the callback.

```javascript
button.addEventListener("click", function (event) {
  console.log(event.type);
  console.log(event.target);
  console.log(event.currentTarget);
});
```

| Property | Meaning |
| --- | --- |
| `event.type` | Event type string |
| `event.target` | Original event target |
| `event.currentTarget` | Target whose listener is currently running |
| `event.timeStamp` | Event timestamp |
| `event.bubbles` | Whether event bubbles |
| `event.cancelable` | Whether default action can be canceled |

### Is `event` a keyword?

No. It is a function parameter name.

```javascript
button.addEventListener("click", function (e) {
  console.log(e.type);
});
```

`e` and `event` are both valid parameter names. The browser supplies the argument when invoking the listener.

### What happens to `event.target` and `event.currentTarget`?

For a click directly on the button with a listener on that same button, they are often the same element. They can differ when a listener is attached to an ancestor and the event originated on a descendant. Later lessons cover propagation and delegation.

## 12. Arrow functions as handlers

Regular function:

```javascript
button.addEventListener("click", function () {
  console.log("Clicked");
});
```

Arrow function:

```javascript
button.addEventListener("click", () => {
  console.log("Clicked");
});
```

| Token | Meaning |
| --- | --- |
| `()` | Empty parameter list |
| `=>` | Arrow function syntax |
| `{` | Starts body |
| `console.log(...)` | Runs when callback is invoked |
| `}` | Ends body |

**Important difference:** A regular listener function has a `this` value associated with the event target when invoked by the event system; an arrow function inherits `this` from its surrounding lexical scope. We will study `this` in dedicated lessons.

## 13. Practical example - click counter

### Complete runnable HTML

Save as `click-counter.html`:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Click Counter</title>
  <style>
    body { font-family: Arial, sans-serif; padding: 24px; }
    button { padding: 10px 16px; cursor: pointer; }
    #countDisplay { font-size: 2rem; }
  </style>
</head>
<body>
  <h1>Click Counter</h1>
  <p id="countDisplay">0</p>
  <button id="countButton" type="button">Increase Count</button>

  <script>
    const countDisplay = document.getElementById("countDisplay");
    const countButton = document.getElementById("countButton");
    let count = 0;

    countButton.addEventListener("click", function () {
      count = count + 1;
      countDisplay.textContent = count;
    });
  </script>
</body>
</html>
```

### Break down `let count = 0;`

- `let` declares a binding that can be reassigned.
- `count` is its identifier.
- `=` assigns the initial value.
- `0` is a number literal.
- `;` ends the statement.

### Break down `count = count + 1;`

- Right-hand `count` reads the current number.
- `+` adds one.
- Left-hand `count =` assigns the result back to the variable.

If `count` is 2: read 2 -> compute `2 + 1` -> result 3 -> store 3.

Equivalent alternatives:

```javascript
count += 1;
count++;
```

For beginner traces, the expanded form is easiest to follow.

### Trace

| Click | Before | Calculation | After | Display |
| --- | ---: | --- | ---: | --- |
| First | 0 | `0 + 1` | 1 | `1` |
| Second | 1 | `1 + 1` | 2 | `2` |
| Third | 2 | `2 + 1` | 3 | `3` |
| Fourth | 3 | `3 + 1` | 4 | `4` |

## 14. Practical example - text input

### Complete runnable HTML

Save as `live-input.html`:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Live Text Input</title>
  <style>
    body { font-family: Arial, sans-serif; padding: 24px; }
    input { padding: 8px; }
  </style>
</head>
<body>
  <label for="nameInput">Your name</label>
  <input id="nameInput" type="text">
  <p id="output" aria-live="polite"></p>

  <script>
    const nameInput = document.getElementById("nameInput");
    const output = document.getElementById("output");

    nameInput.addEventListener("input", function () {
      output.textContent = nameInput.value;
    });
  </script>

</html>
```

### Breakdown

- `nameInput.value` reads the current input value (usually a string).
- `output.textContent` is the output paragraph's text.
- `=` assigns the input value to the output text.
- The `input` event is dispatched when the user changes the value through relevant interactions.
- `aria-live="polite"` asks assistive technologies to announce relevant changes when appropriate; frequent announcements should be designed thoughtfully.

**Trace:** Type `A` -> input event -> value `"A"` -> output `A`; type `l` -> next input event -> value `"Al"` -> output `Al`.

## 15. Practical example - mouse enter and leave

### Complete runnable HTML

Save as `hover-box.html`:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mouse Enter and Leave</title>

    });

    box.addEventListener("mouseleave", function () {
      box.style.backgroundColor = "white";
```

### Breakdown

- `.backgroundColor` is the JavaScript property for CSS `background-color`.
- Assigning `"lightblue"` changes the inline background style.

Do not make essential actions hover-only; touch and keyboard users may not have a mouse hover interaction.

## 16. Multiple event listeners

An element can listen for multiple event types:

```javascript
const button = document.getElementById("myButton");

button.addEventListener("click", function () {
  console.log("Clicked");
});

button.addEventListener("mouseenter", function () {
  console.log("Mouse entered");
});

button.addEventListener("mouseleave", function () {
  console.log("Mouse left");
});
```

Different elements can also have different listeners:

```javascript
const firstButton = document.getElementById("firstButton");
const secondButton = document.getElementById("secondButton");

firstButton.addEventListener("click", function () {
  console.log("First button clicked");
});

secondButton.addEventListener("click", function () {
  console.log("Second button clicked");
});
```

### Two listeners for one event

```javascript
button.addEventListener("click", function () {
  console.log("First listener");
});

button.addEventListener("click", function () {
  console.log("Second listener");
});
```

One click normally prints both lines. These are different anonymous function objects.

## 17. Event execution order

```javascript
console.log("A");

button.addEventListener("click", function () {
  console.log("B");
});

console.log("C");
```

Before a click:

```text
A
C
```

After a click, the console also shows:

```text
B
```

**Why?** `addEventListener()` registers a function. It does not invoke it. The callback runs when the event system dispatches a matching event. This example does not require the callback to run between the two ordinary log statements.

**Nuance:** Events can also be dispatched programmatically, sometimes synchronously, using `dispatchEvent()`. Therefore, not every event callback is inherently asynchronous. Later lessons distinguish event dispatch, the event loop, tasks, and microtasks.

## 18. Common beginner mistakes

| Mistake | Why it is wrong | Correction |
| --- | --- | --- |
| `addEventListener("click", showMessage())` | Calls function during registration | Pass `showMessage` |
| `"clicked"` instead of `"click"` | Wrong event type | Use supported event name |
| Element selection returns `null` | Wrong ID or script timing | Check ID and use `defer` or proper script placement |
| Expecting callback immediately | Registration is not invocation | Wait for dispatch |
| `const count = 0; count = count + 1` | Reassigning `const` throws | Use `let` |
| `addEventListener(click, ...)` | Unquoted `click` treated as identifier | Use `"click"` |
| Reassigning `onclick` repeatedly | Previous property handler replaced | Use `addEventListener()` |
| Assuming all events come from users | Browser and scripts also dispatch events | Understand sources |
| Thinking listeners are polling loops | Event system invokes callbacks | Understand registration and dispatch |
| Ignoring console errors | Makes debugging difficult | Inspect DevTools Console |

## 19. 10 interview questions and answers

### 1. What is a JavaScript event?

**Answer:** An event is a notification that an occurrence has taken place, such as a user interaction, a resource load, or a browser state change. Code can respond through event listeners.

### 2. What is event-driven programming?

**Answer:** It is an approach in which code registers handlers that respond to events instead of relying only on a predetermined sequence of operations.

### 3. What is an event listener?

**Answer:** A callback registered on an event target for a particular event type. The callback can execute when matching events are dispatched.

### 4. What is an event handler?

**Answer:** A function that responds to an event. It can be registered with `addEventListener()` or other supported event-handler mechanisms.

### 5. What does `addEventListener()` do?

**Answer:** It registers a callback for an event type on an `EventTarget`. It does not immediately call the callback.

### 6. Why use `showMessage` instead of `showMessage()`?

**Answer:** `showMessage` is a function reference. `showMessage()` immediately invokes the function and evaluates to its return value. Event registration usually needs the function itself.

### 7. What is the event object?

**Answer:** An object supplied to a listener that describes the event, including its type, target, and other properties.

### 8. What is the difference between `onclick` and `addEventListener()`?

**Answer:** `onclick` is an event-handler property whose assignment replaces its previous property handler. `addEventListener()` supports multiple independently registered callbacks.

### 9. Can one element handle multiple events?

**Answer:** Yes. A button can have listeners for `click`, `mouseenter`, `mouseleave`, `keydown`, and other applicable event types.

### 10. Does `addEventListener()` immediately execute the callback?

**Answer:** No. It registers the callback. The callback executes when a matching event is dispatched and reaches that listener.

## 20. 10 coding exercises with full solutions

Each exercise assumes the named HTML element exists before the JavaScript executes. Try to solve it before reading the solution.

### Exercise 1 - Display a message when clicked

**Task:** Select `#messageButton` and log `Hello JavaScript` on click.

**Solution:**

```javascript
const button = document.getElementById("messageButton");

button.addEventListener("click", function () {
  console.log("Hello JavaScript");
});
```

**Explanation:** Select the element, register a `click` listener, and log the message inside the callback. The message is not logged at registration time.

### Exercise 2 - Change a heading

**Task:** Clicking `#changeButton` changes `#heading` to `Updated Heading`.

**Solution:**

```javascript
const button = document.getElementById("changeButton");
const heading = document.getElementById("heading");

button.addEventListener("click", function () {
  heading.textContent = "Updated Heading";
});
```

**Explanation:** `textContent` is a property. The `=` operator assigns a new string when the listener runs.

### Exercise 3 - Click counter

**Task:** Increase a number each time `#countButton` is clicked.

**Solution:**

```javascript
const button = document.getElementById("countButton");
let count = 0;

button.addEventListener("click", function () {
  count = count + 1;
  console.log(count);
});
```

**Explanation:** `let` allows reassignment. Each click reads the previous value, adds one, and stores the result. Trace: 0 -> 1 -> 2 -> 3.

### Exercise 4 - Log event type

**Task:** Print the event type when `#myButton` is clicked.

**Solution:**

```javascript
const button = document.getElementById("myButton");

button.addEventListener("click", function (event) {
  console.log(event.type);
});
```

**Explanation:** The browser passes the event object to the callback's `event` parameter. Its `type` is `"click"`.

### Exercise 5 - Named callback

**Task:** Create a `showMessage()` function and register it without immediately calling it.

**Solution:**

```javascript
function showMessage() {
  console.log("Welcome");
}

const button = document.getElementById("myButton");
button.addEventListener("click", showMessage);
```

**Explanation:** No parentheses after `showMessage` in the registration statement: the function reference is passed.

### Exercise 6 - Arrow function handler

**Task:** Register an arrow function that logs `Clicked`.

**Solution:**

```javascript
const button = document.getElementById("myButton");

button.addEventListener("click", () => {
  console.log("Clicked");
});
```

**Explanation:** `()` is the empty parameter list, `=>` introduces the arrow function, and `{...}` contains its body.

### Exercise 7 - Respond to input

**Task:** Display the value of `#nameInput` inside `#output` as the user types.

**Solution:**

```javascript
const input = document.getElementById("nameInput");
const output = document.getElementById("output");

input.addEventListener("input", function () {
  output.textContent = input.value;
});
```

**Explanation:** `input.value` reads the current string. Assigning it to `output.textContent` updates the paragraph safely as text.

### Exercise 8 - Mouse enter

**Task:** Change `#box` background to yellow on mouse entry.

**Solution:**

```javascript
const box = document.getElementById("box");

box.addEventListener("mouseenter", function () {
  box.style.backgroundColor = "yellow";
});
```

**Explanation:** The `mouseenter` callback runs when the mouse enters. The inline `backgroundColor` style is assigned a new value.

### Exercise 9 - Two click listeners

**Task:** Print `First` and `Second` from separate click listeners on the same button.

**Solution:**

```javascript
const button = document.getElementById("myButton");

button.addEventListener("click", function () {
  console.log("First");
});

button.addEventListener("click", function () {
  console.log("Second");
});
```

**Explanation:** Each function expression creates a distinct callback. Both can be registered for the same event type.

### Exercise 10 - Toggle ON/OFF

**Task:** Toggle a paragraph between `ON` and `OFF` on each button click.

**Solution:**

```javascript
const button = document.getElementById("toggleButton");
const output = document.getElementById("output");
let isOn = false;

button.addEventListener("click", function () {
  isOn = !isOn;
  output.textContent = isOn ? "ON" : "OFF";
});
```

**Detailed breakdown:**

- `let isOn = false;` starts with a boolean value.
- `!isOn` is logical NOT. `!false` becomes `true`; `!true` becomes `false`.
- `isOn = !isOn;` assigns the opposite boolean back to `isOn`.
- `condition ? valueIfTrue : valueIfFalse` is the ternary conditional expression.
- `isOn ? "ON" : "OFF"` produces `"ON"` if `isOn` is true, otherwise `"OFF"`.
- `output.textContent = ...` updates the displayed text.

Trace:

| Click | `isOn` before | `!isOn` | `isOn` after | Display |
| --- | --- | --- | --- | --- |
| First | `false` | `true` | `true` | ON |
| Second | `true` | `false` | `false` | OFF |
| Third | `false` | `true` | `true` | ON |

Equivalent `if...else`:

```javascript
if (isOn) {
  output.textContent = "ON";
} else {
  output.textContent = "OFF";
}
```

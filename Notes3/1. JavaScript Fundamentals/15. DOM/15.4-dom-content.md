## Learning objectives

By the end, you should be able to read and change text and markup, distinguish rendered text from underlying text nodes, insert content at four positions, create text nodes, replace children, recognize HTML injection risks, and explain each operator and method call step by step.

## 1. Understanding DOM content

```html
<div id="container">
  <h2>Hello</h2>
  <p>Welcome to JavaScript</p>
</div>
```

Simplified tree (whitespace text nodes omitted):

```text
div#container
|-- h2
|   \-- Text: Hello
\-- p
    \-- Text: Welcome to JavaScript
```

**Text content** means text in nodes. **HTML markup** means serialized tags and their contents. **Rendered text** means text as reflected by layout and CSS. Different APIs expose different views.

## 2. textContent

**Syntax:**

```javascript
element.textContent;              // Read
element.textContent = "New text"; // Write
```

**Example:**

```html
<p id="message">Hello</p>
```

```javascript
const message = document.getElementById("message");
console.log(message.textContent); // Hello
message.textContent = "Welcome";
```

**Detailed breakdown of `message.textContent = "Welcome";`:**

| Token | Meaning |
|---|---|
| `message` | Variable referring to a DOM element |
| `.` | Property access operator |
| `textContent` | Property holding node text content |
| `=` | Assignment operator |
| `"Welcome"` | String value |
| `;` | Statement terminator |

**Execution trace:**

1. Resolve `message` to the paragraph element.
2. Access its `textContent` setter.
3. Supply the string `"Welcome"`.
4. Replace existing child nodes with text.
5. Browser reflects the changed DOM on screen.

Reading an element's `textContent` combines text from descendants, including hidden text and source whitespace. Assigning it **replaces** children rather than appending.

```html
<div id="container"><h2>Old heading</h2><p>Old paragraph</p></div>
```

```javascript
const container = document.getElementById("container");
container.textContent = "New content";
// The h2 and p are removed from this div.
```

**Literal markup demonstration:**

```javascript
message.textContent = "<strong>Hello</strong>";
```

The page displays the literal text `<strong>Hello</strong>`; no `strong` element is created. Prefer `textContent` for untrusted text.

## 3. innerText

`innerText` reads or sets text with rendered layout taken into account.

```javascript
const message = document.getElementById("message");
console.log(message.innerText);
message.innerText = "Updated";
```

**Hidden-content example:**

```html
<div id="container">
  <p>Visible text</p>
  <p style="display: none">Hidden text</p>
</div>
```

```javascript
const container = document.getElementById("container");
console.log(container.textContent); // Includes both text strings and whitespace
console.log(container.innerText);   // Typically just "Visible text"
```

`innerText` depends on rendering. If the element itself is not rendered, the getter may behave more like `textContent`. It is not a general-purpose visibility test. Reading `innerText` can require layout calculation.

```javascript
container.innerText = "First line\nSecond line";
```

Setting `innerText` can turn newline characters into line-break elements. Setting `textContent` creates text containing newline characters; CSS determines how those appear.

## 4. textContent vs innerText

| Behavior | `textContent` | `innerText` |
|---|---|---|
| Reflects underlying text nodes | Yes | Rendered-text view |
| Includes hidden descendant text | Yes | Usually not when rendered ancestor is visible |
| Depends on CSS/layout | No | Yes |
| Includes source whitespace | Yes | Uses rendered-text rules |
| Interprets assigned HTML | No | No |
| Typical use | General text handling | Text as shown to user |

**Practice:** Predict the two outputs before running the hidden-content example above in your browser console.

## 5. innerHTML

`innerHTML` reads or replaces the **HTML markup inside** an element.

```html
<div id="container"></div>
```

```javascript
const container = document.getElementById("container");
container.innerHTML = "<h2>Hello JavaScript</h2>";
```

**Token breakdown:**

| Token | Meaning |
|---|---|
| `container` | Element reference |
| `.` | Property access |
| `innerHTML` | HTML-fragment getter/setter |
| `=` | Assignment |
| `"<h2>Hello JavaScript</h2>"` | String to parse as HTML |

**Execution trace:**

1. Locate the `div` element.
2. Evaluate the HTML string.
3. Parse the string as an HTML fragment.
4. Create a new `h2` element and its text node.
5. Replace the div's previous children.
6. Render the new heading.

**Reading markup:**

```html
<div id="container"><strong>Hello</strong></div>
```

```javascript
console.log(container.innerHTML); // <strong>Hello</strong>
```

Serialization may not reproduce the original source whitespace or quote style exactly.

**Template literals:**

```javascript
const name = "Alex";
const greeting = `Hello, ${name}`; // "Hello, Alex"
container.innerHTML = `
  <h2>Products</h2>
  <p>Available products</p>
`;
```

Backticks delimit a template literal. `${name}` evaluates and interpolates the variable. Multiline template literals preserve line breaks.

## 6. HTML injection and XSS

**Do not assign untrusted HTML to `innerHTML`.** The browser parses it, and malicious event-handler attributes can execute code.

```javascript
const userInput = '<img src="invalid" onerror="alert(1)">';
container.innerHTML = userInput; // Unsafe: demonstration only
```

The fact that inserted `<script>` tags often do not execute does **not** make this safe.

**Safer when displaying text:**

```javascript
container.textContent = userInput;
```

When genuinely accepting HTML, use an appropriate maintained HTML sanitizer (for example, DOMPurify) and applicable browser security controls. Do not invent a sanitizer from a few regular expressions.

| Input | Recommended handling |
|---|---|
| Product name | `textContent` |
| User comment | `textContent` |
| Trusted static markup | `innerHTML` may be appropriate |
| Untrusted rich HTML | Sanitize before HTML insertion |
| Dynamic text and elements | `createElement()` + `textContent` |

## 7. outerHTML

`outerHTML` includes the selected element's own tag and all descendant markup.

```html
<div id="container"><p>Hello</p></div>
```

```javascript
const container = document.getElementById("container");
console.log(container.innerHTML); // <p>Hello</p>
console.log(container.outerHTML); // <div id="container"><p>Hello</p></div>
```

Assigning `outerHTML` replaces the selected element in its parent:

```javascript
container.outerHTML = '<section id="newSection">Hello</section>';
```

**Reference trap:** `container` still refers to the old, detached `div`, not the replacement section. To access the replacement:

```javascript
const newSection = document.getElementById("newSection");
```

Like `innerHTML`, assigning untrusted markup to `outerHTML` risks XSS.

## 8. innerHTML vs outerHTML

```text
Original:
<div id="container">
  <p>Old</p>
</div>

innerHTML = "<p>New</p>"
  -> div remains; its children change.

outerHTML = "<section>New</section>"
  -> div itself is replaced by section.
```

| Feature | `innerHTML` | `outerHTML` |
|---|---|---|
| Getter includes selected element tag | No | Yes |
| Setter replaces children | Yes | No |
| Setter replaces selected element | No | Yes |
| Parses HTML string | Yes | Yes |

## 9. insertAdjacentText

**Syntax:**

```javascript
element.insertAdjacentText(position, text);
```

| Argument | Purpose |
|---|---|
| `position` | One of four position strings |
| `text` | Text to insert, not HTML markup |

Positions:

```text
beforebegin
<element>
    afterbegin
    existing children
    beforeend
</element>
afterend
```

**Example:**

```html
<p id="message">World</p>
```

```javascript
const message = document.getElementById("message");
message.insertAdjacentText("afterbegin", "Hello ");
// The paragraph now displays: Hello World
```

**Step-by-step:** Resolve `message`; call its `insertAdjacentText` method; pass the insertion position and text; insert a text node at that location; preserve existing child elements. The return value is `undefined`.

```javascript
message.insertAdjacentText("beforebegin", "Before"); // Sibling before p
message.insertAdjacentText("afterbegin", "Start ");   // First child
message.insertAdjacentText("beforeend", " End");     // Last child
message.insertAdjacentText("afterend", "After");      // Sibling after p
```

The outside positions require an appropriate parent node.

## 10. insertAdjacentHTML

**Syntax:**

```javascript
element.insertAdjacentHTML(position, htmlString);
```

```html
<ul id="list"><li>Apple</li></ul>
```

```javascript
const list = document.getElementById("list");
list.insertAdjacentHTML("beforeend", "<li>Banana</li>");
```

This parses and inserts a fragment without rebuilding existing children. In contrast:

```javascript
list.innerHTML += "<li>Banana</li>";
```

reads the current markup, concatenates the string, and reassigns `innerHTML`, potentially replacing existing descendants and their directly attached event listeners. `insertAdjacentHTML` is also unsafe with untrusted HTML.

## 11. createTextNode

**Syntax:**

```javascript
document.createTextNode(data);
```

```javascript
const paragraph = document.createElement("p");
const textNode = document.createTextNode("Hello JavaScript");
paragraph.appendChild(textNode);
document.body.appendChild(paragraph);
```

**Trace:**

1. `createElement("p")` creates a detached paragraph element.
2. `createTextNode("Hello JavaScript")` creates a detached text node.
3. `paragraph.appendChild(textNode)` makes the text node a child of the paragraph.
4. `document.body.appendChild(paragraph)` inserts the paragraph into the page.

Text nodes are not HTML elements. Their text is not parsed as markup.

## 12. replaceChildren

**Syntax:**

```javascript
element.replaceChildren(...nodesOrStrings);
```

Here `...nodesOrStrings` is documentation notation meaning zero or more arguments. Ordinary calls do not need literal dots.

```javascript
container.replaceChildren("Hello"); // Replaces children with text
```

```javascript
const heading = document.createElement("h2");
heading.textContent = "New heading";
const paragraph = document.createElement("p");
paragraph.textContent = "New paragraph";
container.replaceChildren(heading, paragraph);
```

To clear all children:

```javascript
container.replaceChildren();
```

Other common clearing approaches:

```javascript
container.textContent = "";
container.innerHTML = "";
```

Prefer `replaceChildren()` or `textContent = ""` for simple clearing without HTML parsing.

## 13. Compound assignment with +=

```javascript
message.textContent += " World";
```

This is approximately equivalent to:

```javascript
message.textContent = message.textContent + " World";
```

**Execution trace:**

| Step | Value |
|---|---|
| Initial `textContent` | `"Hello"` |
| Read property | `"Hello"` |
| Concatenate `" World"` | `"Hello World"` |
| Assign new value | `"Hello World"` |

**Crucial detail:** This replaces the element's children. If the element contains nested tags, they are removed. To insert without replacing child elements:

```javascript
message.append(" World");
// or
message.insertAdjacentText("beforeend", " World");
```

## 14. null, undefined, and empty strings

| Value | Meaning |
|---|---|
| `null` | Intentional absence; often returned when no element matches |
| `undefined` | Value commonly returned for missing properties or no explicit return |
| `""` | A valid string with zero characters |

```javascript
const missing = document.querySelector("#missing");
console.log(missing); // null
```

```html
<p id="message"></p>
```

```javascript
const message = document.getElementById("message");
console.log(message.textContent); // ""
```

**Safe access:**

```javascript
if (message !== null) {
  console.log(message.textContent);
}
```

```javascript
console.log(message?.textContent);
```

The `?.` optional-chaining operator returns `undefined` if `message` is `null` or `undefined`, rather than trying to read the property.

## 15. Whitespace and trim

```html
<p id="message">
  Hello JavaScript
</p>
```

```javascript
const message = document.getElementById("message");
console.log(message.textContent);        // Includes source whitespace
console.log(message.textContent.trim()); // "Hello JavaScript"
```

**Trace of `message.textContent.trim()`:**

1. Resolve `message` to an element.
2. Read the `textContent` string.
3. Access the string's `trim()` method.
4. Call `trim()`; it returns a **new** string with leading/trailing whitespace removed.
5. Original DOM content is unchanged unless you assign the result.

```javascript
message.textContent = message.textContent.trim();
```

## 16. Content replacement and event listeners

```html
<div id="container"><button id="actionButton">Click</button></div>
```

```javascript
const button = document.getElementById("actionButton");
button.addEventListener("click", function () {
  console.log("Clicked");
});
const container = document.getElementById("container");
container.innerHTML = '<button id="actionButton">Click</button>';
```

The old button is removed and a new button is created. The event listener attached directly to the old button is **not** automatically transferred. Prefer insertion methods that preserve existing nodes when their state or listeners matter.

## 17. Project: Safe message preview

Create two files in one folder.

**index.html:**

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Message Preview</title>
  <script src="script.js" defer></script>
</head>
<body>
  <h1>Message Preview</h1>
  <textarea id="messageInput"></textarea>
  <button id="previewButton">Preview</button>
  <button id="clearButton">Clear</button>
  <h2>Preview</h2>
  <div id="preview"></div>
</body>
</html>
```

**script.js:**

```javascript
const messageInput = document.getElementById("messageInput");
const previewButton = document.getElementById("previewButton");
const clearButton = document.getElementById("clearButton");
const preview = document.getElementById("preview");

previewButton.addEventListener("click", function () {
  const message = messageInput.value.trim();

  if (message === "") {
    preview.textContent = "Please enter a message.";
    return;
  }

  preview.textContent = message;
});

clearButton.addEventListener("click", function () {
  messageInput.value = "";
  preview.replaceChildren();
});
```

**Line-by-line execution when Preview is clicked:**

1. The browser dispatches a click event to the Preview button.
2. The registered callback function runs.
3. `messageInput.value` reads the textarea's current string.
4. `.trim()` removes leading/trailing whitespace and returns a new string.
5. `const message = ...` stores that string.
6. `message === ""` checks strict equality with an empty string.
7. If empty, the warning is displayed and `return` exits the callback.
8. Otherwise `preview.textContent = message` displays the text safely.

**Try this input:**

```text
Hello <strong>JavaScript</strong>
```

**Expected preview:** The literal characters `Hello <strong>JavaScript</strong>`, not a bold HTML element.

**Operator breakdown:**

| Syntax | Explanation |
|---|---|
| `.value` | Reads current form-control value |
| `.trim()` | Returns a new trimmed string |
| `===` | Strict equality comparison |
| `if (...)` | Runs its body if condition is truthy |
| `return;` | Exits the current function immediately |
| `addEventListener("click", callback)` | Registers callback for click events |
| `replaceChildren()` | Removes all child nodes |

## 18. Project: Announcement board

**HTML:**

```html
<h1>Announcements</h1>
<input id="announcementInput" type="text">
<button id="addAnnouncement">Add</button>
<div id="announcements"></div>
```

**JavaScript:**

```javascript
const input = document.getElementById("announcementInput");
const addButton = document.getElementById("addAnnouncement");
const announcements = document.getElementById("announcements");

addButton.addEventListener("click", function () {
  const text = input.value.trim();
  if (text === "") {
    return;
  }

  const article = document.createElement("article");
  const paragraph = document.createElement("p");
  paragraph.textContent = text;
  article.appendChild(paragraph);
  announcements.appendChild(article);
  input.value = "";
});
```

**Execution trace:** Input is read and trimmed; empty input exits; an `article` and `p` are created; the text is assigned safely; the paragraph is appended to the article; the article is appended to the document; the input is cleared.

**Why not `innerHTML`?** User-entered text should not be interpreted as markup. Creating elements separately preserves existing announcements and reduces HTML injection risk.

## 19. Common mistakes

| Mistake | Problem | Correction |
|---|---|---|
| `innerHTML` for user text | XSS risk | Use `textContent` |
| Assigning `textContent` to append | Replaces children | Use `append()` or `insertAdjacentText()` |
| Assuming `innerText` equals `textContent` | Rendered-text differences | Choose intentionally |
| Assuming `outerHTML` updates a variable | Old reference remains | Re-select replacement |
| Repeated `innerHTML +=` | Replaces existing descendants | Use insertion APIs |
| Reading content on `null` | Throws error | Check result first |
| Assuming `trim()` mutates DOM | Returns a new string | Assign result explicitly |
| Confusing markup with text | Unexpected elements or literal tags | Select appropriate API |
| Ignoring source whitespace | Unexpected string content | Inspect or trim as needed |
| Replacing buttons without reattaching listeners | New nodes lack old listeners | Preserve nodes or attach listeners to replacements |

## 20. Interview questions and answers

**1. What does `textContent` do?**  
It reads or replaces a node's text content. Assigning it to an element replaces its child nodes with text, without parsing HTML.

**2. How is `innerText` different from `textContent`?**  
`innerText` reflects rendered text and depends on CSS/layout. `textContent` reflects underlying text nodes, including hidden text.

**3. What does the `innerHTML` getter return?**  
A string containing serialized HTML markup of the element's children.

**4. What is the difference between `innerHTML` and `outerHTML`?**  
`innerHTML` deals with children; `outerHTML` includes the selected element itself. Assigning `outerHTML` replaces that element.

**5. Why is `innerHTML` dangerous with untrusted data?**  
It parses input as markup, which may create malicious event handlers or other XSS attack surfaces.

**6. What should be used to display ordinary user-entered text?**  
Usually `textContent`.

**7. What does `insertAdjacentText()` do?**  
It inserts text at a requested position without parsing it as HTML.

**8. Name the four insertion positions.**  
`beforebegin`, `afterbegin`, `beforeend`, and `afterend`.

**9. What does `replaceChildren()` do?**  
It replaces child nodes with supplied nodes or strings; with no arguments it clears all children.

**10. Why can `innerHTML` replacement break event listeners?**  
It can replace old descendant elements with new ones; listeners attached to the old nodes are not transferred automatically.

## 22. Knowledge check

**Question 1:** Which property should usually display untrusted text?  
A. `innerHTML`  
B. `outerHTML`  
C. `textContent`  
D. `insertAdjacentHTML`

**Question 2:** What happens when assigning `innerHTML`?  
A. It always appends text  
B. It parses markup and replaces children  
C. It changes CSS only  
D. It returns a NodeList

**Question 3:** Which method inserts text without replacing existing child elements?  
A. `insertAdjacentText()`  
B. `outerHTML = ...`  
C. `textContent = ...`  
D. `innerHTML = ...`

**Question 4:** What does `replaceChildren()` with no arguments do?  
A. Clones children  
B. Hides children  
C. Removes all children  
D. Converts children to text

**Question 5:** Why might `innerHTML += ...` disrupt existing event listeners?  
A. It disables JavaScript  
B. It can replace existing descendant elements  
C. It clears browser storage  
D. It disables event propagation

**Answer key with explanations:**

1. **C** - `textContent` treats the string as text.
2. **B** - `innerHTML` parses markup and replaces children.
3. **A** - `insertAdjacentText()` inserts a text node at a specified position.
4. **C** - With no arguments, `replaceChildren()` clears all children.
5. **B** - Replacing markup can recreate descendant nodes without old directly attached listeners.

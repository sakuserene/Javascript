## 1. Learning objectives

After this lesson, you should be able to explain what the DOM represents, how HTML becomes a tree of nodes, what makes an element different from a text node, how parent/child/sibling relationships work, how `window` differs from `document`, and how JavaScript changes a live webpage. You should also understand references, `null`, the difference between attributes and properties, and why script timing matters.

## 2. What is the DOM?

**DOM** stands for **Document Object Model**. It is a programming interface representing an HTML or XML document as a tree of objects called *nodes*. A browser parses HTML and creates the DOM. JavaScript can then read or change the nodes.

HTML:

```html
<h1>Hello World</h1>
<p>Welcome to JavaScript</p>
```

JavaScript:

```javascript
document.querySelector("h1").textContent = "Hello DOM";
```

The displayed heading changes to `Hello DOM`. The DOM is **not** the HTML file on disk: it is the current in-memory document. JavaScript can use it to change text, insert and remove elements, update attributes and classes, read form controls, and respond to events.

**Syntax breakdown:** `document` is the document object; `.` accesses a member; `querySelector` is a method; `("h1")` passes the CSS selector string `"h1"`; the returned element's `textContent` property is assigned a new string using `=`; `;` ends the statement. If no `h1` exists, `querySelector` returns `null`, so the assignment would throw.

## 3. HTML vs DOM

HTML describes document structure using markup; the DOM represents the parsed structure as objects. CSS describes styling; JavaScript is the programming language that can manipulate the DOM and respond to events.

```html
<!DOCTYPE html>
<html lang="en">
<head><title>My Website</title></head>
<body>
  <h1>Welcome</h1>
  <p>Hello JavaScript</p>
</body>
</html>
```

Simplified tree (whitespace text nodes and doctype omitted):

```text
document
|-- html
|   |-- head
|   |   \-- title
|   |       \-- "My Website" (text)
|   \-- body
|       |-- h1
|       |   \-- "Welcome" (text)
|       \-- p
|           \-- "Hello JavaScript" (text)
```

| HTML | DOM |
| --- | --- |
| Markup/source | Parsed object representation |
| Tags and attributes | Nodes, interfaces, properties and methods |
| May be stored in a `.html` file | Exists in the running document |
| Does not automatically change when JavaScript runs | Can change while the page runs |

For example, `document.body.append("New content")` modifies the live DOM but does not rewrite the original file.

## 4. Nodes and node types

A **node** is a unit of the DOM tree. Not every node is an element.

| Type | Example | Meaning |
| --- | --- | --- |
| Document | `document` | Represents the whole document |
| Element | `<p>` | Represents an HTML/XML element |
| Text | `Hello` | Text inside an element |
| Comment | `<!-- note -->` | Markup comment |
| DocumentType | `<!DOCTYPE html>` | Document type declaration |
| DocumentFragment | `document.createDocumentFragment()` | Lightweight node container |

```html
<div>Hello <span>World</span></div>
```

The `div` is an element node. It has a text node containing `Hello ` and a `span` element node; the `span` has its own text node containing `World`. **Every element is a node, but not every node is an element.** Whitespace can also create text nodes, which is why `childNodes` and `children` may give different results.

## 5. DOM tree relationships

```html
<div id="container">
  <h2>Products</h2>
  <ul>
    <li>Laptop</li>
    <li>Mouse</li>
  </ul>
</div>
```

- **Parent:** the `ul` is the direct parent element of both `li` elements.
- **Child:** each `li` is a direct child element of the `ul`.
- **Sibling:** the two `li` elements share the same parent.
- **Ancestor:** both `ul` and `div` are ancestors of each `li`.
- **Descendant:** `h2`, `ul`, and both `li` elements are descendants of `div`.

**Direct** matters: a descendant is not necessarily a direct child. Later, we will use `parentElement`, `children`, `nextElementSibling`, and `closest()` to navigate these relationships.

## 6. Window and document

In a normal browser page, `window` represents the window environment and is the global object for ordinary page scripts. `document` represents the webpage document. `window.document` refers to the document.

```javascript
console.log(window.document === document); // true, in a normal page
console.log(window.innerWidth);             // viewport width
console.log(window.location.href);         // current URL
window.alert("Hello");
```

`window` exposes browser capabilities such as `location`, `setTimeout`, `scrollTo`, and `innerWidth`. `document` exposes document information and DOM access.

```text
window
\-- document
    \-- html
        |-- head
        \-- body
```

This diagram shows access relationships, not a complete browser object hierarchy.

## 7. Document properties

```html
<!DOCTYPE html>
<html><head><title>Learning DOM</title></head>
<body><h1>Hello</h1></body></html>
```

```javascript
console.log(document.title);           // "Learning DOM"
console.log(document.body);            // body element
console.log(document.head);            // head element
console.log(document.documentElement); // html element

document.title = "JavaScript DOM Tutorial";
```

**Assignment breakdown:** `document.title` accesses the title property; `=` assigns the new string; the browser updates the current document title. `const` creates a binding that cannot be reassigned; it does **not** make a referenced DOM element immutable.

## 8. Browser parsing and rendering

A simplified browser pipeline:

```text
Receive HTML
   |
   v
Parse HTML -> build DOM
   |
   v
Parse CSS -> styling information (CSSOM)
   |
   v
Determine rendered boxes
   |
   v
Calculate layout
   |
   v
Paint and composite
```

Browsers may do these steps incrementally and repeat some of them as resources load or the DOM changes. Not every DOM node creates a visible box; for example, `display: none` suppresses normal rendering. DOM changes can cause style recalculation, layout, and/or painting, depending on what changed.

## 9. First complete DOM program

Save the following as `index.html`:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>DOM Example</title>
</head>
<body>
  <h1 id="heading">Original Heading</h1>
  <p id="message">Original paragraph</p>
  <script src="script.js"></script>
</body>
</html>
```

Save this as `script.js` in the same folder:

```javascript
const heading = document.getElementById("heading");
const message = document.getElementById("message");

heading.textContent = "Updated Heading";
message.textContent = "Updated paragraph";
```

**Syntax details:** `const` declares a binding; `heading` is its name; `=` assigns the method's return value; `document.getElementById("heading")` finds the element with that ID; `textContent` reads or replaces the element's text content.

| Step | Code | Effect |
| --- | --- | --- |
| 1 | `getElementById("heading")` | Save a reference to the heading |
| 2 | `getElementById("message")` | Save a reference to the paragraph |
| 3 | `heading.textContent = ...` | Replace heading text |
| 4 | `message.textContent = ...` | Replace paragraph text |

**Before:** `Original Heading` and `Original paragraph`. **After:** `Updated Heading` and `Updated paragraph`.

## 10. Objects and references

DOM elements are objects. Variables hold references to them, not copies of their HTML.

```javascript
const first = document.getElementById("heading");
const second = document.getElementById("heading");
console.log(first === second); // true
first.textContent = "Changed";
console.log(second.textContent); // "Changed"
```

`===` checks strict equality. Here it returns `true` because both variables reference the **same object**. Changing the object through one reference is visible through the other.

## 11. Attributes vs properties

HTML attributes are written in markup. DOM properties are values exposed on objects. Some correspond closely; others differ.

```html
<input id="username" type="text" value="Alice">
```

```javascript
const input = document.getElementById("username");
console.log(input.id);                  // "username"
console.log(input.type);                // "text"
console.log(input.value);               // "Alice"
input.value = "Bob";
console.log(input.value);               // "Bob"
console.log(input.getAttribute("value")); // usually "Alice"
```

The `value` **attribute** supplies the default value; the `value` **property** tracks the current value. This is one reason attributes and properties must not be treated as interchangeable. Later lessons cover `getAttribute`, `setAttribute`, boolean attributes, and `dataset` in depth.

## 12. The live DOM

```javascript
const paragraph = document.createElement("p");
paragraph.textContent = "New paragraph";
document.body.appendChild(paragraph);
```

Execution:

1. `createElement("p")` creates a detached paragraph element.
2. `textContent = ...` creates/replaces its text content.
3. `appendChild(paragraph)` inserts it as the final child of `body`.

Before:

```html
<body><h1>Hello</h1></body>
```

After (simplified):

```html
<body><h1>Hello</h1><p>New paragraph</p></body>
```

The original HTML file on disk is not rewritten.

## 13. DOM interface inheritance

An HTML heading element implements capabilities inherited from multiple interfaces:

```text
EventTarget
\-- Node
    \-- Element
        \-- HTMLElement
            \-- HTMLHeadingElement
```

| Interface | Example members |
| --- | --- |
| EventTarget | `addEventListener`, `removeEventListener`, `dispatchEvent` |
| Node | `parentNode`, `childNodes`, `appendChild` |
| Element | `getAttribute`, `querySelector`, `classList` |
| HTMLElement | `style`, `innerText`, `hidden` |
| HTMLHeadingElement | Represents heading elements such as `h1` |

This explains why one heading element supports methods and properties defined by several interfaces. Unlike a plain object literal, a DOM element has standardized browser-defined behavior.

## 14. Handling null

```javascript
const heading = document.getElementById("missing");
console.log(heading); // null, if no matching element exists
```

This would fail:

```javascript
heading.textContent = "Hello"; // TypeError if heading is null
```

Safe approach:

```javascript
if (heading !== null) {
  heading.textContent = "Hello";
}
```

`!==` means **strictly not equal**. The block runs only when `heading` is not `null`.

For reading:

```javascript
console.log(heading?.textContent); // undefined if heading is null
```

`?.` is optional chaining. It avoids an error when the base value is `null` or `undefined`. It cannot be used on the left side of assignment: `heading?.textContent = "Hello"` is invalid syntax.

## 15. Script timing

If a classic script runs before an element has been parsed, a selection can return `null`:

```html
<head>
  <script>
    const heading = document.getElementById("title"); // null here
  </script>
</head>
<body><h1 id="title">Hello</h1></body>
```

Three common solutions:

**A. Script after the relevant markup:**

```html
<body>
  <h1 id="title">Hello</h1>
  <script src="script.js"></script>
</body>
```

**B. External classic script with `defer`:**

```html
<head><script src="script.js" defer></script></head>
```

**C. Wait for `DOMContentLoaded`:**

```javascript
document.addEventListener("DOMContentLoaded", function () {
  const heading = document.getElementById("title");
  console.log(heading);
});
```

`DOMContentLoaded` fires when parsing is complete and deferred/module scripts have executed; it does not wait for every image to finish loading. We'll cover events in Module 16.

## 16. Developer tools

On desktop Chrome, Edge, or Firefox, open developer tools (`F12` is a common shortcut), choose the **Elements** or **Inspector** panel, expand the DOM tree, and inspect elements. In the **Console**, try:

```javascript
document.body
document.documentElement
document.querySelector("h1")
document.querySelectorAll("p")
```

You can inspect changes to the DOM while JavaScript executes. Note that browser consoles often display object references interactively, not just fixed snapshots.

## 17. Common mistakes

| Mistake | Why it happens | Better approach |
| --- | --- | --- |
| DOM confused with HTML file | Source vs live representation | Distinguish markup and parsed objects |
| Every node assumed to be an element | Text/comments are also nodes | Understand node types |
| `window` and `document` treated as identical | Both are globally accessible | Learn their distinct responsibilities |
| Element accessed before parsing | Script runs too early | Use `defer` or place script later |
| `null` ignored | Selector found no match | Check before accessing properties |
| DOM updates assumed to save to disk | Browser memory vs file system | Treat DOM changes as runtime state |
| Attributes treated like properties | Some reflect defaults, others current state | Learn their semantics |
| DOM elements treated as strings | Elements are objects | Use properties and methods |

## 18. Student profile project

**Goal:** Render data from a plain JavaScript object into a webpage.

`index.html`:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Student Profile</title>
  <script src="script.js" defer></script>
</head>
<body>
  <h1 id="studentName">Unknown</h1>
  <p id="studentAge">Age: -</p>
  <p id="studentCourse">Course: -</p>
</body>
</html>
```

`script.js`:

```javascript
const student = {
  name: "Alice",
  age: 20,
  course: "Computer Science"
};

const nameElement = document.getElementById("studentName");
const ageElement = document.getElementById("studentAge");
const courseElement = document.getElementById("studentCourse");

nameElement.textContent = student.name;
ageElement.textContent = `Age: ${student.age}`;
courseElement.textContent = `Course: ${student.course}`;
```

**Template literal detail:** Backticks (`` ` ``) create a template literal; `${student.age}` evaluates `student.age` and inserts its value into the string. The result is `Age: 20`.

| Step | Operation | Result |
| --- | --- | --- |
| 1 | Create `student` object | Data stored |
| 2 | Select three elements | References stored |
| 3 | Assign name text | Alice |
| 4 | Assign age text | Age: 20 |
| 5 | Assign course text | Course: Computer Science |

Expected visible content:

```text
Alice
Age: 20
Course: Computer Science
```

## 19. Ten interview questions and answers

1. **What does DOM stand for?** Document Object Model, a standardized interface representing documents as trees of nodes.
2. **Is DOM the same as HTML?** No. HTML is markup; the DOM is the parsed, current object representation.
3. **What is a DOM node?** A unit in the tree, such as an element, text, comment, document, or document type.
4. **Node vs element?** An element is a node type; many nodes are not elements.
5. **Window vs document?** `window` is the browser window environment; `document` is the webpage document.
6. **What does `document.body` return?** The body element when available, otherwise `null`.
7. **What is DOM traversal?** Navigating relationships among nodes, such as parents, children, and siblings.
8. **Why can `getElementById()` return `null`?** No matching ID exists, or the element has not been parsed yet.
9. **Do DOM changes modify the HTML file?** No, they modify the live in-memory document.
10. **Attribute vs property?** Attributes are in markup; properties belong to DOM objects. Their values and synchronization may differ.

## 20. Ten coding exercises with solutions

Try each task before looking at the solution. Unless otherwise stated, run the JavaScript after the matching HTML has been parsed (for example, by placing a script before `</body>` or using `defer`).

### Exercise 1 - Read the document title

**Task:** Print the page title.

```javascript
console.log(document.title);
```

`document.title` reads the title property; `console.log()` prints it.

### Exercise 2 - Change the title

**Task:** Change the title to `Learning JavaScript DOM`.

```javascript
document.title = "Learning JavaScript DOM";
```

The `=` operator assigns the new string to the property.

### Exercise 3 - Select and read a heading

**HTML:**

```html
<h1 id="heading">Hello</h1>
```

**Solution:**

```javascript
const heading = document.getElementById("heading");
console.log(heading.textContent); // Hello
```

The method returns a reference to the element with ID `heading`; `textContent` reads its text.

### Exercise 4 - Change a heading safely

**HTML:**

```html
<h1 id="heading">Hello</h1>
```

**Solution:**

```javascript
const heading = document.getElementById("heading");
if (heading !== null) {
  heading.textContent = "Welcome to DOM";
}
```

`!== null` protects against a missing element.

### Exercise 5 - Read the root element

```javascript
console.log(document.documentElement);
```

For a normal HTML document, this returns the `html` element.

### Exercise 6 - Read the body

```javascript
console.log(document.body);
```

This returns the body element when available.

### Exercise 7 - Compare references

**HTML:**

```html
<p id="message">Hello</p>
```

**Solution:**

```javascript
const first = document.getElementById("message");
const second = document.getElementById("message");
console.log(first === second); // true
```

Both references identify the same object. `===` compares their identity.

### Exercise 8 - Create and insert a paragraph

```javascript
const paragraph = document.createElement("p");
paragraph.textContent = "JavaScript is powerful";
document.body.appendChild(paragraph);
```

The paragraph is created first, populated second, and inserted third. It is not visible until inserted.

### Exercise 9 - Handle a missing element

```javascript
const element = document.getElementById("unknown");
if (element === null) {
  console.log("Element not found");
} else {
  console.log(element.textContent);
}
```

`===` checks strict equality. If the element is missing, only the first branch runs.

const student = {

### Bonus - Plain loop vs built-in method preview

A key principle in this course is comparing traditional loops with built-in methods. Detailed DOM collection iteration belongs to Lesson 15.3, but here is a preview using an ordinary array:

```javascript
const names = ["Alice", "Bob", "Carol"];

// Plain loop
for (let i = 0; i < names.length; i++) {
  console.log(names[i]);
}

// Built-in method
names.forEach(function (name) {
  console.log(name);
});
```

Both print all three names in order. The `for` loop explicitly controls `i`; `forEach` invokes a callback for each item. Later we will apply these patterns to `NodeList` and `HTMLCollection` and examine how live collections behave.

## 22. Summary and mastery checklist

You have learned that the DOM is a live tree of objects, not the original HTML file. The browser constructs this tree by parsing markup. Nodes include elements and text nodes; elements are related by parent/child/sibling relationships. `window` provides browser-level features, while `document` provides access to the document. DOM objects are referenced by JavaScript variables, attributes and properties can differ, and script timing matters.

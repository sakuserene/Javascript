## 1. Learning Objectives

DOM traversal means navigating between nodes in an HTML document. By the end of this lesson, you should be able to distinguish parents, children, siblings, ancestors, and descendants; tell element nodes apart from text and comment nodes; navigate using parent, child, and sibling properties; use `closest()`, `matches()`, and `contains()`; understand live versus static collections; and build two small interactive applications.

## 2. The DOM Tree

```html
<div id="container">
  <h2>Title</h2>
  <p>First paragraph</p>
  <p>Second paragraph</p>
</div>
```

Conceptual *element* tree (whitespace text nodes omitted):

```text
div#container
|-- h2: Title
|-- p: First paragraph
`-- p: Second paragraph
```

- **Parent:** a node containing a direct child.
- **Child:** a node immediately inside a parent.
- **Sibling:** nodes with the same parent.
- **Ancestor:** parent, grandparent, and so on.
- **Descendant:** child, grandchild, and so on.
- **Root:** the top of a tree, such as the `document` node for an HTML document.

The `div` is the parent of the heading and paragraphs. The heading and paragraphs are siblings. A nested `span` inside a paragraph would be a descendant of the `div`, but not its direct child.

## 3. Node Types

The DOM is a tree of **nodes**, not just HTML elements. Indentation and newlines in HTML can become text nodes.

```html
<div id="container">
  <p>Hello</p>
</div>
```

The actual children of the `div` can be:

```text
div#container
|-- #text (newline and indentation)
|-- p
|   `-- #text ("Hello")
`-- #text (newline)
```

| Node | `nodeType` |
| --- | ---: |
| Element | 1 |
| Text | 3 |
| Comment | 8 |
| Document | 9 |
| DocumentFragment | 11 |

```js
const paragraph = document.querySelector("p");
console.log(paragraph.nodeType);            // 1
console.log(paragraph.firstChild.nodeType); // 3, if the first child is "Hello" text
```

**Token breakdown:** `paragraph` is a variable holding an element reference; `.` accesses a property; `nodeType` is a numeric property, not a method, so it has no parentheses. `console.log(...)` prints its argument. `//` starts a JavaScript comment, which is not executed.

**Execution trace:** (1) find the first `p`; (2) read its `nodeType` -> `1`; (3) read its first child, the text node; (4) read that node's `nodeType` -> `3`.

## 4. parentNode

`node.parentNode` returns the immediate parent node, or `null` if there is none.

```html
<div id="container"><p id="message">Hello</p></div>
```

```js
const message = document.getElementById("message");
const parent = message.parentNode;
console.log(parent.id); // "container"
```

**Line-by-line breakdown:**

1. `const` declares a binding that cannot be reassigned.
2. `message` names that binding.
3. `=` assigns the result of the expression on its right.
4. `document.getElementById("message")` calls a document method with the string ID `"message"`, returning the matching element or `null`.
5. `message.parentNode` reads the parent node from the selected paragraph.
6. `parent.id` reads the parent's `id` property.
7. `console.log(parent.id)` prints `container`.

A parent may be an `Element`, `Document`, or `DocumentFragment`:

```js
console.log(document.documentElement.parentNode === document); // true
```

Here `===` means *strict equality*: both sides reference the same document object.

## 5. parentElement

`node.parentElement` returns the immediate parent **if it is an Element**; otherwise it returns `null`.

```js
const message = document.getElementById("message");
console.log(message.parentElement.id); // "container"

const html = document.documentElement;
console.log(html.parentNode === document); // true
console.log(html.parentElement);            // null
```

The `<html>` element's parent is the document node, which is not an element. For ordinary nested HTML elements, `parentNode` and `parentElement` usually return the same object.

| Property | Returns |
| --- | --- |
| `parentNode` | Any kind of parent node, or `null` |
| `parentElement` | Parent element, or `null` |

## 6. children

`element.children` returns a **live HTMLCollection** of its direct child **elements**.

```html
<ul id="fruits">
  <li>Apple</li>
  <li>Banana</li>
  <li>Orange</li>
</ul>
```

```js
const list = document.getElementById("fruits");
console.log(list.children.length);          // 3
console.log(list.children[0].textContent);  // "Apple"
console.log(list.children[1].textContent);  // "Banana"
```

**Breakdown of `list.children[0].textContent`:**

- `list`: reference to the `ul` element.
- `.children`: access the collection of direct element children.
- `[0]`: bracket notation selects the item at index zero, the first item.
- `.textContent`: reads all text inside that child.

JavaScript indices begin at **0**, not 1. For three elements the valid indices are `0`, `1`, and `2`.

To find the last child using indexing:

```js
const last = list.children[list.children.length - 1];
console.log(last.textContent); // "Orange"
```

Step by step: `list.children.length` is `3`; `3 - 1` is `2`; `list.children[2]` selects Orange. This indexing expression needs a nonempty collection; if it is empty, the result is `undefined`.

## 7. childNodes

`node.childNodes` returns a **live NodeList** of **all** direct child nodes, including elements, whitespace text nodes, and comments.

```js
const container = document.getElementById("container");
console.log(container.childNodes);
console.log(container.children);
```

| Feature | `children` | `childNodes` |
| --- | --- | --- |
| Direct element children | Yes | Yes |
| Text nodes | No | Yes |
| Comment nodes | No | Yes |
| Collection type | `HTMLCollection` | `NodeList` |
| Live | Yes | Yes |

Use `children` for element-based UI operations; use `childNodes` when text and comments are relevant. The exact number of text nodes depends on whitespace in the HTML source.

## 8. First and Last Child Properties

```html
<div id="container">
  <h2>Heading</h2>
  <p>Paragraph</p>
  <button>Button</button>
</div>
```

```js
const container = document.getElementById("container");
console.log(container.firstChild);                 // Possibly whitespace text
console.log(container.lastChild);                  // Possibly whitespace text
console.log(container.firstElementChild.tagName); // "H2"
console.log(container.lastElementChild.tagName);  // "BUTTON"
```

| Property | Result |
| --- | --- |
| `firstChild` | First child node, regardless of type |
| `lastChild` | Last child node, regardless of type |
| `firstElementChild` | First child element |
| `lastElementChild` | Last child element |

If the appropriate child does not exist, these properties return `null`. The uppercase `tagName` results are typical of HTML elements in HTML documents.

## 9. Sibling Navigation

```html
<div>
  <p id="first">First</p>
  <p id="second">Second</p>
  <p id="third">Third</p>
</div>
```

```js
const second = document.getElementById("second");
console.log(second.previousElementSibling.id); // "first"
console.log(second.nextElementSibling.id);     // "third"
console.log(second.previousSibling);           // May be a whitespace text node
console.log(second.nextSibling);               // May be a whitespace text node
```

| Property | Direction | Node filtering |
| --- | --- | --- |
| `previousSibling` | Backward | Any node |
| `nextSibling` | Forward | Any node |
| `previousElementSibling` | Backward | Elements only |
| `nextElementSibling` | Forward | Elements only |

At either boundary, the corresponding property returns `null`.

**Execution trace:** `second.nextElementSibling` starts at the second paragraph, skips any intervening whitespace text nodes, and returns the third paragraph. No new element is created.

## 10. closest()

`element.closest(selector)` checks the element **itself**, then each ancestor, and returns the first matching element or `null`.

```html
<article class="card">
  <div class="content">
    <button id="removeButton">Remove</button>
  </div>
</article>
```

```js
const button = document.getElementById("removeButton");
const card = button.closest(".card");
console.log(card.tagName); // "ARTICLE"
```

**Syntax breakdown:** `button` is the starting element; `.` accesses the method; `closest` is the method name; `(".card")` passes a CSS class selector string. The leading `.` means a CSS class, not a JavaScript property operator because it appears **inside the string**.

**Execution trace:**

1. Check whether the button has class `card`: no.
2. Move to its parent `.content`: no.
3. Move to the `<article class="card">`: yes.
4. Return that article.

Safely handle no match:

```js
const card = button.closest(".card");
card?.remove();
```

The `?.` optional chaining operator calls `remove()` only when `card` is not `null` or `undefined`.

## 11. matches()

`element.matches(selector)` checks **only that element** against a CSS selector. It returns `true` or `false`.

```html
<button id="submitButton" class="primary active">Submit</button>
```

```js
const button = document.getElementById("submitButton");
console.log(button.matches(".active"));   // true
console.log(button.matches(".disabled")); // false
```

`matches()` does not search ancestors. Use `closest()` for that.

## 12. contains()

`node.contains(otherNode)` returns `true` if `otherNode` is the same node or a descendant.

```html
<div id="container"><p id="message">Hello</p></div>
```

```js
const container = document.getElementById("container");
const message = document.getElementById("message");
console.log(container.contains(message));   // true
console.log(container.contains(container)); // true
```

**Important:** a node contains itself. To test for a *strict descendant*, combine containment with inequality:

```js
const isStrictDescendant =
  container.contains(message) && container !== message;
```

`&&` means logical AND; both conditions must be truthy. `!==` means strict inequality: the references must differ.

## 13. Live and Static Collections

```html
<ul id="list"><li>Apple</li><li>Banana</li></ul>
```

```js
const list = document.getElementById("list");
const liveItems = list.children;
const staticItems = list.querySelectorAll("li");

console.log(liveItems.length);   // 2
console.log(staticItems.length); // 2

const orange = document.createElement("li");
orange.textContent = "Orange";
list.appendChild(orange);

console.log(liveItems.length);   // 3
console.log(staticItems.length); // 2
```

`children` updates automatically because it is live. `querySelectorAll()` captures a static list of matching elements at the time it runs. Calling it again returns a new snapshot. **Not all NodeLists are static:** `childNodes` is a live NodeList.

Be careful when removing elements while iterating a live collection. Removing index `0` causes the next element to move into index `0`.

Problematic example:

```js
for (let i = 0; i < list.children.length; i++) {
  list.children[i].remove(); // May skip elements as indices shift
}
```

Safer snapshot:

```js
for (const item of Array.from(list.children)) {
  item.remove();
}
```

Or clear the list directly:

```js
list.replaceChildren();
```

## 14. Array.from()

`Array.from(iterableOrArrayLike)` creates a new JavaScript array from a collection.

```js
const list = document.getElementById("list");
const items = Array.from(list.children);
items.forEach(function (item) {
  console.log(item.textContent);
});
```

**Token-by-token:**

| Token | Explanation |
| --- | --- |
| `const` | Declare a binding |
| `items` | Name of new array variable |
| `=` | Assignment |
| `Array` | Built-in JavaScript constructor object |
| `.from` | Static method that creates an array |
| `list.children` | Source HTMLCollection |
| `()` | Call method with the source as argument |
| `.forEach(...)` | Execute a callback once for each array item |
| `function (item)` | Callback parameter receives one item per iteration |

The array holds references to the **same elements**; it does not clone those elements. Its membership is a snapshot.

## 15. Traversing with Loops

```html
<ul id="list">
  <li>Apple</li>
  <li>Banana</li>
  <li>Orange</li>
</ul>
```

```js
const list = document.getElementById("list");
let current = list.firstElementChild;

while (current !== null) {
  console.log(current.textContent);
  current = current.nextElementSibling;
}
```

**Detailed breakdown:**

1. `const list = ...` selects the list.
2. `let current = ...` declares a *reassignable* variable referencing the first element.
3. `while (...)` starts a loop that checks its condition **before** each iteration.
4. `current !== null` uses strict inequality; the loop continues while a node exists.
5. `console.log(current.textContent)` prints the current element's text.
6. `current = current.nextElementSibling` moves the reference forward by one element.
7. When there is no next element, the property is `null`, so the loop stops.

| Iteration | `current` | Condition | Output |
| --- | --- | --- | --- |
| 1 | Apple | true | Apple |
| 2 | Banana | true | Banana |
| 3 | Orange | true | Orange |
| 4 | null | false | Loop ends |

**Common mistake:** Omitting `current = current.nextElementSibling` can create an infinite loop because `current` never changes.

## 16. Project 1 - Select a Fruit

**Goal:** Clicking a fruit button adds `active` to that button and removes `active` from its siblings. This example uses event delegation, `closest()`, `contains()`, and `children`.

Create three files in the same folder.

**index.html**

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Fruit Selector</title>
  <link rel="stylesheet" href="styles.css">
  <script src="script.js" defer></script>
</head>
<body>
  <h1>Select a Fruit</h1>
  <div id="fruitList" aria-label="Choose a fruit">
    <button type="button">Apple</button>
    <button type="button">Banana</button>
    <button type="button">Orange</button>
  </div>
  <p id="selection" aria-live="polite">No fruit selected.</p>
</body>
</html>
```

**styles.css**

```css
body { font-family: Arial, sans-serif; padding: 24px; }
#fruitList { display: flex; flex-wrap: wrap; gap: 12px; }
#fruitList button { padding: 12px 18px; cursor: pointer; }
#fruitList button.active { background: #2563eb; color: white; }
#fruitList button:focus-visible { outline: 3px solid #f59e0b; outline-offset: 2px; }
```

**script.js**

```js
const fruitList = document.getElementById("fruitList");
const selection = document.getElementById("selection");

fruitList.addEventListener("click", function (event) {
  if (!(event.target instanceof Element)) {
    return;
  }

  const button = event.target.closest("button");

  if (button === null || !fruitList.contains(button)) {
    return;
  }

  for (const sibling of fruitList.children) {
    sibling.classList.remove("active");
  }

  button.classList.add("active");
  selection.textContent = `Selected: ${button.textContent}`;
});
```

**Line-by-line reasoning:**

- `addEventListener("click", ...)` registers a callback that runs when a click bubbles to the container.
- `event` is the event object; `.target` identifies the original clicked node.
- `instanceof Element` checks whether the target is an element. `!` negates that boolean. If it is not an element, `return` stops the callback.
- `event.target.closest("button")` finds the nearest button, including the target itself.
- `button === null || !fruitList.contains(button)` means: stop if there is no button **OR** the button is outside this container. `||` is logical OR and short-circuits: if the first condition is true, the second is not evaluated.
- `for (const sibling of fruitList.children)` iterates through the direct child elements.
- `sibling.classList.remove("active")` removes the active class from each.
- `button.classList.add("active")` activates only the selected button.
- `` `Selected: ${button.textContent}` `` is a template literal: backticks delimit the string, and `${...}` inserts the value of an expression.

**Execution trace when Banana is clicked:**

1. The button receives a click.
2. The click bubbles to `fruitList`.
3. The event target is verified to be an element.
4. `closest("button")` finds the Banana button.
5. `contains()` confirms the button belongs to the fruit list.
6. The loop removes `active` from Apple, Banana, and Orange.
7. The Banana button receives `active`.
8. The selection paragraph displays `Selected: Banana`.

**Try it:** Add a fourth button inside `fruitList`; the parent listener handles it without registering another listener. This is called *event delegation*.

## 17. Project 2 - Remove Cards

**Goal:** Click a nested Remove button, find its containing card with `closest()`, and remove only that card.

**index.html**

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Remove Cards</title>
  <link rel="stylesheet" href="styles.css">
  <script src="script.js" defer></script>
</head>
<body>
  <h1>Cards</h1>
  <div id="cardList">
    <article class="card">
      <h2>Card One</h2>
      <p>First description</p>
      <button type="button" class="remove-button">Remove Card One</button>
    </article>
    <article class="card">
      <h2>Card Two</h2>
      <p>Second description</p>
      <button type="button" class="remove-button">Remove Card Two</button>
    </article>
  </div>
  <p id="status" aria-live="polite">2 cards remaining.</p>
</body>
</html>
```

**styles.css**

```css
body { font-family: Arial, sans-serif; padding: 24px; }
.card { border: 1px solid #bbb; border-radius: 8px; padding: 16px; margin-bottom: 12px; }
button { padding: 8px 12px; cursor: pointer; }
button:focus-visible { outline: 3px solid #2563eb; outline-offset: 2px; }
```

**script.js**

```js
const cardList = document.getElementById("cardList");
const status = document.getElementById("status");

cardList.addEventListener("click", function (event) {
  if (!(event.target instanceof Element)) {
    return;
  }

  const removeButton = event.target.closest(".remove-button");

  if (removeButton === null || !cardList.contains(removeButton)) {
    return;
  }

  const card = removeButton.closest(".card");

  if (card !== null && cardList.contains(card)) {
    card.remove();
    const count = cardList.querySelectorAll(".card").length;
    status.textContent = `${count} cards remaining.`;
  }
});
```

**Important operators and methods:**

| Code | Explanation |
| --- | --- |
| `!condition` | Logical NOT; reverses a boolean |
| `===` | Strict equality |
| `!==` | Strict inequality |
| `||` | Logical OR; either condition may be true |
| `&&` | Logical AND; both conditions must be true |
| `closest(".card")` | Finds the nearest matching card ancestor or self |
| `contains(card)` | Checks the card is within the intended container |
| `card.remove()` | Detaches that card from the DOM |
| `querySelectorAll(".card").length` | Counts matching card elements at that moment |

**Execution trace when Remove Card One is clicked:**

1. Click event bubbles to `cardList`.
2. The target is confirmed to be an element.
3. `closest(".remove-button")` finds the clicked button.
4. `contains()` confirms the button is inside `cardList`.
5. `closest(".card")` finds Card One.
6. The card is checked to be within `cardList`.
7. `card.remove()` detaches Card One.
8. `querySelectorAll(".card")` returns a new static snapshot containing Card Two.
9. `.length` is `1`, so the status reads `1 cards remaining.`

**Accessibility note:** Removing a focused button can move keyboard focus unexpectedly. In a production interface, deliberately manage focus after removal (for example, move it to an adjacent card control or another meaningful target).

## 18. Common Mistakes

| Mistake | Why it fails | Better approach |
| --- | --- | --- |
| Assuming `firstChild` is an element | It may be whitespace text | Use `firstElementChild` |
| Assuming `nextSibling` is an element | It may be text or a comment | Use `nextElementSibling` |
| Assuming `parentElement` always exists | Parent may be a Document | Check for `null` |
| Calling `.remove()` on a null `closest()` result | Throws a TypeError | Check or use `?.` |
| Expecting `matches()` to search ancestors | It checks only the current element | Use `closest()` |
| Treating every NodeList as static | `childNodes` is live | Check the source API |
| Removing items while indexing a live collection | Indices shift | Use `Array.from()` or `replaceChildren()` |
| Forgetting to advance a `while` loop | Infinite loop | Update `current` |
| Expecting `children` to include grandchildren | It includes direct children only | Use `querySelectorAll()` |
| Assuming `contains()` excludes the node itself | A node contains itself | Also compare with `!==` |

## 19. Interview Questions and Answers

**1. What is DOM traversal?**  
Navigating between related nodes in a DOM tree, including parents, children, siblings, ancestors, and descendants.

**2. What is the difference between `parentNode` and `parentElement`?**  
`parentNode` returns the parent node regardless of node type; `parentElement` returns the parent only when it is an Element, otherwise `null`.

**3. What is the difference between `children` and `childNodes`?**  
`children` is a live HTMLCollection of direct element children. `childNodes` is a live NodeList of all direct child nodes, including text and comments.

**4. Why might `firstChild` return a text node?**  
Whitespace and line breaks between HTML tags can become text nodes.

**5. How do `nextSibling` and `nextElementSibling` differ?**  
`nextSibling` returns the next node of any type; `nextElementSibling` skips non-element nodes.

**6. What does `closest()` do?**  
Checks the current element and then its ancestors for the nearest match to a CSS selector, returning the matching element or `null`.

**7. What does `matches()` return?**  
A boolean indicating whether the element itself matches the selector.

**8. What does `contains()` check?**  
Whether another node is the same node or a descendant.

**9. What is a live HTMLCollection?**  
A collection that automatically reflects DOM changes, such as additions and removals of child elements.

**10. Is the NodeList returned by `querySelectorAll()` live?**  
No. It is static. However, some other NodeLists, such as `childNodes`, are live.

### Exercise 10: Traverse All Siblings

**Task:** Print the text of every direct child element of `#list` using a `while` loop.

2. Set `current` to the first element child.

5. Move `current` to its next element sibling using assignment `=`.
6. Repeat until the next element sibling is `null`.

For Apple, Banana, Orange, the output is:

```text
Apple
Banana
Orange
```

## 21. Knowledge Quiz

Choose an answer before reading the explanation.

**Question 1. Which property returns only direct child elements?**

A. `childNodes`  
B. `children`  
C. `parentNode`  
D. `nextSibling`

**Answer: B.** `children` returns a live HTMLCollection of direct element children.

**Question 2. Which property skips whitespace text nodes when finding the next sibling?**

A. `nextSibling`  
B. `nextElementSibling`  
C. `firstChild`  
D. `parentNode`

**Answer: B.** `nextElementSibling` returns the next sibling that is an element.

**Question 3. What does `closest(".card")` search?**

A. Only descendants  
B. The current element and its ancestors  
C. Only siblings  
D. Every element in the document

**Answer: B.** It checks the current element first, then walks upward.

**Question 4. What does `querySelectorAll()` return?**

A. A live HTMLCollection  
B. A static NodeList  
C. One Element  
D. A text node

**Answer: B.** The resulting NodeList is a snapshot of matching elements.

**Question 5. What does `element.contains(element)` return?**

A. `false`  
B. `null`  
C. `true`  
D. `undefined`

**Answer: C.** A node is considered to contain itself.

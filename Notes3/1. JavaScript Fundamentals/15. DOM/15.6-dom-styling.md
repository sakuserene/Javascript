## 1. Understanding CSS and the DOM

HTML defines structure, CSS defines presentation, and JavaScript defines behavior.

```html
<p class="message">Hello World</p>
```

```css
.message {
  color: blue;
  font-size: 20px;
  background-color: lightgray;
}
```

```javascript
const message = document.querySelector(".message");
```

Three ways to apply CSS:

```html
<!-- External stylesheet -->
<link rel="stylesheet" href="styles.css">

<!-- Internal stylesheet -->
<style>p { color: blue; }</style>

<!-- Inline style -->
<p style="color: blue;">Hello</p>
```

JavaScript can update inline declarations and classes, and read computed styles.

## 2. The element.style property

`element.style` exposes the element's **inline** CSS declarations as a `CSSStyleDeclaration` object.

```html
<p id="message">Hello JavaScript</p>
```

```javascript
const message = document.getElementById("message");
message.style.color = "red";
```

The result is conceptually `<p id="message" style="color: red;">Hello JavaScript</p>`.

### Token-by-token explanation

| Token | Meaning |
| --- | --- |
| `message` | Variable referring to the paragraph DOM element |
| `.` | JavaScript property access operator |
| `style` | Inline CSS declaration object |
| `.` | Access a property on that object |
| `color` | CSS color property |
| `=` | Assignment operator; replaces the property's value |
| `"red"` | JavaScript string containing the CSS color value |
| `;` | Statement terminator |

### Execution trace

1. Evaluate `message` to obtain the DOM element.
2. Access its `.style` object.
3. Select the `.color` property.
4. Assign the string `"red"`.
5. Browser updates the inline declaration and recalculates presentation as needed.

### Multiple properties

```javascript
message.style.color = "white";
message.style.backgroundColor = "blue";
message.style.fontSize = "24px";
message.style.padding = "12px";
message.style.borderRadius = "8px";
```

### Interactive playground equivalent

In a browser console, try:

```javascript
const p = document.createElement("p");
p.textContent = "Hello JavaScript";
document.body.append(p);
p.style.color = "blue";
p.style.fontSize = "24px";
p.style.fontWeight = "normal";

// Try each change and inspect the page:
p.style.color = "red";
p.style.fontSize = "36px";
p.style.fontWeight = "bold";
```

Changing any of these properties updates the same paragraph rather than creating a new one.

## 3. CSS property naming in JavaScript

CSS commonly uses hyphenated names, but dot-property access usually uses camelCase.

| CSS name | JavaScript style name |
| --- | --- |
| `background-color` | `backgroundColor` |
| `font-size` | `fontSize` |
| `font-weight` | `fontWeight` |
| `border-radius` | `borderRadius` |
| `margin-top` | `marginTop` |
| `padding-left` | `paddingLeft` |
| `text-align` | `textAlign` |
| `line-height` | `lineHeight` |
| `z-index` | `zIndex` |

```javascript
// Incorrect: the hyphen is treated as subtraction.
// element.style.background-color = "blue";

// Correct:
element.style.backgroundColor = "blue";
element.style["background-color"] = "blue";
element.style.setProperty("background-color", "blue");
```

The square brackets in `style["background-color"]` access a property by its string name; they are not array indexing in this example.

## 4. Understanding CSS units

```javascript
element.style.width = "200px";
```

`200` is the magnitude, `px` is the unit, and `"200px"` is the string sent to CSS.

| Unit | Meaning |
| --- | --- |
| `px` | CSS pixels |
| `%` | Percentage; reference depends on property |
| `em` | Relative to a font size depending on property |
| `rem` | Relative to root font size |
| `vw` | Percentage of viewport width |
| `vh` | Percentage of viewport height |

```javascript
element.style.width = "50%";
element.style.padding = "1rem";
element.style.height = "100px";
```

Some CSS properties accept unitless values:

```javascript
element.style.opacity = "0.5";
element.style.zIndex = "10";
element.style.flexGrow = "1";
```

`opacity: 0.5` means half opacity; `opacity: 1` means fully opaque.

## 5. Reading inline styles

```html
<p id="message" style="color: red;">Hello</p>
```

```javascript
const message = document.getElementById("message");
console.log(message.style.color); // "red"
```

However, if `color: blue` comes only from a stylesheet, `message.style.color` is `""`. The `style` object does not expose all stylesheet rules. Use `getComputedStyle()` when you need the resolved style.

## 6. Understanding cssText

`element.style.cssText` reads or **replaces** the complete inline CSS declaration string.

```html
<p id="message" style="color: red; font-size: 20px;">Hello</p>
```

```javascript
const message = document.getElementById("message");
console.log(message.style.cssText);
// Typically: "color: red; font-size: 20px;"
```

Set it:

```javascript
message.style.cssText =
  "color: white; background-color: blue; padding: 12px;";
```

### Replacement pitfall

```javascript
message.style.color = "red";
message.style.fontSize = "20px";
message.style.cssText = "background-color: yellow;";
```

The old inline `color` and `font-size` declarations are removed. This differs from updating one property with `style.color = ...`.

## 7. Understanding setProperty

Syntax:

```javascript
element.style.setProperty(propertyName, value, priority);
```

The third argument is optional.

| Parameter | Meaning |
| --- | --- |
| `propertyName` | CSS property name, e.g. `"font-size"` |
| `value` | CSS value, e.g. `"24px"` |
| `priority` | Optional `"important"` |

```javascript
message.style.setProperty("background-color", "yellow");
message.style.setProperty("font-size", "24px");
message.style.setProperty("color", "red", "important");
```

### Step-by-step

For `message.style.setProperty("font-size", "24px")`:

1. Resolve `message` to the element.
2. Access its `style` object.
3. Call the `setProperty` method using `()`.
4. Pass `"font-size"` as the first argument.
5. The comma separates arguments.
6. Pass `"24px"` as the second argument.
7. The inline CSS declaration is updated.

Use `!important` sparingly; it complicates overrides.

## 8. Understanding removeProperty

```javascript
element.style.removeProperty(propertyName);
```

```javascript
message.style.color = "red";
const oldColor = message.style.removeProperty("color");
console.log(oldColor); // "red"
```

`removeProperty()` removes the inline declaration and returns its previous value. The element may still have a color from another stylesheet or inheritance.

## 9. Understanding CSS classes

Classes group reusable styles:

```html
<p class="message">Hello</p>
<p class="message">Welcome</p>
```

```css
.message {
  color: blue;
  font-size: 18px;
}
```

Rather than writing many inline styles, JavaScript can add or remove a class that contains the desired declarations.

## 10. Understanding className

`className` reads or replaces the element's entire class attribute string.

```html
<p id="message" class="message active">Hello</p>
```

```javascript
const message = document.getElementById("message");
console.log(message.className); // "message active"
message.className = "highlight";
```

The assignment **replaces both** `message` and `active` with the single class `highlight`. Use `classList` to preserve other classes.

## 11. Understanding classList

`classList` returns a live `DOMTokenList` for the element's CSS class tokens.

### add()

```javascript
message.classList.add("highlight");
message.classList.add("highlight", "active", "large");
```

Adds class tokens without removing existing ones.

### remove()

```javascript
message.classList.remove("highlight");
message.classList.remove("highlight", "active");
```

Removing an absent class does nothing.

### contains()

```javascript
if (message.classList.contains("active")) {
  console.log("The element is active");
}
```

Returns `true` or `false`.

### toggle()

```javascript
message.classList.toggle("highlight");
```

Adds `highlight` if absent; removes it if present.

```javascript
message.classList.toggle("highlight", true);  // Ensure present
message.classList.toggle("highlight", false); // Ensure absent
```

`toggle()` returns whether the class is present afterward.

### replace()

```javascript
const replaced = message.classList.replace("inactive", "active");
```

Returns `true` when `inactive` existed and was replaced; otherwise `false`.

### Browser demo

```html
<style>
  .highlight { background: yellow; font-weight: bold; }
</style>
<p id="message">Hello JavaScript</p>
<button id="toggle">Toggle highlight</button>
<script>
  const message = document.getElementById("message");
  const toggle = document.getElementById("toggle");
  toggle.addEventListener("click", function () {
    message.classList.toggle("highlight");
    console.log(message.className);
  });
</script>
```

Click 1: class becomes `highlight`. Click 2: class is removed. The paragraph node remains the same.

## 12. className vs classList

| Feature | `className` | `classList` |
| --- | --- | --- |
| Read classes | Full string | Token list |
| Replace all classes | Yes | Not directly |
| Add one class | Manual string handling | `add()` |
| Remove one class | Manual string handling | `remove()` |
| Toggle | Manual logic | `toggle()` |
| Check presence | Parse string | `contains()` |
| Replace one class | Manual logic | `replace()` |

Prefer `classList` for token-level class manipulation.

## 13. Understanding getComputedStyle

```html
<style>
  .message { color: blue; font-size: 20px; }
</style>
<p id="message" class="message">Hello</p>
```

```javascript
const message = document.getElementById("message");
const styles = getComputedStyle(message);
console.log(styles.color);    // e.g. "rgb(0, 0, 255)"
console.log(styles.fontSize); // "20px"
```

### Syntax breakdown

| Part | Meaning |
| --- | --- |
| `const` | Declare a binding |
| `styles` | Name for the returned style object |
| `=` | Assignment |
| `getComputedStyle` | Browser function returning resolved CSS values |
| `(` and `)` | Function-call delimiters |
| `message` | Element argument |

`message.style.color` may be `""` even while `getComputedStyle(message).color` returns blue. Computed style objects are read-only for styling purposes: update `element.style` or CSS classes instead.

## 14. Understanding the CSS cascade

```css
p { color: black; }
.message { color: blue; }
#message { color: green; }
```

```html
<p id="message" class="message">Hello</p>
```

The browser determines the winning declaration using origin, importance, cascade layers, specificity, scoping proximity, and source order. In ordinary rules of the same origin and layer, ID specificity outranks class specificity, which outranks type specificity.

```javascript
message.style.color = "red";
```

An ordinary inline declaration generally wins over ordinary author stylesheet rules, but `!important` and other cascade considerations mean inline styles do not **always** win.

## 15. Understanding CSS custom properties

CSS custom properties begin with `--`:

```css
:root {
  --primary-color: blue;
  --spacing: 12px;
}
button {
  background-color: var(--primary-color);
  padding: var(--spacing);
}
```

Set one using JavaScript:

```javascript
document.documentElement.style.setProperty(
  "--primary-color",
  "purple"
);
```

### Detailed explanation

1. `document` is the current page document.
2. `.documentElement` is its root `<html>` element.
3. `.style` accesses the root's inline declarations.
4. `.setProperty()` sets the named CSS custom property.
5. `"--primary-color"` identifies the variable.
6. `"purple"` supplies the new value.
7. Any CSS using `var(--primary-color)` may update accordingly.

Read it:

```javascript
const styles = getComputedStyle(document.documentElement);
const primaryColor = styles.getPropertyValue("--primary-color");
console.log(primaryColor.trim());
```

`.trim()` returns a new string with leading/trailing whitespace removed. It does not modify the DOM.

CSS variables are useful for themes, spacing, sizing, and design systems.

## 16. Showing and hiding elements

### display

```javascript
element.style.display = "none";
element.style.removeProperty("display");
```

`display: none` removes the element from normal layout. Removing the inline declaration allows CSS to decide its display type. Do not always restore with `display: block`: the original might be `flex`, `grid`, or `inline`.

### visibility

```javascript
element.style.visibility = "hidden";
```

The element is invisible but generally retains its layout space.

### opacity

```javascript
element.style.opacity = "0";
```

The element becomes transparent but generally remains in layout and may remain interactive.

| CSS declaration | Visible? | Keeps layout space? |
| --- | --- | --- |
| `display: none` | No | No |
| `visibility: hidden` | No | Yes |
| `opacity: 0` | No | Yes |

### hidden property

```html
<p id="message" hidden>Hello</p>
```

```javascript
message.hidden = false; // Show
message.hidden = true;  // Hide
```

The `hidden` attribute is useful for simple visibility state, though author CSS can affect its behavior.

## 17. Project: Show and hide a message

### Complete HTML + JavaScript

Save as `show-hide.html` and open in a browser:

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Show and Hide</title>
</head>
<body>
  <button id="toggleButton">Hide Message</button>
  <p id="message">Hello JavaScript</p>

  <script>
    const toggleButton = document.getElementById("toggleButton");
    const message = document.getElementById("message");

    toggleButton.addEventListener("click", function () {
      message.hidden = !message.hidden;
      toggleButton.textContent = message.hidden
        ? "Show Message"
        : "Hide Message";
    });
  </script>
</body>
</html>
```

### Understanding `!`

`!` is logical NOT. It converts `false` to `true` and `true` to `false`:

| `message.hidden` before | `!message.hidden` | `message.hidden` after |
| --- | --- | --- |
| `false` | `true` | `true` |
| `true` | `false` | `false` |

### Understanding `? :` step by step

```javascript
toggleButton.textContent = message.hidden
  ? "Show Message"
  : "Hide Message";
```

General form:

```javascript
condition ? valueIfTrue : valueIfFalse;
```

| Token | Meaning |
| --- | --- |
| `message.hidden` | Boolean condition |
| `?` | Start the result used when true |
| `"Show Message"` | Value selected when condition is true |
| `:` | Separate true and false results |
| `"Hide Message"` | Value selected when condition is false |
| `=` | Assign selected string to `textContent` |

Equivalent expanded code:

```javascript
if (message.hidden) {
  toggleButton.textContent = "Show Message";
} else {
  toggleButton.textContent = "Hide Message";
}
```

### Execution trace

| Click | Previous hidden | New hidden | Button label |
| --- | --- | --- | --- |
| Initial | - | `false` | Hide Message |
| First | `false` | `true` | Show Message |
| Second | `true` | `false` | Hide Message |
| Third | `false` | `true` | Show Message |

The listener executes on each click; `hidden` and button text are updated together.

## 18. Project: Light and dark theme switcher

Create these three files in the same folder.

### index.html

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Theme Switcher</title>
  <link rel="stylesheet" href="styles.css">
  <script src="script.js" defer></script>
</head>
<body>
  <main class="container">
    <h1>Theme Switcher</h1>
    <p>Switch between light and dark themes.</p>
    <button id="themeButton" type="button">Enable Dark Mode</button>
  </main>
</body>
</html>
```

### styles.css

```css
:root {
  --background: #ffffff;
  --text-color: #111827;
  --card-background: #f3f4f6;
}

:root.dark-theme {
  --background: #111827;
  --text-color: #f9fafb;
  --card-background: #1f2937;
}

body {
  background-color: var(--background);
  color: var(--text-color);
  font-family: Arial, sans-serif;
}

.container {
  max-width: 600px;
  margin: 40px auto;
  padding: 24px;
  background-color: var(--card-background);
  border-radius: 12px;
}

button {
  padding: 12px 18px;
  cursor: pointer;
}
```

### script.js

```javascript
const themeButton = document.getElementById("themeButton");

themeButton.addEventListener("click", function () {
  const isDark = document.documentElement.classList.toggle(
    "dark-theme"
  );

  themeButton.textContent = isDark
    ? "Enable Light Mode"
    : "Enable Dark Mode";
});
```

### Step-by-step code explanation

1. `document.getElementById("themeButton")` selects the button.
2. `const themeButton = ...` stores a reference that cannot be reassigned.
3. `.addEventListener("click", function () { ... })` registers a function to run on clicks.
4. `document.documentElement` selects the root `<html>` element.
5. `.classList.toggle("dark-theme")` adds or removes the theme class.
6. `toggle()` returns a boolean indicating whether the class exists afterward.
7. `const isDark = ...` stores that boolean.
8. The ternary `isDark ? ... : ...` selects the appropriate button label.
9. `themeButton.textContent = ...` updates the visible label.
10. CSS rules using `:root.dark-theme` change the variables; components using `var(...)` adopt the new colors.

### Execution trace

| State | Root class | `isDark` | Button label |
| --- | --- | --- | --- |
| Initial | None | Not evaluated | Enable Dark Mode |
| Click 1 | `dark-theme` | `true` | Enable Light Mode |
| Click 2 | None | `false` | Enable Dark Mode |
| Click 3 | `dark-theme` | `true` | Enable Light Mode |

## 19. DOM styling performance

Style updates can trigger style recalculation, layout, and paint.

Instead of repeated individual declarations:

```javascript
element.style.color = "red";
element.style.backgroundColor = "yellow";
element.style.border = "1px solid black";
```

Define a reusable class:

```css
.highlight {
  color: red;
  background-color: yellow;
  border: 1px solid black;
}
```

```javascript
element.classList.add("highlight");
```

A class is often easier to maintain, though not automatically faster in every situation.

Avoid alternating layout-affecting writes and layout reads unnecessarily:

```javascript
element.style.width = "200px";
const width = element.offsetWidth; // May require updated layout
 element.style.width = "300px";
```

Batch reads and writes when practical. Inline styles remain useful for truly dynamic values, such as progress percentages.

## 20. Accessibility considerations

- Maintain sufficient text/background contrast.
- Do not communicate important information only through color.
- Keep visible keyboard focus indicators.
- Ensure hidden content is not unexpectedly reachable through keyboard navigation.
- Consider reduced-motion preferences.
- Test both themes for readability.

Example:

```css
@media (prefers-reduced-motion: reduce) {
  * {
    scroll-behavior: auto;
  }
}
```

This is illustrative; production applications should consider which animations to reduce rather than indiscriminately overriding everything.

## 21. Common mistakes

| Mistake | Why it fails | Better approach |
| --- | --- | --- |
| `style.font-size` | Hyphen parsed as subtraction | `style.fontSize` |
| `style.width = "200"` | Missing unit for nonzero CSS width | `"200px"` |
| Read stylesheet CSS through `.style` | `.style` reads inline declarations | `getComputedStyle()` |
| `className = "active"` | Replaces every existing class | `classList.add("active")` |
| Toggle without considering state | Reverses presence | Use force argument when necessary |
| Assign to computed styles | Computed result is read-only for styling | Update inline style or class |
| Assign `cssText` carelessly | Replaces existing inline declarations | Set individual properties |
| Restore hidden element with `display:block` | Original may be flex/grid/inline | Remove inline `display` |
| Use `opacity:0` to disable controls | Invisible controls may remain interactive | Manage disabled/inert state appropriately |
| Overuse inline styles | Harder to maintain | Use reusable classes |

## 22. Ten interview questions and answers

### Q1. What does `element.style` represent?

**Answer:** A `CSSStyleDeclaration` object representing the element's inline CSS declarations.

### Q2. Why `backgroundColor` rather than `background-color` in dot notation?

**Answer:** JavaScript dot notation uses the camelCase property name. A hyphen in an expression acts as subtraction. Alternatively, use `setProperty("background-color", ...)`.

### Q3. Difference between `className` and `classList`?

**Answer:** `className` is the full class string; `classList` offers token-level methods to add, remove, toggle, check, and replace classes.

### Q4. What does `classList.toggle()` return?

**Answer:** `true` if the class is present afterward, `false` if absent.

### Q5. Why can `element.style.color` return `""`?

**Answer:** The element may not have an inline `color` declaration, even if CSS stylesheets give it a visible color.

### Q6. What does `getComputedStyle()` do?

**Answer:** It returns a read-only view of resolved CSS values considering applicable rules and the cascade.

### Q7. What does `style.setProperty()` do?

**Answer:** Sets an inline CSS declaration by its CSS name, with optional priority.

### Q8. What does `style.removeProperty()` return?

**Answer:** The previous value of the removed inline declaration.

### Q9. What is a CSS custom property?

**Answer:** A property named with two leading hyphens, such as `--primary-color`, usable with CSS `var()` and modifiable through `setProperty()`.

### Q10. Difference between `display:none` and `visibility:hidden`?

**Answer:** `display:none` removes the element from normal layout; `visibility:hidden` generally hides it while retaining layout space.

## 24. Knowledge check

Try these without looking at the answer key.

1. Which property changes inline text color?  
   A. `element.css.color`  
   B. `element.style.color`

## Learning objectives

By the end of this lesson you should be able to insert nodes at the beginning or end of a container, insert siblings before or after a reference node, replace and remove nodes, understand return values and error conditions, explain why inserting an existing node moves it, and build dynamic interfaces safely.

## 1. DOM relationships

```html
<div id="container">
  <h2>Title</h2>
  <p>First paragraph</p>
  <p>Second paragraph</p>
</div>
```

The `div` is the **parent** of the heading and paragraphs. The heading and paragraphs are **children** of the div and **siblings** of one another. An element's position matters when inserting nodes.

```text
div#container
|-- h2: Title
|-- p: First paragraph
\-- p: Second paragraph
```

**Key distinction:** `append()` and `prepend()` insert *children* inside the receiver. `before()` and `after()` insert *siblings* beside the receiver.

## 2. appendChild

**Syntax:** `parent.appendChild(child)`

```html
<div id="container"></div>
```

```javascript
const container = document.getElementById("container");
const paragraph = document.createElement("p");
paragraph.textContent = "New paragraph";
const inserted = container.appendChild(paragraph);
console.log(inserted === paragraph); // true
```

### Piece-by-piece breakdown

| Token | Meaning |
|---|---|
| `container` | Variable holding a reference to the parent element |
| `.` | Accesses a property or method of an object |
| `appendChild` | Method that adds one Node as the last child |
| `(` and `)` | Surround the argument passed to the method |
| `paragraph` | The node being inserted |
| `;` | Ends the JavaScript statement |

### Execution trace

1. `getElementById("container")` locates the parent.
2. `createElement("p")` constructs a disconnected paragraph.
3. `.textContent = "New paragraph"` sets its plain text.
4. `appendChild(paragraph)` inserts the paragraph at the end of the parent.
5. The return value is the same paragraph node.
6. `===` compares object identity; the output is `true`.

**Important:** `appendChild()` accepts one Node, not a plain string. `container.appendChild("Hello")` throws a TypeError. Use `append("Hello")` or `createTextNode("Hello")`.

## 3. append

**Syntax:** `element.append(...nodesOrStrings)`

```javascript
const heading = document.createElement("h2");
heading.textContent = "Welcome";
const description = document.createElement("p");
description.textContent = "Learning JavaScript";
container.append(heading, " - ", description);
```

The heading and paragraph are inserted at the end. The string `" - "` becomes a text node.

### `append()` vs `appendChild()`

| Feature | `append()` | `appendChild()` |
|---|---|---|
| Multiple arguments | Yes | No |
| Plain strings | Yes | No |
| Return value | `undefined` | Appended Node |
| Position | Last children | Last child |

```javascript
const result = container.append("Hello");
console.log(result); // undefined
```

`undefined` here means the method does not return the appended content. It does **not** mean the insertion failed.

## 4. prepend

**Syntax:** `element.prepend(...nodesOrStrings)`

```html
<ul id="fruits">
  <li>Banana</li>
  <li>Orange</li>
</ul>
```

```javascript
const list = document.getElementById("fruits");
const apple = document.createElement("li");
apple.textContent = "Apple";
list.prepend(apple);
```

**Before:** Banana, Orange.  
**After:** Apple, Banana, Orange.

`prepend()` inserts at the beginning of the element's children, accepts multiple nodes or strings, and returns `undefined`.

## 5. before

**Syntax:** `referenceNode.before(...nodesOrStrings)`

```html
<div><p id="second">Second</p></div>
```

```javascript
const second = document.getElementById("second");
const first = document.createElement("p");
first.textContent = "First";
second.before(first);
```

**Result:** `first` is a sibling immediately before `second` in their shared parent. It is **not** inserted inside `second`.

## 6. after

**Syntax:** `referenceNode.after(...nodesOrStrings)`

```html
<div><p id="first">First</p></div>
```

```javascript
const first = document.getElementById("first");
const second = document.createElement("p");
second.textContent = "Second";
first.after(second);
```

**Result:** `second` is a sibling immediately after `first`.

| Method | Location |
|---|---|
| `parent.prepend(node)` | First child of parent |
| `parent.append(node)` | Last child of parent |
| `reference.before(node)` | Sibling immediately before reference |
| `reference.after(node)` | Sibling immediately after reference |

## 7. insertBefore

**Syntax:** `parent.insertBefore(newNode, referenceNode)`

```html
<ul id="fruits">
  <li id="apple">Apple</li>
  <li id="orange">Orange</li>
</ul>
```

```javascript
const list = document.getElementById("fruits");
const orange = document.getElementById("orange");
const banana = document.createElement("li");
banana.textContent = "Banana";
list.insertBefore(banana, orange);
```

**Result:** Apple, Banana, Orange.

### Argument breakdown

| Argument | Meaning |
|---|---|
| `banana` (first) | New node to insert |
| `orange` (second) | Existing child that comes after the inserted node |

The method is invoked on the **parent** (`list`). The reference (`orange`) must be a child of that parent or a `NotFoundError` occurs. Passing `null` as the second argument appends to the end:

```javascript
list.insertBefore(banana, null);
```

The return value is the inserted node.

## 8. replaceWith

**Syntax:** `oldNode.replaceWith(...nodesOrStrings)`

```html
<p id="message">Old message</p>
```

```javascript
const oldMessage = document.getElementById("message");
const newMessage = document.createElement("p");
newMessage.textContent = "New message";
oldMessage.replaceWith(newMessage);
```

### Execution trace

1. Select the original paragraph.
2. Create a new, disconnected paragraph.
3. Set its text.
4. Call `replaceWith()` on the original paragraph.
5. The new paragraph occupies the original position.
6. The old paragraph is detached, but remains accessible through `oldMessage`.

`replaceWith()` accepts nodes and strings and returns `undefined`.

```javascript
oldMessage.replaceWith("Replacement text");
```

This inserts a text node instead of an HTML element (provided the original node is still connected when called).

## 9. replaceChild

**Syntax:** `parent.replaceChild(newChild, oldChild)`

**Remember: NEW first, OLD second.**

```html
<div id="container"><p id="oldParagraph">Old</p></div>
```

```javascript
const container = document.getElementById("container");
const oldParagraph = document.getElementById("oldParagraph");
const newParagraph = document.createElement("p");
newParagraph.textContent = "Replacement paragraph";
const removed = container.replaceChild(newParagraph, oldParagraph);
console.log(removed === oldParagraph); // true
```

The parent must contain the old child. Unlike `replaceWith()`, `replaceChild()` takes one replacement Node and returns the removed node.

| Feature | `replaceWith()` | `replaceChild()` |
|---|---|---|
| Called on | Node being replaced | Parent |
| Arguments | Replacement nodes or strings | New child, old child |
| Returns | `undefined` | Removed old child |

## 10. remove

**Syntax:** `element.remove()`

```html
<p id="message">Hello</p>
```

```javascript
const message = document.getElementById("message");
message.remove();
console.log(message.textContent); // Hello
```

Removing the element detaches it from the document. The `message` variable still references the same object.

### Handling a missing element

```javascript
const missing = document.getElementById("missing");
if (missing !== null) {
  missing.remove();
}
```

`!==` is the strict inequality operator. It checks that the value is not `null`.

Shorter version:

```javascript
missing?.remove();
```

`?.` is the **optional chaining operator**. It skips the method call when the left side is `null` or `undefined`.

## 11. removeChild

**Syntax:** `parent.removeChild(child)`

```html
<ul id="fruits"><li id="banana">Banana</li></ul>
```

```javascript
const list = document.getElementById("fruits");
const banana = document.getElementById("banana");
const removed = list.removeChild(banana);
console.log(removed === banana); // true
```

The method returns the removed child. If `banana` is not actually a child of `list`, a `NotFoundError` is thrown.

| Feature | `remove()` | `removeChild()` |
|---|---|---|
| Called on | Node to remove | Parent |
| Requires explicit parent variable | No | Yes |
| Return value | `undefined` | Removed node |

## 12. replaceChildren

**Syntax:** `element.replaceChildren(...nodesOrStrings)`

```javascript
const list = document.getElementById("fruits");
const orange = document.createElement("li");
orange.textContent = "Orange";
list.replaceChildren(orange);
```

All previous children are removed and replaced with the new Orange item.

```javascript
list.replaceChildren(); // Clear all children
```

Compare:

```javascript
list.textContent = ""; // Also clears descendants
```

`replaceChildren()` expresses an intent to replace the child-node collection and can insert replacement nodes in the same call.

## 13. Moving versus copying nodes

```html
<div id="firstContainer">
  <p id="message">Hello</p>
</div>
<div id="secondContainer"></div>
```

```javascript
const message = document.getElementById("message");
const destination = document.getElementById("secondContainer");
destination.appendChild(message);
```

**After the call:** The paragraph is inside `secondContainer` and no longer inside `firstContainer`.

```text
BEFORE                     AFTER
firstContainer             firstContainer
\-- p#message              (empty)
secondContainer            secondContainer
(empty)                    \-- p#message
```

**Why?** A DOM node cannot occupy two positions in the same tree simultaneously. Insertion methods move an existing node instead of automatically duplicating it.

To copy:

```javascript
const copy = message.cloneNode(true);
copy.removeAttribute("id");
destination.appendChild(copy);
```

`cloneNode(true)` copies the node and descendants. If cloned descendants also contain IDs, update them too. Event listeners registered with `addEventListener()` are not copied.

## 14. Practical project 1 - Dynamic list

Build an interface that inserts items at the beginning or end and removes individual items.

### index.html

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Dynamic List</title>
  <script src="script.js" defer></script>
</head>
<body>
  <h1>Dynamic List</h1>
  <label for="itemInput">New item</label>
  <input id="itemInput" type="text">
  <button id="prependButton" type="button">Add to Beginning</button>
  <button id="appendButton" type="button">Add to End</button>
  <ul id="itemList"></ul>
</body>
</html>
```

### script.js

```javascript
const itemInput = document.getElementById("itemInput");
const itemList = document.getElementById("itemList");
const prependButton = document.getElementById("prependButton");
const appendButton = document.getElementById("appendButton");

function createItem(text) {
  const item = document.createElement("li");
  const label = document.createElement("span");
  label.textContent = text;

  const removeButton = document.createElement("button");
  removeButton.type = "button";
  removeButton.textContent = "Remove";
  removeButton.setAttribute("aria-label", `Remove ${text}`);

  removeButton.addEventListener("click", function () {
    item.remove();
  });

  item.append(label, " ", removeButton);
  return item;
}

prependButton.addEventListener("click", function () {
  const text = itemInput.value.trim();
  if (text === "") {
    return;
  }
  const item = createItem(text);
  itemList.prepend(item);
  itemInput.value = "";
});

appendButton.addEventListener("click", function () {
  const text = itemInput.value.trim();
  if (text === "") {
    return;
  }
  const item = createItem(text);
  itemList.append(item);
  itemInput.value = "";
});
```

### Detailed breakdown: `const text = itemInput.value.trim();`

| Piece | Explanation |
|---|---|
| `const` | Declares a binding that cannot be reassigned |
| `text` | Name for the cleaned string |
| `=` | Assigns the result of the right-hand expression |
| `itemInput` | Reference to the input element |
| `.value` | Current text typed into the input |
| `.trim()` | Returns a string without leading/trailing whitespace |
| `;` | Statement terminator |

If the user types `"  Apple  "`, then `itemInput.value` is `"  Apple  "`, but `text` becomes `"Apple"`. `trim()` does not itself change the input's `.value`.

### Detailed breakdown: `if (text === "") { return; }`

- `if` executes its body only if the condition is truthy.
- `===` checks strict equality, without type coercion.
- `""` is the empty string.
- `return;` exits the callback immediately when the input is empty.

### Detailed breakdown: `item.append(label, " ", removeButton);`

The `item` is an `li`. `append()` receives three arguments: a `span` element, a one-space string (converted to a text node), and a `button` element. All three become children of the list item in that order.

### Detailed breakdown: event listener closure

```javascript
removeButton.addEventListener("click", function () {
  item.remove();
});
```

Each call to `createItem()` creates its own `item` variable and its own callback. The callback retains access to that particular `item`. Therefore each Remove button removes the corresponding list item.

### Step-by-step execution trace

| Step | Action | Result |
|---|---|---|
| 1 | User enters `Apple` | Input value is `"Apple"` |
| 2 | Click Add to Beginning | Click callback executes |
| 3 | `.value.trim()` | Produces `"Apple"` |
| 4 | `text === ""` | `false`, so do not return |
| 5 | `createItem(text)` | Constructs an `li` with label and button |
| 6 | `itemList.prepend(item)` | Inserts the `li` as first child |
| 7 | `itemInput.value = ""` | Clears the input |
| 8 | Click the item's Remove button | Calls `item.remove()` and detaches the `li` |

### Try it

1. Add `Apple` at the beginning.
2. Add `Orange` at the end.
3. Add `Banana` at the beginning.
4. Predict the resulting order before checking the page: Banana, Apple, Orange.
5. Remove Apple and verify the remaining order.

## 15. Practical project 2 - Notifications

Build a notification area that replaces an old message with a new one.

### index.html

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Notifications</title>
  <link rel="stylesheet" href="styles.css">
  <script src="script.js" defer></script>
</head>
<body>
  <div id="notificationContainer"></div>
  <button id="successButton" type="button">Show Success</button>
  <button id="errorButton" type="button">Show Error</button>
  <button id="clearButton" type="button">Clear</button>
</body>
</html>
```

### styles.css

```css
.notification {
  padding: 12px;
  border-radius: 6px;
  margin-bottom: 12px;
}
.notification.success {
  background-color: #dcfce7;
  color: #166534;
}
.notification.error {
  background-color: #fee2e2;
  color: #991b1b;
}
```

### script.js

```javascript
const container = document.getElementById("notificationContainer");
const successButton = document.getElementById("successButton");
const errorButton = document.getElementById("errorButton");
const clearButton = document.getElementById("clearButton");

function showNotification(message, type) {
  const notification = document.createElement("div");
  notification.classList.add("notification", type);
  notification.textContent = message;
  notification.setAttribute(
    "role",
    type === "error" ? "alert" : "status"
  );
  container.replaceChildren(notification);
}

successButton.addEventListener("click", function () {
  showNotification("Operation completed.", "success");
});

errorButton.addEventListener("click", function () {
  showNotification("Something went wrong.", "error");
});

clearButton.addEventListener("click", function () {
  container.replaceChildren();
});
```

### Ternary operator breakdown

```javascript
type === "error" ? "alert" : "status"
```

| Piece | Meaning |
|---|---|
| `type` | The function's second argument |
| `=== "error"` | Checks whether type is exactly `"error"` |
| `?` | Starts the value selected when the condition is true |
| `"alert"` | Value if true |
| `:` | Separates the two possible values |
| `"status"` | Value if false |

Equivalent `if/else`:

```javascript
let role;
if (type === "error") {
  role = "alert";
} else {
  role = "status";
}
notification.setAttribute("role", role);
```

### Execution trace: success, then error, then clear

1. Click Show Success.
2. The callback calls `showNotification("Operation completed.", "success")`.
3. A new `div` is created with classes `notification` and `success`.
4. The condition `type === "error"` is false; `role` becomes `"status"`.
5. `replaceChildren(notification)` makes this the container's only child.
6. Click Show Error.
7. A different `div` is created; the condition is true, so `role` becomes `"alert"`.
8. `replaceChildren(notification)` removes the previous success node and inserts the error node.
9. Click Clear.
10. `replaceChildren()` removes the error node, leaving the container empty.

**Accessibility note:** Reserve `role="alert"` for urgent information. For routine status updates, `role="status"` is less disruptive. In production, plan live-region behavior carefully, including whether the region should exist before its content changes.

## 16. Common mistakes

| Mistake | Why it happens | Correct approach |
|---|---|---|
| `appendChild("Hello")` | String is not a Node | Use `append("Hello")` or a text node |
| Expecting `append()` to return the node | Returns `undefined` | Keep a variable for the created node |
| Reversing `replaceChild()` arguments | New node must come first | `parent.replaceChild(newChild, oldChild)` |
| Calling `remove()` on `null` | No node was found | Check `!== null` or use `?.` |
| Using the wrong parent in `removeChild()` | Child does not belong to that parent | Verify the relationship |
| Expecting append to duplicate a node | Existing nodes move | Use `cloneNode()` if copying is intended |
| Copying IDs with cloned elements | Duplicate IDs in the document | Assign unique IDs |
| Using `innerHTML` for untrusted text | HTML parsing may enable XSS | Use `textContent` and safe DOM APIs |
| Replacing all children unnecessarily | Can lose focus and interactive state | Update only what changed |
| Assuming removed nodes cease to exist | JavaScript references may remain | Understand references and garbage collection |

## 17. 10 interview questions and answers

### Q1. What does `appendChild()` do?

**Answer:** It appends one Node as the last child of a parent and returns that appended Node.

### Q2. What is the difference between `append()` and `appendChild()`?

**Answer:** `append()` accepts multiple nodes or strings and returns `undefined`; `appendChild()` accepts one Node and returns it.

### Q3. What does `prepend()` do?

**Answer:** It inserts nodes or strings at the beginning of an element's children.

### Q4. What is the difference between `before()` and `prepend()`?

**Answer:** `before()` inserts siblings immediately before the reference node. `prepend()` inserts children at the beginning of the receiver.

### Q5. Why use `insertBefore()`?

**Answer:** It inserts a node before a specified child of a known parent. The reference must be a child of that parent, or a `NotFoundError` is thrown.

### Q6. What does `replaceWith()` return?

**Answer:** `undefined`. It can replace the receiver with nodes or strings.

### Q7. What is the argument order for `replaceChild()`?

**Answer:** `parent.replaceChild(newChild, oldChild)`; new child first, old child second.

### Q8. How do `remove()` and `removeChild()` differ?

**Answer:** `remove()` is called on the node being removed and returns `undefined`; `removeChild()` is called on the parent and returns the removed child.

### Q9. What happens when an existing node is appended elsewhere?

**Answer:** It moves to the new location; it is not duplicated.

### Q10. What does `replaceChildren()` do?

**Answer:** It replaces all existing children with supplied nodes or strings, or clears the container when called without arguments.

## 18. 10 coding exercises and solutions

### Exercise 1 - Append a paragraph

**Task:** Create a paragraph containing `Hello` and append it to the document body.

```javascript
const paragraph = document.createElement("p");
paragraph.textContent = "Hello";
document.body.appendChild(paragraph);
```

**Why it works:** `createElement` constructs the node, `textContent` adds plain text, and `appendChild` inserts it as the last child of `body`.

### Exercise 2 - Prepend a list item

**Task:** Insert `Apple` at the beginning of a list with ID `fruits`.

```javascript
const list = document.getElementById("fruits");
const item = document.createElement("li");
item.textContent = "Apple";
list.prepend(item);
```

**Why it works:** `prepend` inserts the new `li` before all existing children.

### Exercise 3 - Insert before a target

**Task:** Insert a paragraph immediately before `#target`.

```javascript
const target = document.getElementById("target");
const paragraph = document.createElement("p");
paragraph.textContent = "Before target";
target.before(paragraph);
```

**Why it works:** `before` inserts a sibling, not a child of `target`.

### Exercise 4 - Insert after a target

**Task:** Insert a paragraph immediately after `#target`.

```javascript
const target = document.getElementById("target");
const paragraph = document.createElement("p");
paragraph.textContent = "After target";
target.after(paragraph);
```

**Why it works:** `after` inserts the paragraph as the next sibling.

### Exercise 5 - Use insertBefore

**Task:** Insert `Banana` before `#orange` inside `#fruits`.

```javascript
const list = document.getElementById("fruits");
const orange = document.getElementById("orange");
const banana = document.createElement("li");
banana.textContent = "Banana";
list.insertBefore(banana, orange);
```

**Why it works:** The parent method receives the new node first and the existing reference child second.

### Exercise 6 - Replace an element

**Task:** Replace `#old` with a new paragraph.

```javascript
const oldElement = document.getElementById("old");
const replacement = document.createElement("p");
replacement.textContent = "New content";
oldElement.replaceWith(replacement);
```

**Why it works:** `replaceWith` detaches the original node and inserts the replacement in its position.

### Exercise 7 - Safely remove an optional element

**Task:** Remove `#message` only if it exists.

```javascript
const message = document.getElementById("message");
message?.remove();
```

**Why it works:** Optional chaining `?.` skips the method call if `message` is `null` or `undefined`.

### Exercise 8 - Remove a child through its parent

**Task:** Remove `#banana` from `#fruits`.

```javascript
const list = document.getElementById("fruits");
const banana = document.getElementById("banana");
list.removeChild(banana);
```

**Why it works:** `removeChild` removes a specified child of the receiving parent. The parent-child relationship must be correct.

### Exercise 9 - Clear all children

**Task:** Empty the list with ID `fruits`.

```javascript
const list = document.getElementById("fruits");
list.replaceChildren();
```

**Why it works:** With no replacement arguments, `replaceChildren` removes all existing children.

### Exercise 10 - Move a node between containers

**Task:** Move `#item` into `#destination` without creating a copy.

```javascript
const item = document.getElementById("item");
const destination = document.getElementById("destination");
destination.appendChild(item);
```

**Execution trace:**

1. `getElementById("item")` returns a reference to the existing node.
2. `getElementById("destination")` returns a reference to the destination.
3. `appendChild(item)` detaches the item from its previous parent, if any.
4. The item becomes the last child of the destination.
5. The original object identity remains unchanged.

## 19. Knowledge check

Try answering before reading the answer key.

**1. Which method inserts a node as the first child?**

A. `append()`  
B. `prepend()`  
C. `after()`  
D. `replaceWith()`

**2. What happens when `appendChild()` receives a node already in another container?**

A. It duplicates the node  
B. It moves the node  
C. It always throws  
D. It removes the destination

**3. What is the correct argument order for `replaceChild()`?**

A. Old child, new child  
B. New child, old child  
C. Parent, old child  
D. Old child only

**4. Which method removes all children when called without arguments?**

A. `removeChild()`  
B. `before()`  
C. `replaceChildren()`  
D. `insertBefore()`

**5. What does `removeChild()` return?**

A. `undefined`  
B. The parent node  
C. The removed child node  
D. A boolean

### Answer key with explanations

1. **B - `prepend()`**. It inserts nodes or strings at the beginning of an element's children.
2. **B - It moves the node**. An existing node cannot simultaneously occupy two positions in the DOM tree.
3. **B - New child, old child**. The signature is `parent.replaceChild(newChild, oldChild)`.
4. **C - `replaceChildren()`**. Calling it without arguments clears all child nodes.
5. **C - The removed child node**. `removeChild()` returns the node that was removed.
